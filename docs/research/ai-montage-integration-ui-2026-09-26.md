## 1. 结论

将分享内容中的“素材片段库 → 结构化剪辑计划 → 现有时间线 → FFmpeg 渲染”逐层接入本项目。推荐在现有 React + FastAPI 工作台中增加能力，保留已实现的脚本候选、素材 ID、版本校验、预览、审核与导出流程。

优先完成脚本确认、多音色试听、所选音色配音和混剪的完整声画闭环；再补片段级理解与检索，最后增加对话修改。数字人直播继续暂停，启动门槛仍以现有路线图为准。

来源：[用户分享的 AI 混剪流程](https://chatgpt.com/share/6ab73b7e-3184-83ea-95c7-c478df4a7032)。已读取正文；分享中的项目能力描述另用官方仓库核验。以下接口与顺序属于针对本项目提出的设计建议。

## 2. 现状与接入位置

| 分享中的能力 | 本项目现状 | 推荐接入方式 |
| --- | --- | --- |
| 媒体探测、分镜与抽帧 | 已有 FFmpeg 本地预处理、镜头变化检测及参考素材分析 | 提取可复用的处理能力，对所选项目素材建立片段索引；当前参考素材的分析结果不能直接当作所有项目素材的索引 |
| ASR 与时间戳 | 已有混剪字幕识别、编辑与烧录 | 对素材原声建立时间戳文本，供片段搜索；配音字幕仍绑定实际声音和时间线 |
| 画面内容理解 | 已有参考素材的结构化语义分析 | 对所选素材片段补充场景、主体、动作与画面描述，并区分观察事实和模型建议 |
| Clip 素材库 | 有项目素材；未形成供批量混剪检索的片段级语义库 | 保存素材 ID、源时间范围、缩略图、文字描述和分析版本；文件仍作为不可变项目素材保留 |
| AI 脚本 | `AigcCreator` 已有创作简报、5 条候选、编辑、事实关联、确认与批量交接 | 将入口和后续步骤串联，保留事实核对与每次发送确认 |
| AI 剪辑计划 | `batch_recommendation.py` 当前按名称/备注关键词匹配，片段从素材开头取至多 3 秒 | 引入带具体时间范围和选材理由的计划；校验后转换成已有时间线 |
| 时间线与渲染 | 已有视频/音频轨、字幕、FFmpeg 合成、版本快照 | 复用现有引擎和校验；编辑计划是其上游输入 |
| TTS 与 BGM | 可导入音频、录音、混音；多音色试听与正式自动配音尚未接通 | 音色试听置于混剪之前；按确认脚本生成配音，使用真实配音时长安排镜头和字幕 |
| 对话修改 | 未实现 | 在片段检索与计划稳定后，先支持换镜头、调整时长、调整音量等有限操作 |

现有代码入口：`frontend/src/PreproductionWorkspace.tsx`、`frontend/src/AigcCreator.tsx`、`frontend/src/BatchEditor.tsx`、`backend/app/batch_recommendation.py`、`backend/app/timeline_render.py`。

## 3. 用户主流程

```text
确认商品事实、卖点与受众 + 选择授权素材
  → 展示本次 AI 请求内容与接收服务，确认发送
  → 生成 5 条脚本候选
  → 编辑并确认脚本
  → 同文案多音色试听，选择满意音色
  → 生成配音，依据实际时长生成剪辑计划
  → 查看脚本与镜头匹配，必要时替换片段
  → 编排已有时间线，合成字幕、配音和配乐
  → 在同一条 MP4 中预览画面、声音与字幕
  → 审核通过后导出
```

素材分镜、原声转录和片段理解属于素材准备，可在编排前完成。向外部视觉服务发送帧图或原声，须另行明确展示内容和接收方；既有“脚本生成只发送文字”的确认不包含这项传输。

有配音的营销视频按实际配音时长安排镜头，不能继续假定每句固定 3 秒。超出可用片段范围时提示修改计划或补充素材，不能截断配音或用空画面掩盖缺口。

## 4. 最小数据设计

### 源码复用要求（用户于 2026-09-26 确认）

正式功能与 GitHub 项目相同时，优先直接复用已核验的源码或官方依赖，只编写接入本项目所需的适配层，不从头重写同类算法和组件。每个正式实施任务先列出源仓库、固定 commit、具体模块、许可与依赖，再决定导入方式。已有本项目功能继续复用；第三方模块若许可或接口不满足要求，记录具体差异再确定替代方案。

本轮可点击原型仅验证信息结构和操作顺序，不作为正式功能实现。现有 React 工作台与第三方 Streamlit/Next.js 整页之间的差异不能通过直接复制入口解决，应优先提取其可复用模块，避免为了嵌入整页而迁移整个项目。

### 素材片段索引

建议先在项目内保存：

```json
{
  "id": "segment_001",
  "assetId": "existing_asset_id",
  "sourceStart": 4.2,
  "sourceEnd": 8.7,
  "transcript": "带时间戳的原声文本（可为空）",
  "visualDescription": "热水注入滤杯，咖啡粉浸润",
  "tags": ["手冲", "注水", "特写"],
  "analysisRevision": 1
}
```

片段是对源素材时间范围的引用，初期无需把每个片段另存一个视频文件。描述可由人工修订；未分析、失败或待核对必须可见。先以可解释文字检索验证选材效果，数据规模和检索效果确有需要时再评估 embedding 与向量库。

### 结构化剪辑计划

建议保存脚本版本、音色/配音版本、片段索引版本和计划版本。每个计划段包含：脚本段、所依据事实、片段 ID、源入点/出点、时间线位置、字幕及选材理由。画面缺失时留在待修复状态。

后端先检查素材存在、片段范围有效、时间线可实现、事实关联及脚本版本，再转换为现有 `assetId/inPoint/duration/start` 轨道结构。模型输出不直接执行命令；本地路径由后端根据素材 ID 解析。

更换脚本、音色、配音、镜头或字幕都使相关预览和审核失效；沿用现有版本门槛。对话操作先展示拟修改的镜头/版本与差异，采用后仍须重新预览、审核。

### 推荐的两层界面

**制作入口：步骤导航 + 当前步骤内容。** 将当前嵌在批量页中的脚本候选流程显式串联成“创作简报、脚本确认、声音选择、镜头编排、审核交付”。提供返回编辑并保留草稿；未完成的步骤显示原因，不能只按点击顺序解锁。

**单条精修：三栏 + 底部时间线。**

```text
项目 / 当前变体                 素材·脚本·配音版本 / 保存状态
────────────────────────────────────────────────────────
素材与片段库       成片播放器                当前选择的属性
缩略图/搜索        画面 + 声音 + 字幕        文案 / 片段范围
标签/源时间段      时间码/播放              音量 / 选材理由
────────────────────────────────────────────────────────
视频轨       [片段 A] [片段 B] [片段 C]
配音轨       [当前脚本对应的实际配音]
配乐轨       [可试听的配乐与音量]
字幕         [可编辑字幕段]
────────────────────────────────────────────────────────
批量变体列表 / 预览状态 / 审核 / 退回理由 / 导出资格
```

音色页每张卡显示名称、语言、风格、试听/停止、选择状态；同一句短文案比较，同时只播放一个样本。支持“都不满意，换一组”，服务失败显示实际原因。未取得真实试听音频时不能伪造可用状态，也不能回退到用户已拒绝的本机音色。

窄屏改为素材、播放器、属性依次展开，时间线保留可控横向滚动。键盘操作、焦点、试听状态及错误文字都要可用；动效只用于状态反馈，不妨碍编辑。上述是设计要求，尚未进行本项目新界面的浏览器验收。

## 6. 推荐实施顺序与验收

1. **脚本到声音的完整入口**：复用脚本生成/确认；接通正式音色目录、真实试听、所选音色配音，进入现有混剪。验收至少一个用户认可的音色；同一交付 MP4 的画面、声音、字幕完整且同步；旧审核不能导出修改版。当前专业音色试生成受 fal 余额不足阻碍，工作台正式 TTS 尚未接通，界面方案不能替代该验收。
2. **素材片段库与时间段检索**：至少两份项目视频获得源时间范围、缩略图和可修改描述；可找到所需画面并定位源片段；无结果和分析失败有清楚反馈。外部分析先完成发送披露。
3. **结构化剪辑计划接现有时间线**：每句文案能看到选材理由和具体片段；匹配错误可替换；按真实配音时长安排；5 条变体在内容或镜头安排上可见差异，并逐条审核。
4. **对话修改**：从“替换首镜头”“将背景音乐调低”等有限动作起步；验证只改目标范围、保护已编辑内容、版本变化触发重新审核。局部重渲染属于后续性能优化，需要单独验证，当前不承诺。

AI 全新画面、自动音乐和客户独立网页工作台仍按第二阶段完整目标另行推进，不能因上述四项完成就宣称 AIGC 全部完成。ADR 0007/0008 仍记录最终 AI 视频生成在外部执行；实际接入全新画面生成前须依据用户已确认的扩展范围更新对应边界，本方案不静默覆盖旧决策。
