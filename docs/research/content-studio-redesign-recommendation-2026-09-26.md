# 全站内容工作台：流程与视觉改版建议

日期：2026-09-26。状态：用户已确认全站方案，已实现 DEV 可点击视觉稿；正式界面迁入待实施。

预览入口：`http://127.0.0.1:5188/?prototype=studio-redesign`。覆盖八个主要页面及四步制作示意，样音与公开样片可播放；不调用模型或正式项目接口。实施与验证范围见 [视觉稿任务](../../.scratch/whole-site-ui-redesign/spec.md)。

## 目标与已确认范围

用户明确反馈网站繁琐、难以理解，整体 UI 简陋、缺少特色。用户进一步明确要求**全站整体修改，不能只改一个模块**。覆盖首页、项目入口、制作、素材、精修、审片、复刻、工具和设置；优先打通：**商品资料和素材 → AI 脚本 → 选音色 → 批量短视频**。服务内部交付团队，保留客户自助的后续计划；数字人继续暂停。

既有 A 步骤制作 / B 单条精修 / C 批量审片布局已经获批。本次沿用布局分工，完善正式入口、默认操作与视觉表达。现有 DEV 原型未接完整真实制作链，不能直接把其中的模拟生成逻辑迁入正式页面。

## 1. 正式网站的实际问题

本轮在独立后台标签页，只读打开“本地配音 · 公开素材技术验收”项目和已保存任务。该任务只有两段视频与两句配音；未发送 AI 请求、修改素材或创建任务。

| 实际观察 | 对用户的影响 | 改版要求 |
| --- | --- | --- |
| 项目仍展示参考视频复刻六阶段，提示未上传参考视频、未添加镜头 | 商品视频已有素材仍出现不相关阻塞提示 | 根据制作入口显示对应流程，复刻作为独立入口 |
| 需求、素材、镜头、工具、剪辑、批量混剪、交付七个功能并列 | 用户需要自己记住功能执行顺序 | 顶部四步主流程，功能目录退出普通制作主线 |
| 编辑区含 33 个按钮、52 个输入控件，其中 33 个数值字段 | 简单任务暴露大量工程决策 | 常用内容可见，时间、速度、淡入淡出放精修 |
| 编辑区高约 4,925 px，窗口高 720 px | 文案、声音、预览和审核相隔多屏 | 当前步骤与预览同屏，操作栏保持可找到 |
| 上述计数未包含后来展开的 AI 商品内容创作表单 | 脚本生成作为附加表单叠在旧编辑区 | 脚本成为第二步主体，移除重复手填五条入口 |
| 素材以文件名呈现；多个“添加素材”“选择推荐素材”入口并存 | 难以知道选了什么画面、用于哪里 | 带缩略图与说明的一次素材选择，后续沿用 |
| 暖灰底、接近默认样式的输入框、同等级按钮与密集文字 | 缺少内容制作的视觉重点 | 真实画面、脚本与成片承担视觉层级 |

计数为整个已渲染编辑区，**不是首屏同时可见**。这是一个技术验收任务的基线，其他项目的控件数随内容变化。

## 2. 方案比较

| 方案 | 收益 | 成本与不足 | 选择 |
| --- | --- | --- | --- |
| 只美化按钮、收起参数 | 改动小 | 仍需跨模块交接、重复保存，入口问题未解决 | 不作为主方案 |
| 四步制作 + 内容预览 + 按需精修 | 保留真实能力，用户围绕内容决策 | 要将现有接口组织为连续流程，并验证恢复和版本一致性 | **推荐** |
| 替换为开源完整编辑器 | 有成熟时间线外观 | 栈、许可证、渲染体系差异大；完整编辑器并不自动减少任务步骤 | 当前不选 |

渐进披露支持把高级功能后置，也提醒相互依赖的内容不宜拆得太散；本项目将资料与素材同屏、脚本与画面同屏。四步是本项目设计选择，并非来源规定。[NN/G](https://www.nngroup.com/articles/progressive-disclosure/)

## 3. 推荐的默认操作

### 第一步：准备商品与素材

同一页填写商品事实、受众和卖点，上传或选用授权素材。行动引导与禁用表达在清楚标注的补充区内，不能被自动臆造。素材直接显示缩略图、名称、时长和选中状态。默认继承现有竖版与五条产出设置；高级规格按需修改。

主动作：“生成 5 条脚本”。先保存有效简报，再展示本次发送的文字与目标服务，用户确认后才调用。该发送确认是用户既有要求，继续保留；不让用户分别点击保存、预览发送、换模块寻找生成入口。

### 第二步：看脚本与对应画面

左侧五条脚本摘要，中间当前脚本文字，右侧对应素材缩略图；每段文字与画面有明确对应关系。修改时在当前页保存并确认该条，回看其他候选保持状态。显示“已确认 3/5”，五条确认后继续。

现有首期交接契约要求一组五条，本轮不增加任意条数交接。不能把选中脚本或浏览脚本当作人工确认。素材推荐目前按名称和备注匹配，不可包装成已经理解视频画面；没有匹配依据时显示待核对画面。

多候选审核与采用可参考 [CapCut 官方脚本教程](https://www.capcut.com/resource/script-writing-ai)，脚本作为场景编排主线可参考 [Pictory 官方教程](https://pictory.ai/academy/how-to-turn-script-into-video-pictory-ai)。

### 第三步：选声音并制作

默认先展示现有原生中文推荐音色，提供明确“查看全部 9 种”。每项有描述、适用场景、原生语言、同文案样音与选中状态；一次只播放一个声音。整批默认一个音色，单条覆盖留在精修。

区分“听音色样音”和“试听当前文案”：前者已有真实本地样音；后者是需验证接口和缓存的改版目标，尚不能宣称已接入。商品读音不满意时能返回文案修改。此区分参考 [Clipchamp 官方 TTS 帮助](https://support.microsoft.com/en-us/clipchamp/how-to-use-the-text-to-speech-feature)。

主动作：“制作 5 条视频”。确认当前脚本与音色后，串联交接、真实配音、按实际音频时长编排、字幕和渲染；不要求人工添加配音轨、填写起止秒数或再次粘贴脚本。缺素材先指出具体缺口。

### 第四步：看成片、修改、导出

展示五张可播放的竖版成片卡：缩略图、卖点、实际时长与待审核/已通过状态。选择一条在较大播放器中检查声音、画面和字幕；相邻位置提供“改文案”“换画面”“改字幕”。时间线位于“精细调整”，承接 B 布局。

逐条明确审核后可导出，批量栏显示选取范围和通过数量。版本编号收在详情里；是否为最新内容必须在卡片上直说。审核只认可当前真实预览，不能用首帧缩略图代替播放检查。[Adobe Express 字幕编辑](https://helpx.adobe.com/express/web/video-creation-and-editing/edit-videos/caption-video.html)、[Carbon 批量操作](https://carbondesignsystem.com/components/data-table/usage/)

## 4. 视觉方向：以真实内容为中心的制作工作台

推荐浅色编辑区与深色预览舞台组合。专业感来自清楚的层级、精确的对齐、真实媒体和完整交互状态。主体采用中文系统无衬线字体；不下载字体或加入动画依赖。

| 角色 | 建议 token | 用法 |
| --- | --- | --- |
| 工作区背景 | `#F3F5F8` | 商品资料、脚本编辑与列表 |
| 内容面板 | `#FFFFFF` | 明确分区，减少重复嵌套卡片 |
| 预览舞台 | `#202733` | 让不同明度视频都与操作区分开 |
| 正文 | `#17202D` | 文字与重要摘要 |
| 次要信息 | `#596579` | 时长、说明；对比度需实现时测量 |
| 主要动作 | `#5B50E6` | 当前步骤、选中项、唯一主按钮 |

该方向已获用户确认，token 用于隔离的 DEV 视觉稿。现有 DESIGN.md 的暖纸与锈红仍对应正式工作台；正式迁入时同步规范与全站 token。

视觉重点：

1. **脚本与画面直接对照。** 当前句子、所用镜头和预览形成同一工作区；这是产品最值得突出的特征。
2. **媒体占主要面积。** 素材使用真实缩略图；竖版预览保持 9:16，宽屏中占约三分之一工作区，不拉伸画面。
3. **五条结果形成作品墙。** 内容一眼可比较，状态和动作就近呈现；精修时仅展开当前作品。
4. **音色有可比较的听感信息。** 名称、描述、语言、试听与选中标记完整；不使用虚构人物头像暗示真人身份。
5. **排版有层级。** 标题约 24–28 px，区块标题 16–18 px，正文 14–16 px；真实操作目标至少 44 px，窄屏按步骤上下排列。
6. **交互反馈具体。** 已保存、正在制作第几条、哪个失败、如何重试都在原位置；进度只使用可测数据。动效限于切换和状态反馈，尊重减少动画设置。

本轮还实际查看了 [CapCut 官方教程的编辑器截图](https://www.capcut.com/resource/how-to-use-capcut)：素材、播放器、调整面板与时间线分区明确。借鉴其媒体与面板的比例，将大量参数只放 B 精修。LTX 的素材引用与分镜排列来自 [官方教程正文](https://ltx.io/blog/ltx-studio-tutorial)，本轮没有把其登录后界面当作已验证。

建议结构：

```text
项目 / 商品名                       已保存 · 设置
准备资料 ── 确认脚本 ── 选声制作 ── 审核导出
┌─────────────────────────┬─────────────────┐
│ 当前步骤：内容与操作      │ 当前素材/成片    │
│ 脚本摘要 / 当前文案       │ 竖版预览         │
│ 对应画面缩略图           │ 对应内容摘要     │
└─────────────────────────┴─────────────────┘
当前缺项说明                       继续 / 制作5条
```

不将复刻状态、工程日志、变体手填表和配音数值一并放入这个默认界面。

## 6. 后续实施与验收边界

先用现有公开咖啡素材做四步主流程的视觉样稿，确认层级与风格后接真实接口。新增依赖、模型、软件下载仍须用户同意。正式落地后更新 README 的操作说明；本轮 README 只添加研究与未实施状态入口。

验收须同时满足：

- 新进入者能指出资料入口和下一步，不需要解释内部术语。
- 五条脚本不用重新复制到混剪表，音色在制作前可试听选择。
- 推荐路径不用填写片段起止秒数，不用手动插入配音或字幕。
- 正常流程只呈现当前步骤；每步一个主动作，阻塞原因可直接修复。
- 单条失败可就近恢复，已成功产物保留；刷新后按真实保存状态恢复，不重复提交已有任务。
- 文案或音色改变后正确使受影响声音、预览与审核失效；两窗口版本冲突不得覆盖新草稿。
- 使用真实 MP4 验证声音、画面、字幕、审核与导出，同步检查宽屏与窄屏可用性。
- 不将公开素材技术验收称为真实客户验收；本轮没有运行产品测试或上游兼容测试。

此研究完成了选择依据和可评审方案；正式 UI 改版、连续制作编排和当前文案试听仍待实施。

## 7. 用户追加要求：全站统一改版

本节约束整个改版，前述四步只是商品视频的业务主线。不能只给 BatchEditor 添加新皮肤后宣称全站完成，也不能让新制作页和旧项目页使用两套导航、按钮及状态语言。

### 全站页面覆盖

| 区域 | 统一改版内容 | 必须保留的实际边界 |
| --- | --- | --- |
| 首页 / 项目中心 | 真实作品封面、最近项目、继续制作；“新建视频”提供商品制作与参考复刻两个清楚入口 | 旧项目仍可打开；暂无成片时显示真实素材封面或明确空状态 |
| 全站框架 | 统一侧栏、项目位置、页面标题、主操作位置和设置入口 | 切换项目与页面保留草稿；不让工程状态成为每页最醒目内容 |
| 项目制作 | 商品四步主流程；复刻按其自身准备流程组织 | 商品不出现参考复刻阻塞项；复刻不出现五脚本必填项 |
| 项目素材 | 缩略图网格、预览、选中状态与同位置详情；上传后可继续当前制作 | 素材仍归当前项目，不建立未经需求确认的跨项目共享资产系统 |
| 单条精修 | 文案 / 画面 / 预览联动，按需进入时间线；统一右侧详情 | 保留时间线保存、冲突、撤销、声音与真实渲染行为 |
| 成片与批量审片 | 可播放作品网格、逐条状态、明确的批量范围 | 审核绑定当前版本；预览、导出与交付包区分清楚 |
| 参考分析 / 镜头准备 | 输入预览、分镜缩略图、当前镜头详情和下一步；减少同时展开的工具表单 | 白模、深度与参考视频保持真实不同能力边界，外部最终生成不冒充内置 |
| 工具与处理记录 | 按任务目的组织，选素材后显示可用工具和进度，结果就近预览 | 未安装引擎明确不可用；不自动下载依赖 |
| 应用设置 / 备份恢复 | 独立清晰入口，同样的表单、反馈和说明规则 | 凭据继续现有安全存储；窄屏设置现有只读限制不擅自改变 |

建议全局导航控制为“项目、工具、设置”，新建视频为明确按钮；进入项目后再显示“制作、素材、成片”，精修从作品打开。导航名称、排序与是否需要项目内工具入口仍须结合整站视觉样稿核对。这是信息组织方案，不表示已建立新路由或新数据库。

### 跨页面一致性要求

- 一套颜色、字体、间距、圆角、图标和按钮体系覆盖所有正式页面，更新 DESIGN.md 后由共享 token 引用；禁止各模块硬编码另一套主题。
- 项目名称、当前所在位置、保存状态和主要动作在可预测的位置；项目切换不隐式启动任务或丢弃草稿。
- 表单、上传、弹窗、抽屉、播放器、列表、空状态、加载、失败和成功反馈共用交互规则。整站使用相同词汇，避免“任务 / 项目 / 变体 / 候选”混用。
- 视频与素材承担主要视觉，侧栏降低权重；复杂细节在原位置展开，避免同时出现两层侧栏加多层工具标签。
- 统一宽屏、窄屏与键盘操作设计；生产构建覆盖全部改版页面，不能仅用 DEV query 参数展示新站。
