# 商用 AI 混剪完整链路：GitHub 开源复用选型

核验日期：2026-09-29。范围是“片段级索引 → 视觉语义选片 → 混剪规划 → 复杂转场和花字 → 主体感知竖屏裁满 → 字幕模板 → 音频节奏 → 自动质检”。本报告先复用项目的[累计融合登记表](./reference-project-integration-register.md)、[Media Search Agent 深审](./media-search-agent-current-project-integration-audit-2026-09-28.md)、[OpenShorts 深审](./openshorts-current-project-integration-audit-2026-09-28.md)及[MoneyPrinterTurbo 深审](./moneyprinterturbo-current-project-integration-audit-2026-09-28.md)，再核上游固定提交、官方代码/文档和许可证。没有安装新候选、运行真实素材、验证渲染画质或取得法律意见；GitHub `pushed_at` 仅表示仓库有推送，不代表所列功能仍被维护。

## 直接结论

**没有发现一个可整套商用复用、且覆盖上述八环并能直接落到当前项目身份/审核契约的单一仓库。** 已审的端到端候选中，[MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo/blob/d7b738345e2298d3e21738140190b8a6a68cd39f/README.md)覆盖脚本、图库、配音、字幕与成片，但其[本地视频路径](https://github.com/harry0703/MoneyPrinterTurbo/blob/d7b738345e2298d3e21738140190b8a6a68cd39f/app/services/task.py#L648-L667)不做片段语义索引；[OpenShorts](https://github.com/mutonby/openshorts/blob/89f030934388d5167b3b0ede164ef893dad09ae9/README.md)主攻长视频高光和竖屏重构，缺全库片段检索与当前项目的变体审核；[Media Search Agent](https://github.com/openara-ai/media-search-agent/blob/1ea46df10b00e350c00a1cf344267a979a183db6/docs/features/video.md)做分镜向量检索，却明确不索引音频/ASR/字幕，也无混剪制作链。这是对上述仓库在固定提交的能力比较，不是对 GitHub 全部仓库的不存在证明。

可行方案是**保留当前产品主链，借多个 permissive 项目的局部模块**。当前唯一业务身份是 `ContentProject`、`ProjectAssets.assetId`、变体/Timeline/审核版本；唯一成片链是 Python FFmpeg；运行交给 `durable_runs`。候选只产出带来源区间和证据的建议，经人工改选后写入已有变体/Timeline。此约束来自[累计登记表](./reference-project-integration-register.md#1-当前项目唯一能力归属)和本地 [`project_assets.py`](../../backend/app/project_assets.py)、[`batch_production.py`](../../backend/app/batch_production.py)、[`timeline_render.py`](../../backend/app/timeline_render.py)。

## 当前项目的真实融合缺口

当前 [`timeline_render.py::_video_filter`](../../backend/app/timeline_render.py)执行 `scale=...:force_original_aspect_ratio=decrease,pad=...:color=black`，所以 16:9 素材进 9:16 会留黑边；其[`_build_command`](../../backend/app/timeline_render.py)把片段叠在黑底并逐段 overlay，目前没有转场边界对象，字幕也只是 PNG 叠加。这里必须在**计划和 Timeline schema 阶段**同时纳入转场、花字和裁剪路径，否则后期仅补滤镜会缺重叠片段时长、素材 handle、音频 crossfade、预览一致性、模板版本与审核失效。FFmpeg 官方 [`xfade` 要求两路输入同分辨率、像素格式、帧率和时基](https://ffmpeg.org/ffmpeg-filters.html#xfade)；先规范化源片段，再组转场图。下述数据字段是本项目新增建议，不是声称已经实现：

```text
SegmentCandidate: projectId, assetId, sourceFingerprint, [start,end], evidence, scores
MontageProposal: variantId, ordered segment candidates, beat anchors, reasons
TimelineClip: existing clipId/assetId/inPoint/duration + cropPathRef + graphicCueRefs
TimelineBoundary: leftClipId, rightClipId, transitionPreset, duration, audioCrossfade
FrozenPreview: timelineRevision + subtitleRevision + template/font versions + source fingerprints
QCReport: previewVersion, ruleVersion, findings[{timeRange, severity, evidence}]
```

`ProjectAssets` 保存源和授权，索引仅保存可重建派生物；视觉召回、高光模型、节拍模型各自打分，由 `MontagePlanner` 输出建议；人工确认后才进入现有 Timeline/变体。源、模板或字幕改变使旧预览和审核失效，实际视频质检只附加证据。外部库存视频经 MPT 式 Provider 检索后也要先导入 `ProjectAssets`，记录来源/作者/许可快照，不能用远端 URL 或向量 ID 作为业务身份。[本地变体版本和审核](../../backend/app/batch_production.py)、[MPT 素材来源逻辑](https://github.com/harry0703/MoneyPrinterTurbo/blob/d7b738345e2298d3e21738140190b8a6a68cd39f/app/services/material.py#L41-L156)。

## 最小可交付接入顺序

1. **一条真素材打通片段索引与候选**：受控 `assetId` → 场景 `[start,end]` → 关键帧/文本向量 → 多片段检索结果 → OpenShorts 候选排序。验证同一长视频能返回多个不同可播放源区间，换源/换模型会使索引失效。[MSA 当前折叠缺陷](./media-search-agent-current-project-integration-audit-2026-09-28.md#结论先行)。
2. **同一版 Timeline 同时落转场、花字、裁满**：MPT 式分配建议进入现有变体；边界对象驱动 `xfade`，ASS 模板驱动花字/字幕，主体轨迹驱动逐帧 crop。验证两段横屏视频的 9:16 预览无黑边、主体不越界，转场和字卡在实际预览与导出一致，编辑后审核失效。[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)。
3. **节奏与自动质检附着冻结成片**：节拍建议只辅助选边界；质检实际文件的声画、字幕安全区和时长，保留人工审核。验证有时间点的质检发现能回跳预览，不会自动批准或修改已批准版本。[librosa beat](https://librosa.org/doc/main/generated/librosa.beat.beat_track.html)、[FFmpeg 黑帧/静音检测](https://ffmpeg.org/ffmpeg-filters.html)。

以上是复用研究与实施建议，**没有引入库、复制代码或修改产品范围**。项目[累计登记表](./reference-project-integration-register.md#4-累计优先级)仍将新算法/Provider 放在真实商品试点之后的 P1；若要现在实施完整混剪能力，需要按产品范围冻结基线另行调整优先级。
