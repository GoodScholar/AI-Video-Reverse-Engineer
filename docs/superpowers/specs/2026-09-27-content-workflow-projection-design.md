# 内容制作阶段投影设计

**状态：** 已确认

**关联任务：** `.scratch/module-business-boundaries/issues/02-content-workflow-projection.md`

**决策依据：** `CONTEXT.md`、ADR 0009、现有 AIGC 内容与批量制作契约

## 1. 目标

为默认内容工作室提供唯一、可恢复的内容制作阶段投影。投影由已经保存的创作简报、脚本候选、AIGC 交接、短视频变体、配音、预览、审核和导出记录实时派生；不新增可手工修改、可能与真实对象漂移的阶段字段。

完成后：

- 刷新页面和跨页面导航仍能恢复正确步骤。
- 修改脚本、素材编排、画布、配音、字幕或时间线后，旧预览、审核和交付按现有版本规则失效。
- 每条短视频变体保留独立状态，一条失败或退回不会覆盖其他变体。
- 既有状态文件、写接口、版本冲突、预览和导出契约保持兼容。

## 2. 非目标

- 不引入通用工作流引擎、事件总线或新的持久化状态机。
- 不迁移或重写现有 AIGC、批量任务、预览、审核和导出记录。
- 不改变五条脚本交接、配音、预览、审核或导出的写入规则。
- 不把旧批次的合法快照因上游简报后来变化而删除或改写。
- 不在本任务拆分完整批量制作模块；该工作由后续任务 03 负责。

## 3. 现状与问题

当前 `ContentProductionWorkspace` 用 React 局部 `stage` 决定四步界面的当前位置，并通过 `AigcCreator`、`BatchEditor` 回调拼接完成状态。该值没有持久化事实来源，页面刷新会回到第一步；任意历史批量任务也可能使当前新简报被误判为已经进入制作。

服务端已经保存了形成投影所需的事实：

- AIGC 简报版本、候选生成批次、候选版本与确认版本。
- AIGC 交接父任务中的 `aigcGroup`，以及子任务中的来源快照。
- 脚本、时间线、字幕的独立版本。
- 配音、预览、审核和导出绑定的版本及运行状态。
- 审核的新鲜度规则和导出必须来自当前已通过预览的约束。

因此缺少的不是另一份工作流状态，而是这些事实的只读业务投影。

## 4. 方案选择

### 4.1 采用：独立只读投影接口

新增一个内容工作流投影模块和只读接口：

```text
GET /api/projects/{project_id}/content-workflow
```

接口在同一个项目写锁下读取 AIGC、批量制作和项目素材状态，调用纯投影函数后返回结果。投影模块只依赖窄的状态读取接口和现有版本判定函数，不调用其他 HTTP 路由，也不写入任何状态文件。

优点：

- 业务规则只有一个服务端来源。
- 不产生双写或阶段漂移。
- 前端刷新、导航和多个入口得到相同结论。
- 可用纯输入/输出测试覆盖完整状态矩阵。

### 4.2 不采用：前端组合现有接口

让前端同时读取 AIGC 与批量制作工作区虽然改动较少，但会把版本新鲜度、活动批次选择和混合审核状态继续留在 React 中，无法形成权威业务边界。

### 4.3 不采用：持久化工作流状态机

新增可写 `stage` 会与简报、变体、运行和审核记录形成第二套事实，需要所有写路径同步更新，故意制造本任务要消除的漂移风险。

## 5. 模块边界

建议新增：

- `backend/app/content_workflow.py`：纯投影、阶段枚举和新鲜度组合规则。
- `backend/app/content_workflow_api.py`：项目校验、状态读取、错误映射和 GET 路由。
- `frontend/src/contentWorkflowApi.ts`：响应类型与读取函数。

现有模块只暴露投影真正需要的窄接口：

- AIGC 内容状态读取。
- 批量制作状态读取。
- 审核版本、审核状态等已经存在的纯判定函数。

不得让投影模块反向调用路由处理器，也不得在前端复制 `_review_status` 一类服务端规则。

## 6. 活动工作选择

项目可以保留多个历史简报、交接批次和独立批量任务。投影必须区分“当前默认制作”与“仍可访问的历史工作”。

选择规则：

1. 取当前简报版本下最后一组脚本候选作为当前脚本生成。
2. 使用现有交接算法，以当前 `generationId`、当前 `briefRevision` 和五条候选的 `(candidateId, candidateRevision)` 计算 `aigcHandoffKey`；只有父任务保存的 key 完全相等时，才是当前活动批次。`aigcGroup` 只用于识别历史来源，不足以证明交接仍覆盖当前脚本版本。
3. 更早简报、更早脚本生成或同组候选的旧版本交接只计入历史，不得使当前新简报或已修改脚本自动跳到选声或审核步骤。
4. 对没有 AIGC 创作记录的旧项目，允许以最后一个拥有子变体的批量父任务作为兼容活动批次。
5. 历史批次的快照和审核仍然有效；它们只是不能替代当前创作的阶段事实。

该规则沿用现有状态数组的追加顺序，不新增 `activeStage` 或迁移字段。

## 7. 阶段模型

投影使用以下用户可见语义：

```text
draft
→ brief_ready
→ scripts_confirmed
→ voice_ready
→ preview_ready
→ review_pending
→ approved | rejected
→ delivered
```

不是每个项目都必须逐个停留在所有阶段。例如没有配音但已经存在合法当前预览的旧项目，可以直接越过 `voice_ready`；单条变体的预览一旦就绪，也可能立即成为 `review_pending`。

### 7.1 上游阶段

- `draft`：商品名称为空、没有商品事实、少于两项当前可用的图片或视频素材，或者当前简报尚无可用保存版本。
- `brief_ready`：简报满足生成前置条件，但当前简报下最后一组候选不是恰好五条当前确认脚本。
- `scripts_confirmed`：当前简报下最后一组候选恰好五条，且每条 `confirmedRevision == revision`、`briefRevision == 当前简报 revision`；尚未进入更后的活动批次事实。

简报在交接前变化会使旧候选退出当前阶段。交接后产生的批量任务拥有自己的脚本和素材快照，上游继续编辑不会改写该历史批次。

### 7.2 单条变体阶段

每条活动子变体独立计算，优先使用当前版本的最深合法事实：

1. `delivered`：存在完成的导出，且脚本、变体、字幕、预览和已通过审核均与当前版本一致。
2. `approved` / `rejected`：现有审核新鲜度函数对当前版本返回对应决定。
3. `review_pending`：存在当前有效预览，但没有当前版本审核。
4. `voice_ready`：配音状态为完成，且配音绑定当前脚本、变体和字幕版本。
5. `scripts_confirmed`：变体由当前活动交接产生，但还没有更深的当前事实。

当前有效预览要求：

- 使用最后一次预览运行。
- 运行状态为 `completed`。
- 脚本、变体和字幕版本等于当前版本。
- 预览快照的画布与轨道等于当前保存值。
- 预览字幕等于当前字幕。
- 如果存在配音记录，配音必须为当前完成版本。

预览已证明下游制作可用时，不因“没有配音记录”而回退，以兼容既有无配音预览。

### 7.3 项目聚合阶段

项目级 `stage` 是当前活动工作的“下一处业务瓶颈”，不是把所有变体压成一个最终决定：

- 尚无活动批次时，使用上游阶段。
- 有活动批次但没有任何当前配音或预览时，为 `scripts_confirmed`。
- 所有可制作变体已有当前配音、尚无当前预览时，为 `voice_ready`。
- 至少一条已有当前预览、但并非所有可制作变体都可审核时，为 `preview_ready`。
- 所有可制作变体都可审核，但仍有未决定、失效或混合通过/退回结果时，为 `review_pending`。
- 所有可制作变体均为当前通过时，为 `approved`。
- 所有可制作变体均为当前退回时，为 `rejected`。
- 所有当前通过变体都已有当前完成交付，且没有其他未处理变体时，为 `delivered`。

生成失败、预览失败或导出失败作为对应变体的 `issues` 返回，不覆盖兄弟变体的阶段。失败变体不被静默视为完成。

## 8. 响应契约

建议响应形状：

```ts
type ContentWorkflowStage =
  | "draft"
  | "brief_ready"
  | "scripts_confirmed"
  | "voice_ready"
  | "preview_ready"
  | "review_pending"
  | "approved"
  | "rejected"
  | "delivered";

type ContentWorkflowProjection = {
  stage: ContentWorkflowStage;
  currentStep: 0 | 1 | 2 | 3;
  completedSteps: [boolean, boolean, boolean, boolean];
  activeGenerationId: string | null;
  activeBatchId: string | null;
  counts: {
    total: number;
    pending: number;
    approved: number;
    rejected: number;
    delivered: number;
    failed: number;
  };
  variants: Array<{
    taskId: string;
    stage: ContentWorkflowStage;
    reviewStatus: "pending" | "approved" | "rejected" | "stale";
    currentPreviewRunId: string | null;
    currentExportRunId: string | null;
    issues: Array<{ code: string; message: string }>;
  }>;
  issues: Array<{ code: string; message: string; taskId?: string }>;
};
```

`issues.code` 使用稳定机器码，`message` 提供用户可读原因。第一轮只返回界面实际需要的标识和计数，不复制完整简报、时间线、审核或运行对象。

## 9. 四步界面映射

现有四步保持不变：

| 服务端事实 | 当前步骤 | 完成标记 |
| --- | ---: | --- |
| `draft` | 0 准备资料 | 无 |
| `brief_ready` | 1 确认脚本 | 准备资料 |
| `scripts_confirmed` | 2 选声制作 | 准备资料、确认脚本 |
| `voice_ready` | 2 选声制作 | 准备资料、确认脚本 |
| `preview_ready` 及以后 | 3 审核导出 | 准备资料、确认脚本、选声制作 |
| `delivered` | 3 审核导出 | 四步全部完成 |

`ContentProductionWorkspace` 删除把局部 `stage` 当作事实的用法，改为：

- `viewStep` 仅表示用户此刻查看的步骤。
- 首次加载或切换项目时，用投影 `currentStep` 初始化 `viewStep`。
- 步骤是否完成、是否可点击、是否允许进入审核由投影决定。
- 用户可以返回已完成步骤查看或编辑，但这不会改写服务端阶段。
- 保存简报、确认脚本、完成交接、配音、预览、审核、导出或相关编辑成功后，触发投影刷新。
- 投影读取失败时显示真实错误，不回退为看似有效的本地进度。

为避免请求瀑布，内容工作区首次进入时可与现有 AIGC、批量工作区读取并行请求投影；子组件 mutation 成功后只刷新投影，不串行重载无关目录。

## 10. 失效与兼容规则

| 变更 | 投影结果 |
| --- | --- |
| 交接前修改简报或素材选择 | 当前候选失去确认资格，回到 `brief_ready` |
| 修改已交接子任务脚本 | 当前配音、预览、审核和交付失效，该变体回到 `scripts_confirmed` |
| 修改画布、素材编排或时间线 | 当前预览、审核和交付失效；当前配音若版本不匹配也失效 |
| 修改字幕 | 当前预览、审核和交付失效 |
| 重新生成配音 | 运行中显示问题状态；完成后进入 `voice_ready`，旧预览和审核按版本规则失效 |
| 预览失败 | 仅对应变体返回失败问题，兄弟变体保持原状态 |
| 审核退回 | 仅对应变体为 `rejected`；其他变体审核状态不变 |
| 修改退回变体并保存 | 该变体旧审核变为 `stale`，回到其当前最深合法阶段 |
| 当前通过后导出完成 | 对应变体进入 `delivered` |
| 上游简报在历史交接后变化 | 新创作回到上游阶段；历史批次快照和历史审核仍可访问 |

## 11. 错误处理

- 项目不存在：沿用 `404 project_not_found`。
- AIGC 或批量状态损坏、无法读取：返回明确 `503`，不得伪装为 `draft`。
- 单条历史记录业务失败：在 `issues` 中返回，不使整个投影接口失败。
- 状态结构不满足既有校验：仍作为存储损坏处理，不在投影中猜测或修复。
- GET 接口无副作用，不创建缺失目录或状态文件。

## 12. 测试策略

按 TDD 分三层实现：

1. 纯投影单元测试
   - 覆盖九种阶段、活动批次选择、旧项目兼容和混合变体。
   - 使用状态对象直接测试，不依赖 FastAPI 或文件系统。
2. 后端接口测试
   - 覆盖刷新恢复、损坏状态错误、版本失效、审核独立性和导出完成。
   - 复用现有 AIGC、配音、预览、审核与导出测试夹具。
3. 前端集成测试
   - 先证明当前实现刷新后回到第一步。
   - 验证服务端投影恢复步骤、点击仅改变视图、mutation 后刷新投影、读取失败不伪装进度。

最终运行受影响定向测试、完整前端测试、完整后端测试、生产构建和 `git diff --check`。

## 13. 成功标准

- 仓库中不存在新的可写阶段字段。
- 页面刷新后四步状态与服务端保存事实一致。
- 所有失效规则使用既有版本和快照契约，而不是时间或前端猜测。
- 混合批次中每条变体的审核与交付状态可独立解释。
- 历史状态文件无需迁移即可读取。
- 现有 API 和测试保持兼容，新测试覆盖投影新增行为。

## 14. 自检

- **领域一致性：** 投影不拥有真实对象，只解释内容项目内对象的生命周期，符合 ADR 0009。
- **状态唯一性：** 没有新增手工阶段或双写路径。
- **边界深度：** 前端只消费小型投影接口，版本与聚合规则封装在服务端纯模块中。
- **批量语义：** 项目阶段表达下一处瓶颈，变体阶段表达真实独立结果，避免一个全局状态吞掉混合结果。
- **兼容性：** 无配音预览、旧批量项目、历史交接和现有写接口均有明确处理。
- **范围控制：** 不顺带拆分批量模块、不迁移存储、不改变最终生成边界。
