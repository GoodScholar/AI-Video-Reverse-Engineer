# 以镜头列表和受约束关系图共同投影制作镜头

**状态：** accepted

**日期：** 2026-09-27

**部分取代：** ADR 0007 中“以列表组织节点功能，取代无限画布”的界面结论

制作镜头、场景、流程节点、素材引用和结果候选采用一份权威领域模型；镜头列表负责管理顺序与批量操作，受约束的镜头关系图负责依赖、分支、复用和空间上下文。每个制作镜头只有一个规范 ShotNode，列表、关系图、分镜板和时间线来源定位都引用同一镜头身份，不分别保存镜头副本。

关系图不是通用无限画布。节点类型和端口来自受控目录，依赖为可校验的有向边；画布布局单独保存，不改变镜头排名、时间线位置、内容修订或结果有效性。时间线仍拥有真实播放顺序，最终 AI 视频生成仍依 ADR 0007 在外部工具完成。

前端使用成熟节点画布库作为渲染与交互适配层，不从零实现画布内核，也不完整移植 BeefTV 或 basketikun/infinite-canvas 的生成、插件、存储和业务运行时。代价是需要新增统一选择状态、领域命令、布局存储和 v1 到 v2 迁移；收益是保留列表的可管理性，同时为复杂依赖提供高自由度表达，并避免多视图数据漂移。
