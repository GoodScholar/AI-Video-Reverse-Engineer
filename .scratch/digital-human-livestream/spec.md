# 数字人直播代运营：快手电商首场试点

Status: needs-info

本规格是第三阶段的**备用试点计划，目前暂停推进**。只有智能剪辑完成真实素材验收，且 AIGC 内容创作的首期与 AI 全新画面、自动配音、音乐生成、客户自助等完整目标均实现并通过真实客户验收后才重新启动。本规格不表示已经取得快手直播权限、女娲或服务商接入资格，也不表示本地工作台已经具备直播推流和自动互动能力。公开平台依据见[官方资料核验](../../docs/research/digital-human-livestream-platforms-2026-09-25.md)，完整服务方向见[路线图](../ai-content-services/roadmap.md)。

## 试点目标

面向一位愿意授权试播的电商商家，在快手平台以女娲或平台认可的服务商提供数字人能力，完成单商品组、约 60 分钟、全程有人值守的短场直播。首场验证获准开播、已审核 FAQ 的受控自动回答、其他评论的人工处理、人工接管和数据复盘。成交额与投入产出记录为观察项，不作为首场通过条件。

“7×24 小时不间断直播”保留为后续业务目标；首场不承诺连续长时段、无人值守、预录循环或跨平台通用接入。

## 服务与产品分工

| 参与方 | 首场职责 |
| --- | --- |
| 商家 | 提供并逐场确认商品事实、价格、优惠、禁用表达及可用商品/形象/声音素材；授权试播账号和商品；指定异常与投诉的联系人。确认内容变更后，原确认版本不得继续用于直播。 |
| 内部交付团队 | 准备话术和 FAQ、保存商家确认版本、完成开播检查、全程值守、处理未授权自动回答的评论、接管与停播、记录事件并复盘。 |
| 女娲或平台认可的服务商 | 明确数字人生成/驱动、直播控制台、受控 FAQ、人工接管、故障处理和可导出数据的实际能力与服务边界；提供适用账号的正式接入路径。 |
| 快手及试点账号 | 以平台规则、实际账号直播权限和对具体直播模式的答复为准。公开接口或产品宣传不能替代上述核验。 |

## 首场工作流

1. **招募与授权**：找到一位电商商家，核对快手经营及直播账号、商品类目、直播权限、素材与数字人形象/声音授权；记录账号控制人与授权范围。
2. **供应方案核实**：向女娲或平台认可的服务商说明单商品组、约 60 分钟、有人值守、已审核 FAQ 自动答、人工接管的具体模式，取得可留存的接入、规则适用、费用和支持方式答复；确认试点账号实际可用。
3. **内容准备**：复用现有创作简报和已审核素材形成直播话术、FAQ、禁用表达与商品信息快照。商家逐场确认商品事实、价格、优惠、素材和最终播出版本。直播场景内容需单独审核，不直接把短视频脚本视为可播话术。
4. **排练与开播检查**：在供应商允许的环境中验证画面、声音、商品展示、FAQ 命中、未覆盖问题转人工、人工接管、停播和断流处理。值守人员、商家联系人和服务商支持渠道均可联系后才开播。
5. **受控试播**：全程有人值守；自动回复只使用已审核 FAQ。涉及未确认的商品事实、价格、优惠、投诉或其他 FAQ 外问题时交由人工处理。发现错误宣传、无法接管、账号警告或重大故障时先停用相关自动能力，必要时停播。
6. **复盘**：从平台或服务商后台人工导出可获得的数据并核对来源，记录实际时长、播放/互动、FAQ 与人工处理、接管、故障及处理结果；成交数据只有在商家授权且后台可得时记录，不可得则标明。商家和交付团队共同确认下一轮调整。

## 本地工作台功能规划

首场可先用受控文档和服务商控制台完成流程验证；不以开发平台接口为试播前提。待接入路径确认后，按以下顺序评估本地工作台功能，保持客户资料与已批准内容可追溯：

1. **直播内容包**：关联项目中的商品事实与授权素材，保存直播话术、FAQ、禁用表达、商家确认版本及适用场次；商品、价格或优惠变化时提示重新确认。
2. **场次与检查表**：记录平台、账号标识、供应商、商品组、排班、人工接管人与开播前检查结果；不在工作台保存直播账号密码或推流密钥。
3. **事件记录与复盘**：按时间记录回答、人工接管、断流、平台提醒及处理；导入或录入后台导出的指标，保留数据来源和缺失项，输出人工可审核的复盘报告。

上述是功能规划，不代表接口已开放。只有在实际账号和服务商授权、数据边界明确且首场证实需要时，才规划实时状态、评论或数据 API 集成。跨平台复用不得假设视频号、淘宝、快手具有相同规则与字段。

## 首场通过条件

- 试播前留有商家逐场内容确认、素材/形象/声音授权、平台或认可服务商对具体模式的接入依据，以及账号权限核验记录。
- 在单商品组、约 60 分钟的有人值守场次中按获准方式开播和结束；若出现平台警告或违规处置，首场不判为通过，先核查原因。
- 至少实测一条已审核 FAQ 的正确回答、一条 FAQ 外问题的人工处理，以及一次计划内人工接管或停用自动回答；未获供应商支持的能力不得用人工模拟冒充已验证。
- 直播内容未使用未经商家确认的价格、优惠或商品主张；发生不确定内容时值守人员按预案处理并记录。
- 形成含数据来源、可得指标、事件、问题和下一轮修改建议的复盘记录；缺失的成交或互动数据明确标注。

任一启动条件未满足时可以完成内部话术排练，但不能把排练记为真实平台试播。若供应商不能提供受控 FAQ 或人工接管能力，需重新选择供应方案或调整试点规格，不能静默降低通过条件。

## 后续阶段与待核实事项

- **长时段试验**：首场通过后，再确定排班覆盖、替班、断流恢复、服务商支持时段、成本与允许的开播时长；逐步延长单场时长，最后才评估 7×24 服务承诺。
- **其他平台**：淘宝先核对服务商入驻或合作路径及试点商家的店铺权限；视频号先就具体实时数字人形式取得平台认可。两者不沿用快手试播结论。
- **仍需外部事实**：试点商家与账号、商品与授权素材、女娲/服务商的实际准入和报价、受控 FAQ 与人工接管方式、平台规则适用答复、可导出指标与数据授权。

## 不在首场范围

自建数字人生成与推流、自动获取账号密钥、直播评论自由生成回复、无人值守、7×24 承诺、自动成交归因、跨平台同时开播，以及在接入授权前开发快手实时接口。
