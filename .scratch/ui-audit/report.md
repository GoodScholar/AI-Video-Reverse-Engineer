当前界面具备一致的检片台风格，基本导航、表单与本地处理状态可用，但尚不宜宣称 UI 全面通过。确认 **7 类问题：P1 两类、P2 四类、P3 一类**。优先解决草稿丢失、键盘上传不可达及嵌套样式污染。

## 已确认的问题

### 1. [P1] 离开项目会静默丢弃未保存镜头

- 位置：`frontend/src/App.tsx:234`、`:249`；`frontend/src/PreproductionWorkspace.tsx:73`。
- 复现：在镜头页新建镜头并添加七个步骤，页面显示“有未保存更改”；点击返回项目首页后重新进入，镜头和步骤均归零。离开前没有提示，重新进入也没有恢复草稿。
- 影响：误点顶部品牌或返回按钮可能丢失已整理的镜头内容。时间线已有缓存不能保护前置工作台草稿。
- 建议：将脏状态纳入项目退出流程，提供保存/保留草稿/放弃的明确处理；按项目持久化草稿并保持版本校验。建议 `$impeccable harden`。

### 2. [P1] 素材与音频上传缺少键盘路径，角色上传缺少可见焦点

- 位置：`frontend/src/PreproductionWorkspace.tsx:233`；`frontend/src/TimelineEditor.tsx:276`；`frontend/src/characterMotion.css:6`。
- 证据：前两处文件 input 使用 `hidden`，实测 `display:none`、调用 focus 后无法获得焦点；外部 label 的 tabIndex 为 -1，没有可聚焦按钮。角色上传 input 虽可聚焦，但 opacity 为 0，外层没有可见焦点指示。
- 影响：键盘用户无法使用主要上传入口，或不知道焦点已经到达角色上传。涉及 WCAG 2.1.1 / 2.4.7。
- 建议：采用可聚焦按钮触发文件选择，或保留视觉隐藏但可访问的 input，并在可见标签上提供 focus-within 样式。建议 `$impeccable harden`。

### 3. [P2] 工作台通配表单样式污染嵌入工具

- 位置：`frontend/src/preproduction.css:21–22`；`frontend/src/styles.css:25`；`frontend/src/videoToolkit.css:1`。
- 证据一：1440px 桌面工具页的 document.scrollWidth 为 **1833px**。`#reference-media-file` 原为 1px 隐藏控件，被更高优先级规则改为 **1440×42px**，右边缘到 1833px，形成整页横向溢出。
- 证据二：视频工具的 `.tool-asset` 原为横向 flex，嵌入后被 `.preproduction-workspace label` 改为 grid，复选框和文件名分成两行，列表密度和对齐失常。
- 建议：把输入/标签规则限制到前置工作台自身表单，不覆盖所有后代；显式排除隐藏、file、checkbox、radio 控件。建议 `$impeccable adapt`。

### 4. [P2] 导航与筛选的选中状态只有视觉样式

- 位置：`frontend/src/PreproductionWorkspace.tsx:218`、`:234`。
- 证据：工作台当前按钮只有 `is-active`，没有 aria-current/aria-selected；素材标签筛选也没有 aria-pressed。
- 影响：读屏用户难以确认当前页面与已启用筛选。建议为页面导航添加 aria-current，为筛选按钮添加 aria-pressed；若使用 tabs 模式则实现完整键盘契约，而不是只加 role。建议 `$impeccable harden`。

### 5. [P2] 部分操作目标明显偏窄

- 位置：`frontend/src/timeline.css:31`；`frontend/src/preproduction.css:57`、`:34–36`。
- 实测：时间线静音、隐藏、排序等按钮为 **20×44px**；镜头排序宽度 21px；素材预览 summary 高度 18px。
- 影响：触控或精细指针操作容易误触，偏离项目 DESIGN.md 的 44px 操作目标约定。这里不将所有小尺寸自动认定为 WCAG 2.1 AA 违规。
- 建议：扩大命中区域，紧密排列的图标需同时增加间距；素材预览/下载保留清晰可见焦点。建议 `$impeccable adapt`。

### 6. [P2] 交付提醒文字对比度低于 AA 阈值

- 位置：`frontend/src/preproduction.css:85`。
- axe 实测：普通 16px 文本前景 `#955b14`、背景 `#e9e7de`，对比度 **4.47:1**，低于 4.5:1。三个主要宽度均复现。
- 建议：略微加深提醒文字颜色，并检查相同状态颜色的其他用法；重新测量而不只靠目测。涉及 WCAG 1.4.3，建议 `$impeccable colorize`。

### 7. [P3] 角色动画面板圆角偏离既有设计系统

- 位置：`frontend/src/characterMotion.css:1`。
- 证据：角色面板使用 16px 圆角；DESIGN.md 规定区块保持方正、控件仅使用 2–3px 小圆角。与相邻平面工具区不一致。
- 建议：沿用现有容器边界和间距，不需要引入新组件库。建议 `$impeccable polish`。

## 保持的优点与误报排除

- 既有暖灰、锈红、系统字体和分区样式总体一致；首页和新建表单在桌面及窄屏下可读，创建输入自动获得可见焦点。
- 预处理状态有文字与图标；素材来源、旧预览版本、未满足前置条件和禁用状态均有说明。
- 390px 与 768px 主页面没有整页横向溢出；手机导航条和剪辑画布自身横向滚动属于局部容器设计，不能当作整页溢出。
- 检测器仅报告两处锈红左边线；它们符合已批准的检片台信号导轨，不作为缺陷。
- 当前未承诺暗色主题，不将没有暗色模式计为缺陷。被禁用的窄屏配置与模型操作符合现有只读约定，不作为无效按钮。
- 截图中悬停项和当前项同时有底色，不代表两个页面同时被选中；源代码和 DOM 只有一个当前 section。

## 建议修复顺序

1. `$impeccable harden`：草稿退出保护、键盘上传、焦点和选中状态。
2. `$impeccable adapt`：隔离表单样式，修复溢出与触控目标。
3. `$impeccable colorize`：修正并测量提醒对比度。
4. `$impeccable polish`：统一角色面板边界，最后对相同状态和尺寸复验。

截图与测量结果保存在本目录 `evidence/`。可按以上顺序集中修复，随后重新审查受影响页面。
