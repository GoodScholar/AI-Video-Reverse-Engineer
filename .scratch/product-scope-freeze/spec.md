# AI 视频创作与生产工作台：完整产品规划与范围冻结基线

Status: resolved
Type: product-baseline
Decision date: 2026-09-29

本文件是当前产品范围、实施优先级和完成标准的权威基线。它不替代各功能规格中的详细行为，也不把规划中的能力描述成已经实现；当历史路线图、研究报告或旧规格与本文件的当前范围冲突时，以本文件和相关 ADR 为准。

## 1. 产品定位

AI Video Reverse Engineer 的产品定位是 **AI 视频创作与生产工作台**。它以一个内容项目统一承载 AI 商品内容创作、已有素材批量混剪、参考图片或视频复刻准备、项目素材、制作镜头与关系图、编辑序列、配音字幕、预览审核和交付。

当前首要用户是内部交付团队：他们需要把真实商品事实和获准使用的素材转成多条可编辑、可审核、可追溯的营销短视频。ComfyUI 创作者和参考复刻操作者继续使用参考复刻工作流，但该工作流不阻塞当前 v1 完成。

产品不是：

- 单一参考复刻工具；
- 随机素材拼接器；
- 通用 Agent 工作台；
- 专业 NLE 的完整替代品；
- 在应用内自建全部图片、视频和音乐模型的生成平台。

当前应用不把最终 AI 视频生成作为内置执行链。工作台负责分析、计划、素材和镜头编排、运行快照、结果回填、剪辑、审核与交付；将来若重新开放应用内发起外部生成，必须通过新的范围决策和 ADR。

## 2. v1 的唯一黄金流程

v1 只有一条决定发布是否完成的黄金流程：

```text
创建内容项目
→ 核实商品事实与素材来源/使用范围
→ 保存创作简报
→ 披露实际发送内容、供应商和模型
→ 真实调用已验证的 AI 脚本服务生成 5 条候选
→ 人工编辑并逐条确认当前脚本版本
→ 试听并选择音色
→ 生成与确认脚本绑定的本地配音
→ 建立至少 2 条镜头安排不同的短视频变体
→ 编辑字幕、音频和变体编辑序列
→ 生成真实预览
→ 人工完整听看并逐条审核
→ 只从当前有效的批准预览导出最终 MP4
→ 保存版本、运行、审核和交付证据
```

黄金流程以一个真实商品完成试点交付。当前优先继续使用“大窑果味汽水”；必须先核实现有图片是否对应正确商品、包装和规格，并确认本次内部试点及最终展示的使用范围。若无法确认，应更换为自有或明确授权的真实商品素材，不能降低验收标准。

## 3. 三个创作入口

三个入口只是开始方式，不是项目类型，也不建立三套项目或素材系统。

| 创作入口 | 起点 | 进入的现有对象 | 当前优先级 |
| --- | --- | --- | --- |
| AI 商品内容创作 | 商品事实、目标受众、卖点、禁用表达和项目素材 | 创作简报、脚本候选、短视频变体 | P0 黄金流程 |
| 已有素材批量混剪 | 已有脚本、卖点或项目素材 | 批量任务、短视频变体、变体编辑序列 | 当前能力；不单独阻塞 v1 |
| 参考素材复刻 | 参考图片或视频 | 参考分析、制作镜头、候选 Workflow、外部结果回填、主编辑序列 | 当前保留；P1 维护与增强 |

同一个内容项目可以先后使用多个入口。入口不能改变项目素材身份、制作镜头身份、版本、审核或交付边界。

## 4. 信息架构

P0 保留现有八页结构，不新增一级页面：

| 层级 | 页面 | 职责 |
| --- | --- | --- |
| 全局 | 项目中心 | 新建、打开和恢复内容项目 |
| 全局 | 本地工具 | 集中承载深度、分镜、姿态、蒙版、插帧、超分和语音识别等工具 |
| 全局 | 应用设置 | AI 服务、本地声音与渲染说明、文件和备份 |
| 项目 | 商品视频制作 | 准备资料、确认脚本、选声制作、进入审核 |
| 项目 | 项目素材 | 管理项目内媒体、来源、备注、可用性和引用 |
| 项目 | 成片与审片 | 查看变体预览、给出审核决定、导出和回看历史 |
| 项目 | 单条精修 | 编辑从审片选中的同一短视频变体，不创建第二份作品 |
| 项目 | 参考视频复刻 | 参考分析、制作准备、结果回填和复刻交付 |

旧版复刻工作台只提供历史兼容访问，不再接收新产品功能。只有新内容工作室能够读取并编辑全部历史复刻项目，且备份恢复与迁移验收通过后，才单独立项移除旧工作台。

## 5. 完成的三层含义

### 5.1 P0 技术基线完成

黄金流程所需功能、版本失效、恢复、审核门禁、数据完整性和真实媒体输出全部通过约定检查。公开素材技术演示可以提供工程证据，但不能独立满足试点交付。

### 5.2 P0 试点交付完成

一个真实商品使用来源和使用范围可追溯的素材，完成正式五条脚本候选和至少两条不同镜头作品；当前审核人完整听看并批准，最终导出批准预览对应的交付文件。不要求已经存在付费客户或投放数据。

### 5.3 商业交付验收

在试点交付基础上，由真实客户确认商品事实和素材授权，并对最终作品给出可追溯的签收或修改结论。商业交付验收不是 v1 完成的前提，但没有它时不得宣称真实客户交付已经通过。

v1 完成要求同时满足 5.1 和 5.2。P1、P2、延后和预留能力均不阻塞 v1。

## 6. 范围分类规则

| 分类 | 定义 |
| --- | --- |
| P0 | v1 和试点交付必需；当前只允许完成黄金流程、真实商品验收及数据完整性、恢复、审核门禁和既有范围冲突修复 |
| P1 | v1 完成后提升核心生产效率或质量，仍属于当前工作台，但不阻塞 v1 |
| P2 | 已认可的较大扩展，需要独立规格、验收和实施周期，不进入当前开发队列 |
| 延后 | 方向可能有价值，但受客户、平台、供应商、权利或商业模式等外部条件阻塞，不承诺实施时间 |
| 预留 | 只守住数据边界或适配接口，不承诺当前产品功能 |
| 不引入 | 会破坏单一真相源、人工审核或结果真实性的做法；不是对所有相邻能力的永久封禁 |

## 7. P0 模块与完成边界

| 模块 | P0 拥有的范围 | 当前状态与剩余工作 |
| --- | --- | --- |
| 内容项目 | 创建、打开、保存、恢复和统一工作流入口 | 已有；试点需从正式入口完整执行 |
| 项目素材 | 上传/导入、稳定 `assetId`、来源和使用范围、引用保护 | 已有；删除引用检查需覆盖 AIGC 与批量变体 |
| 商品简报 | 商品事实、受众、卖点、行动引导、禁用表达和素材范围 | 已有；需用核实后的试点资料完成 |
| AI 脚本候选 | 发送披露、真实服务调用、五条结构化候选、人工编辑和确认 | 本地功能已实现；试点尚未真实走通 |
| 音色与配音 | 多音色试听、明确选择、本地配音、真实时长、脚本版本绑定 | 技术闭环已有；试点读音和听感待批准 |
| 批量混剪 | 变体身份、脚本驱动编排、独立失败、至少两条不同镜头作品 | 技术闭环已有；当前不能声称视觉语义选片 |
| 字幕与音频 | 可编辑字幕、声画对应、混音和最终烧录 | 技术闭环已有；试点内容待验 |
| 编辑序列与渲染 | 变体编辑序列、预览、最终 9:16 交付、取消和恢复 | 已有；试点需最终 720×1280 导出 |
| 审核与交付 | 逐条通过/退回、输入变化后失效、只导出当前批准预览 | 已有；大窑现有两条预览尚未批准和最终导出 |
| 版本与恢复 | 草稿、输入快照、运行记录、失败重试、备份恢复和历史追溯 | 已有；需纳入同一次试点证据 |
| 基础质量 | 黄金流程桌面操作、关键键盘路径、移动查看和明确错误 | 已有历史证据；需按本轮状态复核受影响路径 |
| 范围边界修复 | 关闭仍可提交最终生成的旧 API 行为 | 文档与代码存在冲突，属于 P0 修复 |

P0 不新增新的一级产品模块。已经实现的多比例能力继续保留，但试点只以 9:16 为交付门槛。

## 8. P1：v1 后的核心增强

- 维护并真实验收参考图片/视频分析、深度控制、候选 Workflow 导出和外部结果回填；
- 本地长视频自动拆镜头、高光候选、活跃说话人与竖屏重构；
- `MontagePlanner` 的脚本驱动素材分配、去重、来源记录和跨变体差异化；
- 视频片段视觉语义检索；
- 跨项目共享素材库，选用后必须显式导入 `ProjectAssets`；
- 外部开放素材 Provider 及来源、作者、许可和取得时间快照；
- ComfyUI 产物元数据和生成配置追溯；
- 镜头关系图的受控依赖连线、端口校验和持久化；
- 制作镜头到编辑序列的稳定来源关联；
- 参考镜头段导入制作镜头后的来源版本与显式重新导入；
- 配音语速、情绪等经过验收的控制项；
- 付费调用前的费用与外发确认；
- 依赖过期、迟到结果和并发写回保护。

## 9. P2：已认可的大型扩展

- AI 生成全新商品图片；
- AI 生成全新商品视频镜头；
- AI 音乐生成；
- Agent Storyboard 和跨镜头一致性建议；
- 受控 ComfyUI Workflow 导入、规范化和校验；
- 多语言变体、配音、字幕、审核和交付；
- 当前 FastAPI 之上的公开自动化 API；
- 面向已批准功能的有限 MCP 接口。

P2 必须使用当前内容项目、项目素材、制作镜头、编辑序列、运行、审核和交付模型，不得建立平行系统。

## 10. 延后与预留

### 延后

- 客户独立网页工作台；
- 多客户、多品牌 SaaS；
- 多人实时协作与权限；
- 套餐、积分和计费；
- 自动发布与平台账号接入；
- 数字人直播代运营；
- 企业级素材权利和 DAM 管理。

### 预留

- 分布式 Worker 和集群调度；
- 通用插件市场和通用 MCP 扩展层；
- `Publisher Adapter`；
- 外部生成服务 Adapter；
- 更大规模存储与索引的替换边界。

## 11. 可重新立项，但必须换一种实现方式

以下方向不是永久放弃，但不能按原先会产生平行系统的形态实现：

- 应用内发起 AI 视频生成：只能通过当前项目、素材、运行快照和结果回填边界接入外部生成服务，并须用新 ADR 取代现行外部生成边界；
- Agent：只能成为脚本、Storyboard、选片、连续性或质量提示等受限助手，产出候选而非批准；
- 时间线增强：可以逐项增加转场、关键帧、文字样式和轨道能力，但不自建完整专业 NLE；
- 自动发布：只能消费仍然有效的批准交付版本；
- Redis、数据库、对象存储和分布式 Worker：只能在出现可测量瓶颈后替换现有模块底层，不能长期双写；
- MoviePy、Remotion 或其他渲染引擎：只能隐藏在当前渲染接口后迁移或替换明确能力，不能建立平行成片链；
- 上游开源能力：只按固定提交和许可审计选择算法、规则、交互或数据结构进行适配，不整套迁入应用。

## 12. 长期不引入的约束

- 第二套项目、素材身份、制作镜头、任务状态、编辑序列、审核或交付真相源；
- 让生成成功、Agent checkpoint、模型评分或质量检测自动等于审核批准；
- 绕过人工审核直接发布；
- 用随机重排冒充智能选片或差异化混剪；
- 用文件路径、名称字符串、供应商 ID 或向量 ID 代替稳定业务身份；
- 为复刻参考项目而整套引入其业务模型、项目状态和运行时；
- 因扩容而长期双写两套存储或队列；
- 忽略许可证、素材权利、外发授权或费用确认。

## 13. 唯一数据归属

| 领域对象 | 唯一归属 | 关键规则 |
| --- | --- | --- |
| 内容项目、当前参考素材 | 项目工作区 | 所有创作入口共享同一个项目身份 |
| 项目素材 | `ProjectAssets` | 业务对象只引用稳定 `assetId`；有当前或历史引用时禁止硬删除 |
| 创作简报与脚本候选 | 内容简报模块 | 确认绑定简报和候选版本，不拥有渲染或审核状态 |
| 参考镜头段 | 参考分析/镜头准备 | 是带源时间范围的分析对象，不等于制作镜头 |
| Scene、制作镜头、流程节点和结果候选 | 制作计划 | 参考镜头导入后形成带来源版本的制作快照，不双向同步 |
| 镜头关系图 | 制作计划的服务端投影 | 依赖来自 Scene、Shot、节点及节点输入；布局只保存位置和视口 |
| 主编辑序列 | 项目主时间线 | 服务单条人工剪辑和参考复刻结果 |
| 变体编辑序列 | 各短视频变体 | 与主编辑序列共享结构和渲染规则，但不双向同步 |
| 运行记录 | 运行基础设施 | 只拥有排队、执行、取消、重试、输入快照、输出和错误 |
| 预览、审核与交付 | 审核交付模块 | 运行成功不等于采用、批准或交付 |
| 内容制作阶段 | 只读派生投影 | 从当前有效脚本、配音、预览、审核和交付事实派生，不手工保存全局状态 |

### 13.1 编辑序列交接

主编辑序列与变体编辑序列是不同成片对象拥有的独立实例。两者交接时创建带来源对象和来源版本的快照，不进行双向同步，也不让后续编辑静默改写另一方。

### 13.2 项目素材删除

素材引用检查必须覆盖创作简报、脚本候选、制作镜头、节点、主编辑序列、短视频变体、渲染、审核和交付历史。被引用的素材允许标记为归档或不可用，但不得直接删除身份或用无关文件替换。只有完全无引用的素材才能清理记录和文件。

### 13.3 参考镜头导入

导入制作镜头时保存来源参考镜头段和来源版本；之后两者独立演进。上游重新分析不得覆盖人工提示词、素材绑定、步骤、结果采用或编辑序列。更新只能由用户显式重新导入或创建新版本。

### 13.4 关系图编辑

未来编辑依赖边时，界面必须执行受校验的领域命令并修改对应业务依赖。不能另存一份与制作镜头和节点输入并列的边真相源；前端 Store 也不能成为持久化权威。

## 14. P0 试点验收标准

### 内容与人工验收

- 使用一个真实商品和来源、包装、规格、使用范围经过核对的素材；
- 使用一个已通过连接验证的 AI 服务，展示并确认实际发送文字、供应商和模型；
- 生成五条正式候选，逐条核对事实、禁用表达、素材引用和差异，并确认当前版本；
- 至少制作两条镜头安排不同的作品；
- 审核人完整听看画面、商品名和关键词读音、节奏、字幕、音量及包装呈现；
- 每条作品分别记录通过或具体修改意见；
- 只有当前批准预览能够生成交付版本。

### 工程证据

- 从正式界面完成全流程，不直接伪造状态文件；
- 配音、字幕、预览、审核和导出使用真实本地运行；
- 修改脚本、音色、编辑序列或字幕后，旧预览和旧批准失效；
- 单条失败、取消、重试和应用重启不破坏其他作品；
- 备份并恢复试点项目后，素材、候选、编辑序列、审核和交付仍可追溯；
- 最终文件为批准预览对应的 720×1280、30fps、H.264/AAC MP4；
- 对最终文件完成完整解码、音视频流、实际时长、字幕抽帧和 SHA-256 核验；
- P0 缺陷修复后运行受影响测试、前后端完整回归和生产构建；
- 完成桌面浏览器、关键键盘路径和移动查看验收；
- 未执行或需要人工判断的项目保持未完成，不用旧结果或测试桩冒充本轮证据。

## 15. 当前已知 P0 缺口

1. 大窑现有两条是 640×1138 内部试看，尚未批准，也不是最终交付文件。
2. 现有大窑脚本是手工草稿，不能冒充正式 AI 服务生成的五条候选。
3. 现有商品图片的目标商品、包装、规格和使用范围仍需核对。
4. 素材删除引用检查尚未覆盖 AIGC 简报/候选和批量变体。
5. 历史复刻后端仍存在可提交到 ComfyUI 的旧运行接口，与现行 ADR 和正式界面边界冲突。

这些缺口属于试点完成、数据完整性和既有范围冲突，不是新增产品模块。

## 16. 范围冻结规则

在商品短视频黄金流程达到试点交付前：

1. 不实施任何 P1、P2、延后或预留模块；
2. 只允许 P0 验收工作、P0 缺陷修复，以及安全、数据损坏、许可证和阻断性环境问题；
3. 新需求必须说明它属于哪个现有模块和哪一级；无法归类的需求默认不进入当前开发；
4. 新参考项目只能帮助实现已批准能力，不能产生新的一级导航、业务模型或运行时；
5. 发现更好的开源实现可以触发替换评估，但不能自动扩大范围；
6. 当前闭环外的方向只更新本文件的候选分类，不创建实施任务；
7. P0 完成后再通过独立规划把 P1 拆成可验证任务。

## 17. 文档权威顺序

1. `CONTEXT.md`：领域术语的唯一含义；
2. ADR：难以逆转的产品和架构边界；
3. 本文件：当前产品范围、优先级、完成标准和冻结规则；
4. `.scratch/<feature>/spec.md`：单项功能行为；
5. 验收记录：只证明明确覆盖的版本和范围；
6. 研究及参考项目登记：只决定已批准能力可参考什么；
7. `wontfix`、`superseded` 的历史规格：只保留历史。
