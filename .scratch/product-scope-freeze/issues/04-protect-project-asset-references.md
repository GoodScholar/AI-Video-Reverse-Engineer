# 04: 补齐项目素材引用保护

**What to build:** 将项目素材的引用检查补齐为覆盖 P0 全生命周期的单一保护机制。删除素材前，服务端必须查询创作简报、脚本候选、制作镜头、节点、主编辑序列、短视频变体及其编辑序列、渲染、审核和交付历史中的当前或历史引用；界面展示同一查询结果并阻止误删。直接调用删除接口也必须受到相同保护，同时完全无引用的素材仍能正常删除，避免通过替换文件或遗漏历史对象破坏稳定素材身份。

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] 建立服务端统一引用查询结果，覆盖创作简报及脚本候选中的素材引用。
- [x] 引用查询覆盖制作镜头、节点、主编辑序列、短视频变体及其变体编辑序列。
- [x] 引用查询覆盖变体运行或渲染输入、预览、审核记录、最终交付及其历史版本。
- [x] 素材只要存在任一当前或历史引用，删除接口就拒绝删除记录和文件，并返回可定位引用来源的稳定错误信息。
- [x] 项目素材界面在删除前使用同一引用结果，清楚列出阻塞删除的对象，不以仅前端判断替代服务端保护。
- [x] 被引用素材的不可用或归档状态不会改变其稳定身份，也不会用无关文件静默顶替原素材。
- [x] 完全无引用的素材仍能从界面和接口正常删除，且只清理目标素材自身的记录和文件。
- [x] 增加回归验证，至少覆盖简报、候选、批量变体、渲染、审核、交付历史、直接接口删除和无引用删除路径。

## Comments

- 统一查询已补齐创作简报、全部持久化脚本候选、批量推荐草案、AIGC 交接快照、当前变体、配音、字幕识别、预览、审核和交付历史；既有制作镜头、节点与主时间线查询继续复用。
- 引用查询失败时删除接口返回 `asset_references_unavailable` 并失败关闭；有引用时返回完整 `references`，与素材界面使用的 GET 查询保持一致。
- 验证：后端全量测试 1399 passed / 2 skipped；前端全量测试 454 passed；前端生产构建通过；Standards 与 Spec 双轴审查均无发现。
