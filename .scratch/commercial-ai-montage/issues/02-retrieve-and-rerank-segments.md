# 02: 实现本地召回与豆包视觉复排

**What to build:** 让内部交付人员能够以已确认脚本段落、卖点或动作描述检索素材片段候选。系统先使用本地视觉索引召回多个候选；用户确认实际外发内容后，再由已验证的 `Doubao-Seed-2.1-pro` 对有限候选关键帧和必要文字进行复排并解释选择依据。外部服务不可用时仍保留本地结果，并明确标注未完成云端复排。

**Blocked by:** 01: 建立可播放的素材片段索引。

**Status:** ready-for-agent

- [ ] 输入脚本段落、卖点或动作描述后，本地检索返回多个带素材身份、源时间范围和可播放预览的候选。
- [ ] 候选展示视觉相关性、基础质量、重复风险和证据，不把文件名或备注相似度冒充视觉语义结果。
- [ ] 同一长视频可以返回多个不同镜头，查询响应完整保留每个候选的源入点和出点。
- [ ] 调用豆包前显示实际发送的文字、关键帧范围、供应商和模型，并要求沿用现有显式发送确认。
- [ ] 豆包请求只包含已披露的有限候选，不发送完整视频、音频或未选择的项目素材。
- [ ] 豆包复排结果包含候选顺序、理由和置信信息，并绑定本地召回版本、供应商配置修订和模型标识。
- [ ] 豆包超时、失败、返回无效结构或配置改变时，不静默切换供应商；本地候选仍可浏览和人工采用。
- [ ] 模型或索引版本变化会使旧复排结果明确过期，但不会删除其历史证据。
- [ ] 自动化测试使用固定向量器和协议级假服务验证排序、区间、披露、请求边界、超时、错误、版本绑定和无静默回退。
