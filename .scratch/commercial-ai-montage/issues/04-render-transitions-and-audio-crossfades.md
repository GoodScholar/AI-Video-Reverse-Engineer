# 04: 实现转场与音频交叉淡化

**What to build:** 让混剪提案和现有编辑序列能够把镜头边界保存为正式可编辑对象，并使用现有 FFmpeg 成片链渲染受控复杂转场及匹配的音频交叉淡化。内部交付人员可以查看建议、替换或关闭单个转场；实际预览、审核快照和最终导出必须使用同一冻结边界数据。

**Blocked by:** 03: 生成并采用可解释混剪提案。

**Status:** resolved

- [x] 编辑序列能够保存左右片段、转场模板、持续时间、重叠量和音频交叉淡化，并参与内容版本计算。
- [x] 首批支持硬切、叠化、推拉、擦除、闪白、像素化及受控速度变化；不支持的组合在保存或渲染前返回明确原因。
- [x] 规划器根据场景变化、节拍和卖点强调给出转场建议，普通叙事镜头仍可保持硬切，不随机堆叠效果。
- [x] 用户可以逐个禁用、替换或调整转场，修改后旧预览、自动质检和人工批准按现有规则失效。
- [x] 渲染前统一参与转场片段的分辨率、帧率、像素格式和时基，并校验源素材 handle 足够覆盖重叠区间。
- [x] 视频转场与音频交叉淡化由同一次冻结编辑输入驱动，预览和最终导出在边界帧与听感上保持一致。
- [x] 转场失败不会发布部分输出或错误地复用旧预览；取消、重试和重启恢复沿用现有运行边界。
- [x] 实际 FFmpeg 测试覆盖所有首批模板、不同持续时间、相邻短片段、音频有无、取消和预览/导出一致性。
- [x] 界面支持键盘访问并在桌面编辑、移动只读查看中清楚显示转场类型和持续时间。
