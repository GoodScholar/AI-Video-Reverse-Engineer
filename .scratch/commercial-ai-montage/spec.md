# 商用自动混剪完整链路

Status: ready-for-agent
Type: feature-spec
Decision date: 2026-09-29

## Problem Statement

当前批量混剪已经能够保存短视频变体、安排素材、生成配音和字幕、渲染预览、审核并导出，但系统主要执行人工给定的时间线。制作人员仍需逐段判断镜头入点、出点、顺序和节奏；横屏素材进入竖屏时可能留黑边；转场、花字和字幕包装没有成为可规划、可版本化、可预览且会触发审核失效的正式编辑输入。因此现状可以完成作品，却不能稳定、批量地自动生产达到参考样片结构和包装水平的商用初稿。

用户需要系统从已授权项目素材和已确认脚本出发，自动发现可用片段、按视觉语义选片、规划顺序与节奏，并在同一版编辑序列中同时处理复杂转场、花字、主体感知竖屏裁满、字幕样式和音频节拍。人工应主要审核和少量调整，而不是重新完成一次剪辑。

## Solution

在现有内容项目、项目素材、批量混剪、短视频变体、编辑序列、预览审核和交付边界内增加一条可解释的自动混剪链路：

1. 对项目视频素材做可恢复的场景切分和片段级派生索引，每个素材片段候选保存稳定来源、源时间范围、关键帧、视觉描述、质量和可重建版本。
2. 使用本地视觉向量检索召回多个候选，并在用户完成外发披露后由 `Doubao-Seed-2.1-pro` 对候选关键帧和必要文字复排、解释；外部服务失败时保留本地候选，不伪造智能结果。
3. 由 `MontagePlanner` 根据脚本段落、旁白时长、候选证据、节拍、去重和跨变体差异生成混剪提案，明确镜头入点、时长、顺序和选择理由。
4. 混剪提案同时包含转场边界、音频交叉淡化、主体感知裁剪路径、字幕和花字模板引用，不把包装效果推迟到另一条成片链。
5. 用户在现有商品视频制作界面查看、替换、禁用或应用提案；采用结果写入现有短视频变体编辑序列，继续使用现有冻结预览、审核失效和批准后导出规则。
6. 自动质检只检查实际冻结预览并返回可定位的证据；它可以阻止明确工程错误的交付，但不能自动批准内容。

首个金标基准使用用户指定的参考视频结构。第一期商用自动混剪验收目标为：自动初稿至少 80% 的镜头可保留、人工替换不超过 20%、9:16 输出无黑边、主体和字幕处于安全区、转场与花字完整且预览和最终导出一致。后续增加两组不同素材的回归集，避免只对单一样片过拟合。

## User Stories

1. 作为内部交付人员，我希望选择一个已有内容项目开始自动混剪，以便继续使用已经核实来源和使用范围的项目素材。
2. 作为内部交付人员，我希望看到哪些视频素材尚未建立片段索引，以便知道自动选片的准备状态。
3. 作为内部交付人员，我希望可以启动、取消、重试并恢复片段索引，以便长素材处理中断后不必重新开始全部工作。
4. 作为内部交付人员，我希望每个素材片段候选都显示原素材、入点、出点和可播放预览，以便核实它确实来自正确位置。
5. 作为内部交付人员，我希望片段索引在源文件、切分算法或视觉模型改变后明确失效，以免复用过期结果。
6. 作为内部交付人员，我希望用脚本段落、卖点或动作描述查找视觉匹配片段，以便不再只靠文件名和备注选片。
7. 作为内部交付人员，我希望同一长视频能返回多个不同镜头，而不是只返回整段素材或一个代表镜头。
8. 作为内部交付人员，我希望候选展示视觉相似度、质量、商品可见性、重复风险和选择依据，以便理解并纠正系统判断。
9. 作为内部交付人员，我希望系统在发送关键帧和文字给豆包前显示实际外发范围、供应商和模型，以便确认数据外发。
10. 作为内部交付人员，我希望豆包不可用或超时时仍能查看本地召回候选和明确错误，以便继续人工工作且不会发生静默模型切换。
11. 作为内部交付人员，我希望为一条已确认脚本生成完整混剪提案，以便快速得到可播放初稿。
12. 作为内部交付人员，我希望提案按脚本段落给出镜头顺序、源入点和持续时间，以便画面与旁白语义对应。
13. 作为内部交付人员，我希望系统根据旁白词边界和音乐节拍建议切点，以便节奏自然又不截断表达。
14. 作为内部交付人员，我希望系统限制重复素材、连续相似构图和同一动作反复出现，以便作品有视觉变化。
15. 作为内部交付人员，我希望同一批次的多个短视频变体共享可用素材但保持足够镜头差异，以便批量作品不是简单重复。
16. 作为内部交付人员，我希望每个自动决定都有候选、分数和理由，以便人工替换而不是接受黑盒结果。
17. 作为内部交付人员，我希望替换一个候选片段时看到相同脚本段落的备选项，以便快速微调。
18. 作为内部交付人员，我希望应用混剪提案后得到普通的可编辑变体编辑序列，以便继续使用现有时间线能力。
19. 作为内部交付人员，我希望重新生成提案不会静默覆盖已有人工编辑，以便保护已完成的调整。
20. 作为内部交付人员，我希望每个镜头边界可以选择硬切、叠化、推拉、遮罩、闪白、速度变化等受控效果，以便达到目标样片的包装水平。
21. 作为内部交付人员，我希望系统根据场景变化、节拍和卖点强调建议转场，而不是随机堆叠效果，以便保持统一风格。
22. 作为内部交付人员，我希望关闭或替换单个转场后立即形成新的当前变体版本，以便预览和审核关系保持真实。
23. 作为内部交付人员，我希望转场画面和音频交叉淡化在预览与最终导出中一致，以免审核结果失真。
24. 作为内部交付人员，我希望使用包装模板生成关键词花字、动态标题、卖点强调和片尾行动引导，以便同一批次保持品牌一致。
25. 作为内部交付人员，我希望花字和字幕共享安全区、字体授权和模板版本，以免遮挡商品或平台控件。
26. 作为内部交付人员，我希望可以禁用、替换或编辑任一花字内容，而无需重新生成全部选片结果。
27. 作为内部交付人员，我希望横屏和其他比例素材自动裁满 9:16，并尽量保持商品或人物主体完整，以便输出不出现黑边。
28. 作为内部交付人员，我希望裁剪轨迹显示主体框、置信度和预览，以便在主体不明确时人工指定构图。
29. 作为内部交付人员，我希望主体无法安全裁满时系统标记待处理，而不是静默加黑边或裁掉商品，以便避免错误交付。
30. 作为内部交付人员，我希望音乐节拍只作为剪辑建议，不覆盖对白、脚本和镜头语义，以便保持内容可理解。
31. 作为审核人员，我希望自动质检报告能跳转到黑帧、卡帧、静音、响度异常、黑边、字幕越界或片尾缺帧的具体时间，以便高效复核。
32. 作为审核人员，我希望自动质检结论不会自动把作品标记为审核通过，以便最终责任仍由人工承担。
33. 作为审核人员，我希望任何影响画面、转场、花字、字幕、裁剪或音频的修改都会使旧预览和旧批准失效，以免导出未经审核的新版本。
34. 作为交付人员，我希望只有当前变体版本对应的已批准冻结预览能够导出，以便商用自动混剪继续遵守现有交付门禁。
35. 作为产品负责人，我希望查看金标基准中镜头保留率、人工替换率、黑边、主体安全区、字幕安全区和预览一致性，以便判断是否达到商用自动混剪验收。
36. 作为产品负责人，我希望后续回归集覆盖不同素材和构图，以便防止系统只对单一参考视频有效。

## Implementation Decisions

- 本功能是现有批量混剪模块的增强，不增加新的一级导航、项目类型、项目素材系统、时间线、审核系统或交付系统。
- 当前 P0 的素材引用保护、旧生成接口关闭和全链路收口先完成；本功能实施票据整体受该收口阻塞。
- 片段索引是 `ProjectAssets` 的可重建派生数据。业务引用始终使用稳定项目素材身份和源时间范围，不能使用文件路径、向量 ID 或模型结果序号作为业务主键。
- 场景切分优先使用 PySceneDetect；索引和视觉查询参考 Media Search Agent 的关键帧、指纹、SQLite 正本与派生向量索引设计，但必须保留同一视频的多个镜头并在查询结果返回源区间。
- 视觉语义选片采用两阶段策略：本地索引召回多个候选，豆包仅对有限候选关键帧和必要文字进行复排与解释。云端调用遵守现有供应商配置、连接验证、显式发送披露、费用和失败不静默回退规则。
- 豆包模型固定使用用户已确认的 `Doubao-Seed-2.1-pro`；模型目录名称、供应商标识和真实请求协议以正式配置为准，不用界面标签代替服务契约。
- OpenShorts 仅迁移许可允许且具有测试价值的候选评分、最佳区间精剪和重叠去重逻辑；排除其 `cloud/` 和许可证未满足的模型路径。
- `MontagePlanner` 在一个稳定接口后拥有脚本段落到素材片段候选的分配、时长、顺序、节拍吸附、重复抑制、跨变体差异和选择理由。MoneyPrinterTurbo 只提供规则参考，不引入其项目、任务、Redis、MoviePy 或 Streamlit 链。
- 混剪提案是候选，不是编辑序列。采用提案时以修订校验写入现有短视频变体编辑序列；若当前版本已有人工编辑，必须显式选择覆盖、合并或放弃，不静默改写。
- 第一批效果能力与智能选片同一期交付。Timeline 扩展正式的片段裁剪路径、花字提示和镜头边界对象；边界包含左右片段、转场模板、持续时间及音频交叉淡化。
- 复杂转场优先使用现有 FFmpeg `xfade`/`acrossfade`，每种模板有受控参数和兼容性校验。渲染前统一分辨率、帧率、像素格式和时基；不增加第二套成片渲染器。
- 字幕和花字使用版本化包装模板。首批以 libass/ASS 和当前 FFmpeg 烧录实现；复杂独立字卡如确有需要，可由 Motion Canvas 生成带透明背景的覆盖素材，但它不拥有 Timeline、预览或审核状态。
- 主体感知裁满输出按源时间坐标表示的裁剪路径、置信度和人工覆盖。无法安全构图时返回待处理；正式 9:16 成片不允许用黑色 letterbox 冒充裁满。
- 节拍检测使用本地算法生成候选吸附点；对白词边界、脚本段落和语义连续性优先级更高。
- 自动质检运行于实际冻结预览而非抽象提案，规则和报告均有版本。明确工程错误可以阻止交付，但报告永远不产生人工审核通过状态。
- 任何索引模型、来源素材、混剪提案、编辑序列、裁剪路径、包装模板、字体、字幕或音频修订变化，都按影响范围使依赖的预览、质检和审核失效。
- 只引入许可证和第三方资产权利经过核验的代码、模型、字体和模板。AGPL、非商业许可、未知模型权重或未授权媒体不进入当前商用栈。

## Testing Decisions

- 最高测试接缝是“授权项目素材与已确认脚本 → 可解释混剪提案 → 采用后变体编辑序列 → 冻结可播放预览 → 质检 → 人工审核 → 批准导出”，验证外部行为和版本关系，不断言内部函数调用顺序。
- 片段索引契约测试使用短小、确定性的本地测试视频，验证切分区间、同源多镜头、源指纹、失效、取消、恢复和缺失源处理。
- 视觉召回测试以固定关键帧和替代向量器验证排序、同视频多候选、区间返回和去重；豆包复排使用协议级假服务验证披露、请求边界、超时、错误和不静默回退。真实模型效果只由显式授权的金标验收证明。
- `MontagePlanner` 使用固定候选集做行为测试：脚本覆盖、持续时间、无重叠、少重复、跨变体差异、词边界与节拍优先级、理由和确定性。
- Timeline 合同测试验证提案采用、修订冲突、人工编辑保护、转场边界、裁剪路径、花字模板、冻结快照和版本失效。
- 渲染测试使用合成色块、移动主体、测试音频和字体，实际运行 FFmpeg，验证 `xfade`/`acrossfade`、动态裁剪、ASS 花字、字幕安全区、预览与导出帧的一致性。
- 质检测试使用带已知黑帧、卡帧、静音、黑边、响度异常和字幕越界的媒体夹具，验证时间范围和证据；同时验证报告不会自动批准。
- UI 测试覆盖索引状态、候选来源、豆包发送披露、提案预览、候选替换、转场/花字禁用、裁剪人工覆盖、质检跳转、键盘路径和移动只读查看。
- 金标媒体验收使用用户指定参考视频作为结构基准，记录镜头保留率和人工替换率；一期必须达到至少 80% 镜头保留、人工替换不超过 20%，并通过无黑边、主体/字幕安全区、效果完整和预览导出一致检查。
- 第二阶段在不改变一期门槛的前提下增加两组不同素材回归集。未取得合法测试素材前，相关验收保持未完成，不用合成数据冒充真实质量证明。
- 复用现有项目素材、批量制作、编辑序列、渲染、字幕、审核、导出、取消恢复和生产构建测试作为先例；每张实施票据只增加其纵向切片所需测试。

## Out of Scope

- 建立第二套项目、素材、时间线、渲染、运行、审核或交付系统。
- 完整替换现有编辑器，或实现通用专业 NLE 的全部能力。
- 自动生成全新商品视频镜头、恢复应用内最终 AI 视频生成链或绕过外部生成边界。
- 根据模型评分、质检结果或任务成功自动审核通过、自动交付或自动发布。
- 未经用户披露把完整视频、音频或未选择的素材发送给豆包或其他云服务。
- 引入 AGPL、非商业许可证、未知权重、未授权字体、音乐、库存素材或模板。
- 第一阶段支持任意自定义 shader、第三方插件市场、无限效果参数或与效果供应商双向兼容。
- 第一阶段支持多人实时协作、SaaS 权限、计费、跨项目共享素材库或平台发布。

## Further Notes

- 开源选型和固定提交证据见 `docs/research/commercial-ai-montage-open-source-stack-2026-09-29.md`。
- 当前半自动批量混剪可以继续完成试点，但只有本规格金标门槛通过后，才可宣称“自动批量混剪达到商用标准”。
- 当前 P0 收口完成前可以完成研究、规格和票据，不开始本规格代码实施。
- 参考视频主要由高频硬切、商品功能画面、白字描边字幕和结尾包装构成；选片、入点和节奏仍是核心，复杂效果必须受模板和叙事目的约束，不能用随机堆叠代替内容质量。
