# 真实商品短视频试点验收

Status: ready-for-agent
Type: task
Execution gate: 等待资料核验票 01 完成

## Problem Statement

内部交付团队已有统一内容工作室、脚本候选、选声制作、预览、审核和导出能力，但现有证据来自自动化测试及公开咖啡技术样例。仍需用一个真实商品检验事实准确性、画面对应、声音读音、字幕与最终交付，才能判断本批作品是否满足客户要求。

## Solution

沿用现有工作台，为一个已确认商品建立独立试点项目。只需用户给出商品名称；有图片时直接使用，没有时按商品名称搜索网络图片并核对来源、包装与规格，准备可用画面后生成并逐条确认五条候选；至少选两条镜头安排不同的作品完成本地配音、预览、人工审核与 MP4 导出，保留版本和验收证据。资料收集与执行条件先落实，不能以技术样例替代本次客户样例。

## User Stories

1. 作为商品负责人，我希望填写已核实事实及依据，以便脚本不编造商品声明。
2. 作为商品负责人，我希望注明禁用表达、受众、卖点和行动引导，以便内容符合本次目标。
3. 作为交付人员，我希望知道每份素材展示的内容和获准使用的范围，以便只导入适用素材。
4. 作为交付人员，我希望知道可用脚本服务、费用上限和审核负责人，以便按明确条件开展试点。
5. 作为交付人员，我希望将试点保存为独立项目，以便结果与既有技术演示分开。
6. 作为交付人员，我希望保存后重新打开项目核对简报和素材，以便确认使用了正确输入。
7. 作为交付人员，我希望在发送前核对实际文字、服务与模型，以便确认本次外部请求。
8. 作为交付人员，我希望取消发送不产生生成动作，以便能退出错误请求。
9. 作为审核人员，我希望五条候选分别映射到事实及画面，以便逐条判断准确性。
10. 作为审核人员，我希望候选在卖点或叙事安排上有差异，以便试点有真实比较价值。
11. 作为交付人员，我希望修改后确认当前版本再交接，以便旧确认不会用于新脚本。
12. 作为交付人员，我希望先试听、选声、核对已保存脚本，再执行配音，以便确认商品名和读音。
13. 作为交付人员，我希望至少两条作品独立制作、显示真实失败原因，以便单条失败不破坏其他作品。
14. 作为审核人员，我希望检查完整画面、声音、字幕与镜头顺序，以便记录具体通过或退回原因。
15. 作为交付人员，我希望只导出与当前批准预览一致的作品，以便避免交付过期版本。
16. 作为交付人员，我希望下载文件在普通播放器可播放且参数正确，以便确认交付产物实际可用。
17. 作为商品负责人，我希望看到两条成片及验收结论，以便作出本批接受或修改决定。
18. 作为维护人员，我希望缺陷有明确复现和回归证据，以便修复具体问题并重验受影响路径。

## Implementation Decisions

- 复用正式内容工作室及既有简报、候选确认、批量混剪、音色、预览、审核和导出接口；暂不修改代码、数据库或接口契约。
- 以一个商品、五条当前候选、至少两条不同镜头安排的成片为首轮范围，使用独立试点项目。
- 用户必填仅商品名称，当前已填“大窑果味汽水”。用户图片为可选：提供时优先直接用，不提供则搜索网络图片。卖点补充选填；没有核实卖点时只描述可确认的商品或画面事实。
- 自动找图优先官方商品页和明确可用的公开素材；保留来源网页、图片地址、检索时间、包装/规格匹配情况及使用条件。图片仅来自搜索不代表可无条件商用；匹配与使用条件不明确时保留候选，不伪装成已可交付素材。
- 需要至少两份画面是制作内部条件，由素材准备步骤解决，不要求用户上传两份。网络找不到时明确缺口；AI概念画面只作为后续选择，不生成或改造真实包装后假称实拍。
- 受众默认一般消费者，风格默认简洁商品展示，不添加未经确认的功效、价格、比较声明或促销引导；素材内容由交付人员核对。审核默认由当前用户核对脚本和成片，需要其他审核人时再补充，以上默认不作为客户提供的事实。
- 收到商品名称即可进行资料整理、网络检索并准备本地项目；可选营销信息采用上述默认。必要的服务调用与费用在执行前确认，不放进初始问卷；不替客户编造事实或把其他商品素材当作目标商品。
- 执行前重新核对服务连接状态；目录里的旧 available 记录仅为准备证据。连接探针与生成均需符合本次服务和费用条件。
- 每次生成前核对实际发送披露，仅发送允许的文字、素材名称及备注，不上传原始媒体或凭据；记录生成动作与重试，费用条件不明时先补齐。
- 配音复用已准备的本机环境，结果时长按实际音频确定；短素材或读音失败先修订，不假定固定成片时长或自动循环画面。
- 输出沿用现有竖版720×1280、30fps预设；不同成片按保存内容、变体、字幕、预览及审核版本关联。
- 只检查现有版本失效与导出限制，不为试验更改已批准交付文件；需要实测修改后失效时，使用未交付的剩余试点变体。
- 文档记录必要标识、状态、摘要、文件校验和审核理由；客户原始资料与媒体保留于授权的本地位置，验收文档不存密钥。

## Testing Decisions

- 主验证入口为正式工作台公开操作，串起真实项目、现有HTTP边界、本地配音和FFmpeg及下载文件。以用户可见结果判断，不检查私有组件状态。
- 资料保存与重开验证，发送取消与确认，候选逐条审核，选声与确认，完整播放、批准、下载是本轮必经路径。
- 五条脚本逐条核对事实依据、禁用表达、素材和差异；至少两条成片人工听看全片，核对商品读音、画面、音量及字幕。
- 下载后检查视频/音频流、输出宽高和帧率、实际时长及可播放性；生成SHA-256用于识别交付文件。
- 技术行为已有361项前端回归与本地模型技术验收可作背景证据，不替代本轮客户内容验收，也不无变化重复运行全套测试。
- 如果发现具体问题，先建立能复现本问题的命令或公开操作序列，再按诊断流程修复并跑受影响回归；修复后重新预览和审核。
- 人工审核是内容验收结论来源；未提供审核意见不能由Agent默认批准。

## Out of Scope

数字人直播、全新AI商品画面、声音克隆、投放效果承诺、自动发布、平台账号操作、模型下载或安装、全站重构、自动提交。
