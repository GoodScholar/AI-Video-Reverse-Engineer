# AI Video Reverse Engineer 产品规格

Status: ready-for-agent

## Problem Statement

视频创作者看到一段希望借鉴的参考视频时，通常只能依靠经验手工判断主体、场景、动作、运镜、光线和生成参数，再自行选择模型、准备控制素材并搭建 ComfyUI Workflow。这个过程要求同时理解视频语言与 ComfyUI 技术细节，耗时、容易遗漏，而且结果难以解释和复用。

ComfyUI 创作者虽然能够操作节点和模型，但往往缺少一套系统拆解参考视频并将分析转换为可执行工作流的方法。普通创作者更不了解节点和模型，希望直接获得可用的技术方案，但 MVP 阶段仍要求其设备上已经具备可连接的本地 ComfyUI 环境。

现有同类视频生成入口主要让用户直接选择比例、分辨率、时长和格式，或提供编辑、延长、首尾帧、版权 IP 等生成模式，没有解决“为什么应选择某种生成策略”以及“如何把参考视频转换成可编辑、可运行的 ComfyUI 复刻起点”这一问题。

产品必须避免无法证明的承诺。它不能声称恢复原始 Prompt、种子或制作流程，也不能以主观的综合相似度百分比代替真实的 Workflow 导入和 Queue 结果。

## Solution

AI Video Reverse Engineer（AI 视频复刻分析器）是一款本地 Web 应用。用户围绕一段参考视频创建复刻项目，产品在本地完成解码、镜头检测、关键帧提取和运动计算，并在清楚披露数据边界后，将分析代理发送给用户配置的分析服务。系统把返回结果整理为可解释、可编辑的结构化分析，选择经过验证的生成策略，并生成提示词、控制素材、推荐参数和可执行的 ComfyUI Workflow。

产品采用一条渐进式流程：普通创作者默认使用智能模式，无需理解模型和节点；ComfyUI 创作者可展开高级设置，修改结构化分析、Prompt 和输出参数。分析完成后，用户在复刻工作台中同步查看参考视频、带时间范围的分析条目、关键帧和复刻方案。修改会使旧 Workflow 明确失效，用户重新生成后可下载完整复刻包，或在环境验证通过时发送到本地 ComfyUI。

MVP 正式生成的可执行工作流仅限经过验证的 Wan2.2 14B I2V、Wan2.2 Fun Camera 与 Wan2.2 Fun Control 深度模板。深度动作捕捉在本地生成时间连续的相对深度控制素材，不输出骨骼或三维动作文件。超出可复刻范围的视频仍可生成分析报告，但必须明确说明当前无法可靠生成可执行工作流。产品提供的是高相似度、可继续调整的复刻起点，而不是精确还原。

## User Stories

### 复刻项目与开始流程

1. As a ComfyUI 创作者, I want to 创建以单个参考视频为中心的复刻项目, so that 我可以持续保存分析、修改和执行记录。
2. As a 普通创作者, I want to 从明确的“新建复刻项目”入口开始, so that 我不需要先理解工作流或节点概念。
3. As a returning user, I want to 在项目首页查看最近的复刻项目, so that 我可以继续上次未完成的工作。
4. As a user, I want to 看到分析服务和本地 ComfyUI 的连接状态, so that 我能在开始前理解当前环境能力。
5. As a user, I want to 在没有连接本地 ComfyUI 时仍可创建和分析复刻项目, so that 环境问题不会阻止我获得分析报告与下载文件。
6. As a user, I want to 为复刻项目使用可识别的名称和缩略图, so that 我能从本地项目历史中找到目标项目。

### 参考视频输入与可复刻范围

7. As a user, I want to 上传 MP4 或 MOV 参考视频, so that 我可以使用常见视频素材开始分析。
8. As a user, I want to 在上传前看到 2～10 秒、最大 200 MB、最低 480P 等限制, so that 我能提前选择合适素材。
9. As a user, I want to 获得格式、时长、体积和分辨率的即时校验结果, so that 我知道文件为何可用或不可用。
10. As a user, I want to 让最高 4K 的参考视频通过本地低分辨率代理参与分析, so that 高分辨率素材不会造成不必要的上传和计算成本。
11. As a user, I want to 知道单镜头、单一主要人物或产品、轻中度运动是当前可复刻范围, so that 我对 Workflow 可靠性形成合理预期。
12. As a user, I want to 在视频超出可复刻范围时仍能获得分析报告, so that 已完成的分析仍有使用价值。
13. As a user, I want to 在视频超出可复刻范围时看到明确原因, so that 我不会把后续建议误认为经过验证的可执行工作流。
14. As a user, I want to 在视频无法解码时看到可操作的错误说明, so that 我可以修正文件并重试。

### 数据边界与分析服务

15. As a privacy-conscious user, I want to 在分析前看到哪些内容保留在本地、哪些分析代理会被发送, so that 我能作出知情决定。
16. As a user, I want to 默认只发送低分辨率关键帧组合和运动数据, so that 完整参考视频不会被默认上传。
17. As a user, I want to 从百炼、OpenAI、Gemini、豆包和 Claude 中明确选择供应商并使用自己的 API 密钥, so that 分析请求由我的账户直接承担和控制。
18. As a user, I want to 让 API 密钥只由本地服务和系统安全存储管理, so that 密钥不会进入复刻项目文件或前端持久化数据。
19. As a user, I want to 在分析服务不可用或未配置时获得明确状态, so that 我知道哪些步骤可以继续、哪些步骤被阻止。
20. As a user, I want to 在分析服务失败后保留已完成的本地预处理, so that 重试无需重新解码和提取关键帧。
21. As a user, I want to 从失败的分析步骤继续重试, so that 临时网络或服务错误不会迫使我重建项目。
22. As a user, I want to 在分析服务发生变化前得到明确选择, so that 产品不会在我不知情时将数据发送给其他供应商。

### 分析过程与结构化结果

23. As a user, I want to 看到解码、镜头检测、关键帧提取、运动分析、语义分析、策略生成和 Workflow 构建的阶段状态, so that 我能理解进度和失败位置。
24. As a user, I want to 在分析期间看到已完成的阶段和仍在进行的阶段, so that 等待过程可预测。
25. As a user, I want to 获得参考视频的基础事实与适用性检查, so that 我能判断输入是否适合当前生成能力。
26. As a ComfyUI 创作者, I want to 获得主体、场景、动作、运镜和光线的结构化分析, so that 我不必从零手工拆解视频。
27. As a user, I want to 让分析条目包含明确时间范围, so that 我能把描述与视频片段对应起来。
28. As a user, I want to 清楚区分观察事实、复刻建议和未支持能力, so that 我不会把模型推断当作已验证事实。
29. As a user, I want to 对不确定条目看到局部置信提示和原因, so that 我知道优先检查哪些内容。
30. As a user, I want to 避免看到无依据的总体相似度百分比, so that 我能依据具体分析和执行结果判断质量。
31. As a user, I want to 修改错误的主体、场景、动作、运镜或光线描述, so that 复刻方案能反映我的判断。
32. As a user, I want to 在重新分析前保留自己已经确认的修改, so that 自动分析不会无提示覆盖人工决策。

### 复刻工作台与时间联动

33. As a user, I want to 在同一复刻工作台中查看参考视频、结构化分析和复刻方案, so that 我不必在多个页面之间来回比对。
34. As a user, I want to 点击分析时间范围后自动定位视频, so that 我能立即验证对应内容。
35. As a user, I want to 在定位时同步高亮时间轴、关键帧和相关分析条目, so that 三栏信息保持空间与时间上的一致。
36. As a user, I want to 通过关键帧胶片条快速浏览参考视频变化, so that 我能识别主要动作和镜头节点。
37. As a keyboard user, I want to 通过键盘完成播放、选择分析条目和移动焦点, so that 核心流程不依赖鼠标。
38. As a user, I want to 在页面刷新或重新打开后恢复工作台状态, so that 本地工作不会丢失。

### 生成策略、Prompt 与参数

39. As a user, I want to 看到推荐生成策略及其选择理由, so that 我能理解系统为何选择某个可执行工作流。
40. As a user, I want to 区分可执行工作流和后续建议, so that 我不会尝试运行未经验证的策略。
41. As a user, I want to 在需要时点击按钮，根据分析结果生成中英文正向 Prompt, so that 我可以控制模型调用并直接进入生成准备阶段。
42. As a user, I want to 同时获得中英文负向 Prompt, so that 常见生成缺陷能够被主动约束，并能用于不同语言偏好的创作流程。
43. As a user, I want to 编辑正向和负向 Prompt, so that 我可以保留创作意图并修正分析偏差。
44. As a 普通创作者, I want to 默认使用智能匹配的比例、分辨率和时长, so that 我无需理解每项生成参数。
45. As a ComfyUI 创作者, I want to 在高级设置中覆盖比例、分辨率、时长、音频和生成数量, so that 我可以控制输出成本和表现。
46. As a user, I want to 在参数超出所选模型能力时看到可解释的调整建议, so that Workflow 不会携带明显无效的组合。
47. As a user, I want to 选择保留或移除音频, so that 输出符合素材使用需要而不暗示音频语义分析能力。
48. As a user, I want to 获得当前 Workflow 所需的控制素材清单, so that 我知道执行包中包含什么。

### Workflow 生成与本地 ComfyUI

49. As a user, I want to 基于已确认的分析、Prompt 和参数生成 ComfyUI Workflow, so that 分析结果能转化为可运行资产。
50. As a user, I want to 在编辑会影响 Workflow 的内容后看到“需要重新生成”状态, so that 我不会误用过期 Workflow。
51. As a user, I want to 在重新生成后看到 Workflow 与当前复刻方案一致, so that 下载或发送的内容是最新版本。
52. As a user, I want to 在发送前检查本地 ComfyUI 的连接、版本、节点和模型, so that 执行失败能尽可能提前暴露。
53. As a user, I want to 在环境完整时一键发送 Workflow 到本地 ComfyUI, so that 我无需手工导入节点图即可首次 Queue。
54. As a user, I want to 在模型或节点缺失时看到具体缺失项, so that 我能自行完成环境准备。
55. As a user, I want to 在缺失依赖时避免产品擅自安装软件或模型, so that 本地环境变化仍由我控制。
56. As a user, I want to 在本地 ComfyUI 不可用时仍能下载 Workflow, so that 我可以稍后或在其他环境中导入。
57. As a user, I want to 看到 Workflow 已发送、已 Queue、运行中、成功或失败的状态, so that 我能追踪一次执行。
58. As a user, I want to 保存本地 ComfyUI 返回的执行记录和生成结果关联, so that 我能在复刻项目中回顾结果。

### 输出、历史与可访问性

59. As a user, I want to 下载包含关键帧、Prompt、结构化分析、控制素材和 Workflow 的完整复刻包, so that 我能独立保存和迁移工作成果。
60. As a user, I want to 单独查看或导出结构化分析结果, so that 分析可以用于 Workflow 之外的创作流程。
61. As a user, I want to 让复刻项目保存在本地, so that 我不需要账户或云同步也能持续工作。
62. As a user, I want to 明确知道文件保存位置和导出结果, so that 我可以管理本地存储。
63. As a desktop user, I want to 在宽度不低于 1024px 的界面完成全部工作, so that 三栏工作台保持足够的信息密度。
64. As a mobile user, I want to 查看复刻项目、分析报告和输出状态, so that 我能检查结果而不会误入不适合小屏的编辑流程。
65. As a user with low vision, I want to 获得符合 WCAG 2.1 AA 的对比度和可见焦点, so that 我能识别控件与状态。
66. As a user with reduced-motion preference, I want to 减少非必要动态效果, so that 播放和分析之外的动效不会造成不适。
67. As a user, I want to 通过文字、图标和颜色共同理解状态, so that 信息不只依赖颜色传达。

### 深度动作捕捉与生成服务

68. As a user, I want to 在本地从参考视频生成时间连续的深度控制素材, so that 动作、主体轮廓和前后层次可以进入经过验证的深度控制工作流。
69. As a user, I want to 同步查看参考视频和深度预览, so that 我能在生成前识别闪烁、反转或轮廓破碎。
70. As a user, I want to 看到逐项深度质量结论而不是主观综合分数, so that 我知道素材能否进入正式工作流。
71. As a user, I want to 在 Apple Silicon、CUDA 或 CPU 上完成本地深度提取, so that 控制素材生成不依赖云端服务。
72. As a user, I want to 使用 Wan2.2 Fun Control 深度模板生成并 Queue 可执行工作流, so that 深度素材能够形成完整本地复刻路径。
73. As a user, I want to 在选择云端生成服务时看到其真实能力等级, so that 我不会把参考式生成误认为原生深度控制。
74. As a privacy-conscious user, I want to 在每次云端提交前确认供应商与具体素材清单, so that 派生素材和完整参考视频不会被静默上传。
75. As a user, I want to 在供应商失败时保留输入和执行记录且不自动切换服务, so that 我能控制数据去向和生成费用。

## Implementation Decisions

- 产品形态为运行在用户设备上的本地 Web 应用，由 React + TypeScript 前端和 Python + FastAPI 本地服务组成，并连接外部本地 ComfyUI。
- 系统围绕复刻项目组织数据。复刻项目包含参考视频元数据、本地预处理产物、结构化分析、人工修改、复刻方案、Workflow 版本、环境检查、执行记录和生成结果关联。
- 参考视频输入仅接受 MP4 或 MOV，时长为 2～10 秒，最大 200 MB，最低 480P。系统最高读取 4K，但分析使用本地生成的低分辨率代理。
- 输入校验必须区分不可读取、违反硬性输入限制和超出可复刻范围。前两类阻止分析；超出可复刻范围不阻止分析报告，但不承诺生成可靠的可执行工作流。
- 本地分析流水线负责解码、镜头检测、关键帧提取和运动计算。语义分析只接收分析代理，完整参考视频默认不发送。
- 分析开始前必须向用户披露发送内容、接收方和用途。该披露属于分析服务边界的可验证行为，不得仅作为帮助文档存在。
- 首批分析服务支持百炼、OpenAI、Gemini、豆包和 Claude。用户必须明确选择供应商和产品已验证模型；系统不得自动选择、自动切换或接受任意模型 ID。
- 各供应商密钥由用户提供并使用系统安全存储管理，由本地服务直接调用供应商，不经过产品代理服务器；项目只记录供应商、模型和分析版本。
- 分析服务必须使用可验证的结构化响应契约。返回内容需要转换为稳定的产品领域结构，而不是让界面直接依赖供应商原始响应。
- 供应商失败不得触发静默切换。失败状态保存本地预处理成果、失败阶段和可重试信息。
- 分析过程采用可恢复的阶段状态：待处理、进行中、已完成、失败。重试从可安全恢复的最近阶段继续。
- 结构化分析至少包含基础事实、适用性检查、主体、场景、动作、运镜、光线和时间范围。每项内容必须标记为观察事实、复刻建议或未支持能力之一。
- 不确定性只在具体字段或条目上表达，并包含可理解的原因；产品不计算或展示综合复刻相似度百分比。
- 人工修改与自动分析结果分层保存。重新分析不得无提示覆盖已经确认的人工修改。
- 复刻工作台采用三栏主布局：左侧参考视频与关键帧，中间结构化分析，右侧复刻方案、Prompt、参数、Workflow 和本地 ComfyUI 操作。
- 工作台的核心交互是一套共享时间选择状态。点击带时间范围的分析条目会定位视频，并同步高亮时间轴、关键帧和相关分析内容。
- 视觉方向采用已确认的“胶片检测台”：温暖浅灰白背景、深炭灰信息结构、橙红色时间选区和主操作、蓝灰色连接与辅助状态，以及克制的胶片条和时间码元素。
- 视觉稿仅作为布局与风格基准。稿件中的人物、项目、模型运行结果、品牌标语和示例数据不是产品事实，不得直接固化到实现中。
- 普通创作者与 ComfyUI 创作者共用同一流程。智能模式为默认状态；高级设置是渐进展开区域，不构成第二套独立产品。
- 智能匹配默认依据参考视频选择比例、分辨率和时长，并在模型能力或资源限制下提供可解释调整。
- 高级设置仅允许覆盖比例、分辨率、时长、音频和生成数量。MVP 输出格式固定，不提供 MOV 输出选择。
- 音频只支持保留或移除，不进行语义、口型或音频驱动分析。
- 推荐策略必须包含选择理由和能力状态。只有经过产品集成验证的模板可称为可执行工作流；其余内容只能显示为后续建议。
- Prompt 在用户点击“生成提示词”后按需生成，不随分析完成自动调用；首版生成通用图生视频的中英文正向与负向 Prompt，不提供特定第三方平台格式。
- Prompt 必须记录所依据的结构化分析版本。影响 Prompt 的分析发生变化后，已有结果标记为需要重新生成，但不得自动覆盖用户编辑。
- 超出可复刻范围时仍允许生成 Prompt，但必须标记为实验性建议，且不得暗示其对应可执行工作流。
- MVP 可执行工作流仅支持 Wan2.2 14B I2V、Wan2.2 Fun Camera 和 Wan2.2 Fun Control 深度模板。模板层负责把统一复刻方案转换为特定 Workflow，并校验必要输入和参数。
- 深度动作捕捉使用本地视频深度模型生成时间连续的相对深度控制素材；不把帧变化强度、骨骼姿态或三维网格称为深度动作捕捉。
- 本地深度提取最低目标为 Apple Silicon M1 / 8GB，同时支持 CUDA 与较慢的 CPU 回退；最低目标不包含运行 Wan2.2 Fun Control。
- 深度控制素材必须经过完整性、动态范围、时间闪烁、方向稳定、边缘连续性和时间对齐检查。结论为通过、需要检查或失败，不计算综合相似度。
- 本地深度捕捉与生成服务通过稳定素材边界连接；本地 ComfyUI 是唯一经过验证的原生深度控制服务。
- 云端生成服务采用显式能力声明与用户选择。MiniMax H3 和豆包 Seedance 2.0 在专项验收前只属于实验性参考式生成，Grok 和 Veo 不进入首个开发批次，OpenAI Sora 不实现适配器。
- 完整参考视频默认不上传。任何云端生成提交必须披露供应商、具体素材、大小与用途，并获得本次提交授权；授权不得跨供应商复用。
- 生成服务失败不得触发静默切换或重复计费提交；生成运行保留执行时的策略、能力和输入快照。
- 生成 Workflow 时记录其所依据的复刻方案版本。任何会影响输出的人工修改都会把现有 Workflow 标记为过期，直到用户重新生成。
- 本地 ComfyUI 集成形成独立适配边界，负责连接检查、环境能力读取、Workflow 发送、Queue 状态和执行结果关联；产品领域不直接依赖 ComfyUI 的传输细节。
- 环境检查分别报告分析服务、本地 ComfyUI、版本、模型和节点状态。缺少本地 ComfyUI 不阻止分析和下载；缺少模型或节点阻止直接发送，但不触发自动安装。
- 声明支持的 ComfyUI 精确版本必须等三个可执行工作流完成真实集成测试后锁定，在此之前不得虚构兼容版本。
- 完整复刻包至少包含关键帧、结构化分析、正负 Prompt、控制素材、推荐参数和 ComfyUI Workflow，并记录可理解的清单和版本信息。
- 复刻项目、分析产物、Workflow、执行记录和生成结果均保存在本地。MVP 不引入用户账户、产品云同步或产品服务器端项目存储。
- 密钥与项目数据分离；导出复刻包和项目持久化都不得包含分析服务密钥。
- 桌面端是完整操作界面，目标宽度不低于 1024px。移动端只提供项目、报告和输出查看，不提供完整编辑与发送流程。
- 核心流程遵循 WCAG 2.1 AA：键盘可达、可见焦点、足够对比度、状态不只依赖颜色，并尊重减少动态效果偏好。
- 动效只用于视频播放、时间选区联动、分析进度和执行状态变化，不加入与任务无关的装饰动画。
- 界面默认使用简体中文，信息结构允许未来增加英文，但 MVP 不要求完成英文界面。
- 实现应优先维持少量高层边界：完整复刻任务、分析服务、本地 ComfyUI 和本地持久化。内部模块可以围绕这些边界组织，但不得为了假设中的未来供应商或工作流类型提前建立复杂插件系统。

## Testing Decisions

- 所有测试优先验证用户或外部系统可观察的行为，不断言组件内部状态、私有函数调用顺序、供应商 SDK 细节或具体节点拼装实现。
- 当前代码库尚无实现和测试先例。第一批测试应建立少量高层测试夹具，覆盖确定性的本地视频样本、可控制的分析服务替身、可控制的本地 ComfyUI 替身和临时本地项目存储。
- 最高测试缝隙是完整复刻任务：从上传受支持的参考视频开始，经过分析、人工修改、Workflow 生成，最终完成下载或发送。至少一条端到端路径必须验证普通创作者无需编辑节点即可得到可用输出。
- 完整复刻任务测试需要覆盖受支持视频成功、违反硬性输入限制、超出可复刻范围、没有本地 ComfyUI 仍可下载、编辑后 Workflow 过期以及重新生成后恢复有效等行为。
- 分析服务边界测试通过稳定替身验证分析代理内容、隐私披露、结构化结果转换、无密钥、鉴权失败、超时、无效响应、重试和不静默切换供应商。
- 分析服务测试必须证明失败后本地预处理仍然存在，并且从失败阶段重试不会重复不必要的解码和关键帧提取。
- 本地 ComfyUI 边界测试通过兼容的 API 替身验证连接检查、版本与依赖报告、Workflow 发送、Queue 状态、运行结果和失败反馈。
- 本地 ComfyUI 测试必须分别覆盖未连接、节点缺失、模型缺失、环境完整、Queue 失败和运行失败；断言用户看到的状态及可继续执行的操作，不断言内部 HTTP 库调用细节。
- 三个可执行工作流都必须有真实 ComfyUI 集成测试。集成测试要证明 Workflow 可导入，并在依赖完整的声明环境中成功 Queue；只有这些证据足够后才能锁定正式兼容版本。
- 深度捕捉测试必须覆盖 Apple Silicon、CUDA 与 CPU 的相同输出契约，并在 M1 / 8GB 目标机上用 2～10 秒固定样本验证内存稳定性。
- 深度质量测试分别覆盖帧数或时长不一致、动态范围塌缩、无对应画面运动的闪烁、近远方向反转、主体边缘破碎和时间轴错位。
- 云端生成服务测试必须验证能力不满足时不会提交、未授权素材不会上传、完整参考视频不会被自动绑定、应用重启不会造成重复计费提交。
- 本地持久化边界测试验证复刻项目保存与恢复、人工修改保留、Workflow 版本关联、执行记录关联、导出包完整性以及任何存储和导出中都不包含 API 密钥。
- 时间联动测试在工作台层验证点击分析时间范围后的视频定位，以及时间轴、关键帧和相关分析条目的同步高亮。
- 参数测试使用边界值覆盖比例、分辨率、时长、音频和生成数量，验证智能匹配结果、合法覆盖和超出模型能力时的解释性反馈。
- 可访问性测试覆盖键盘完成核心流程、焦点顺序、焦点可见性、语义标签、颜色对比、非颜色单一传意和减少动态效果偏好。
- 响应式测试验证桌面宽度不低于 1024px 时可完成完整流程；移动宽度下只允许查看项目、报告和输出，不暴露无法可靠使用的完整编辑操作。
- 性能验收使用符合可复刻范围的固定样本与明确的测试环境，测量从确认分析到复刻方案就绪的时间。常规样本目标为 2 分钟内完成，供应商排队或网络耗时需要单独记录。
- 产品质量指标以批量验收集衡量：至少 95% 的受支持视频生成完整复刻包，至少 95% 的 Workflow 成功导入声明环境，环境完整时至少 90% 的 Workflow 能进入 Queue。
- 不以生成画面的主观相似度作为自动化放行条件。效果评估应按主体、场景、动作、运镜和光线分别记录，并与 Workflow 可执行性指标分开。

## Out of Scope

- 恢复原作者的 Prompt、种子、模型配置或制作流程。
- 承诺逐像素复现或展示综合复刻相似度百分比。
- 多镜头长视频、复杂多人交互、高强度或复杂非刚性运动的可靠复刻。
- 口型、对白、音乐、环境声或其他音频语义分析。
- 音频驱动生成、口型同步和自动配音。
- 当前 MVP 的云端视频生成、产品托管模型和产品服务器代理分析请求；MiniMax H3 与豆包 Seedance 2.0 由独立实验里程碑验收。
- 自动多轮生成、生成结果反向评价和自适应优化。
- 产品内 ComfyUI 节点图编辑器。
- 自动安装 ComfyUI、自定义节点、模型或其他本地依赖。
- 除 Wan2.2 14B I2V、Wan2.2 Fun Camera 和 Wan2.2 Fun Control 深度模板之外的可执行工作流。
- 视频编辑、裁剪编排、视频延长、首尾帧独立模式和版权 IP 生成。
- MOV 输出格式；MVP 只将 MOV 作为参考视频输入格式之一。
- 用户账户、团队协作、云端项目同步和跨设备项目历史。
- 完整的移动端编辑、Workflow 生成和发送体验。
- MVP 英文界面以及其他国际化语言。
- 未经真实集成验证的 ComfyUI 版本兼容声明。

## Further Notes

- 产品英文名为 AI Video Reverse Engineer，中文名为 AI 视频复刻分析器。
- 产品对外描述应始终使用“复刻起点”“可解释”“可编辑”“可执行”等可验证表述，不使用“精确还原”“恢复原始 Prompt”或类似承诺。
- 已确认的视觉基准是“胶片检测台”方案：三栏工作台、底部关键帧胶片条和橙红色时间选择是主要识别点。
- 视觉稿中出现的 MKV 输入、超过 10 秒的示例、未经确认的品牌标语及合成人物内容不属于规格，实施时必须替换为符合本规格的受控示例。
- 当前可用证据包括两张竞品入口与参数面板截图，以及一张经确认的合成视觉方向稿；当前没有真实用户访谈、可用性测试、客户案例或复刻效果基准，不得将其表述为已有证据。
- 当前唯一开放的技术兼容决策是正式支持的 ComfyUI 精确版本。该决策由三个可执行工作流的真实集成测试结果锁定。
- 本规格已按完整复刻任务、分析服务、本地 ComfyUI 和本地持久化四个高层测试缝隙组织。后续拆票应沿这些边界形成可纵向验证的 tracer-bullet，而不是按前端、后端和基础设施横向切割。
