# 04：可恢复的多供应商语义分析设计

Status: superseded

Superseded by: [`04-image-reference-and-multi-provider-analysis-design.md`](./04-image-reference-and-multi-provider-analysis-design.md)

> 本文保留为历史设计记录。后续实现不得继续使用本文的“五家首批、Grok/GLM/Kimi 第二批”范围，应以替代设计中的七种分析方式和统一 `ReferenceMedia` 边界为准。

## 目标

让用户在明确了解数据边界后，使用自己配置的分析供应商和已验证模型，将本地分析代理转换为稳定、可恢复的结构化视频语义分析。第一批支持阿里云百炼、OpenAI、Google Gemini、火山方舟豆包和 Anthropic Claude。

### 第一批

- 阿里云百炼

- Anthropic Claude

### 第二批

## 核心架构

后端建立统一 `AnalysisProvider` 接口。语义分析任务只依赖该接口和统一领域模型，不依赖供应商 SDK 或原始响应结构：

```text
分析代理
  → 统一分析请求
  → 用户明确选择的供应商适配器
  → 供应商结构化输出
  → 本地严格校验与领域转换
  → 结构化分析
```

首批五个供应商使用明确适配器实现，不建立任意插件系统。适配器负责鉴权、模型参数、图片编码、供应商请求和错误映射；领域层负责响应校验、时间范围校验、本地判断合并、版本控制和持久化。

供应商失败不得触发自动回退。用户只有在界面中明确切换供应商并重新分析时，数据才会发送给另一接收方。

## 配置模型

应用级设置保存每个供应商的：

- 是否已配置
- 地域、业务空间 ID、项目 ID 等非敏感连接参数
- 默认已验证模型
- API Key 的系统安全存储引用状态

API Key 使用 Python `keyring` 写入系统安全存储；macOS 使用系统钥匙串。前端只提交新密钥，后端读取接口只返回“未配置”或“已配置”和必要掩码状态，任何接口都不得返回密钥明文。

每个供应商维护产品内置的已验证模型列表和一个推荐默认模型。用户可从列表切换，不允许手填任意模型 ID。模型列表属于版本化产品配置，只有完成视觉输入与结构化输出契约测试的模型才能加入。

供应商所需连接字段由各适配器声明。百炼等地域绑定服务只允许选择受支持地域并填写业务空间 ID，由后端构造固定官方地址；不得接受任意 Base URL。

## 项目级分析选择

复刻项目记录：

- 本次选择的供应商 ID
- 本次选择的已验证模型 ID
- 语义分析任务及其状态
- 分析所依据的参考视频 ID 和本地预处理 ID
- 成功结果的供应商、模型、分析版本和请求时间

凭据属于应用级设置，不进入复刻项目。用户可以在分析前切换供应商；已有结果不会因切换而自动重跑。分析完成后切换供应商必须明确点击“重新分析”，并遵清楚新的数据接收方。

## 数据边界

所有供应商只接收：

- `contact-sheet.jpg`
- `analysis-proxy.json`
- 固定系统说明和结构化输出 Schema

不得发送完整参考视频、独立原始关键帧、本地绝对路径、参考视频原文件名、项目名、API Key 或其他供应商凭据。分析开始前，界面必须展示将发送的内容、接收供应商、所选模型和用途，并由用户主动确认。

## 统一结构化分析

供应商响应必须转换为稳定的产品领域结构，至少包含：

- 基础事实
- 适用性检查
- 主体
- 场景
- 动作
- 运镜
- 光线
- 每项对应的时间范围
- 条目类别：观察事实、复刻建议或未支持能力
- 局部置信信息与可理解原因

本地预处理已确认的镜头和运动结论与语义结果合并；供应商不得覆盖确定性的本地失败结论。主要主体数量和复杂交互由语义分析补全，最终得到 `in_scope` 或 `out_of_scope`。产品不生成综合相似度百分比，也不声称恢复原始 Prompt。

## 任务状态与恢复

语义分析任务状态为：未开始、排队、运行、完成、失败。任务在开始外部调用前先持久化，前端通过现有项目读取接口轮询状态。

- 同一项目只允许一个活跃语义分析任务。
- 失败只重跑语义分析，不重新执行解码、镜头检测、关键帧提取或运动分析。
- 上一次成功结果在新请求失败时保留，并清楚标记新请求失败。
- 服务重启后遗留的排队或运行任务转为“已中断，可重试”。
- 请求完成时同时核对任务 ID、参考视频 ID 和本地预处理 ID；任何不匹配的旧结果都不得覆盖当前项目。
- 重新分析不得无提示覆盖 Ticket 06 中用户已确认的人工修改。

## 统一错误模型

供应商错误转换为以下稳定类别：

- `provider_unconfigured`
- `authentication_failed`
- `rate_limited`
- `network_error`
- `timeout`
- `unsupported_model_capability`
- `content_rejected`
- `invalid_response`
- `provider_error`
- `analysis_interrupted`

每个错误包含用户可理解的信息和是否可重试。日志、异常、响应和项目文件必须移除 API Key、Authorization 请求头和供应商原始敏感内容。

## 界面流程

### 应用级配置

供应商配置界面以卡片呈现首批五家供应商。每张卡片包含配置状态、供应商所需连接字段、API Key 写入或替换、连接测试和已验证模型选择。

删除密钥必须明确二次确认。切换供应商不删除旧凭据。连接测试只验证当前配置能完成最小能力请求，不承诺真实分析一定成功。

### 项目语义分析

本地预处理完成后，项目页展示语义分析区域：

1. 用户选择已配置供应商和已验证模型。
2. 界面展示将发送的分析代理内容、接收方和用途。
3. 用户确认后点击“开始语义分析”。
4. 界面展示排队、运行、完成或失败状态。
5. 成功后进入 Ticket 05 的复刻工作台。
6. 失败时保留本地预处理和上一版成功分析，并提供重试。

## 测试策略

建立供应商契约测试，首批每个适配器必须证明：

- 只发送联系表、运动数据和固定提示结构。
- 不发送完整视频、本地路径、文件名、项目名或密钥。
- 可把供应商结构化结果转换成统一领域模型。
- 鉴权、限流、网络、超时、能力不支持、内容拒绝和无效响应正确映射。
- 失败不自动切换供应商。

任务与持久化测试覆盖重复启动、失败重试、服务重启、素材替换、旧请求返回、上一版成功结果保留和旧项目数据兼容。安全测试证明所有读取接口、项目文件、日志和导出内容均无法获得密钥明文。

默认自动化测试只使用供应商替身，不发起真实外部请求或产生费用。真实 API 冒烟测试必须显式启用并使用用户自行配置的凭据；每家供应商完成真实视觉输入和结构化输出测试后，其模型才能进入已验证列表。

## 交付顺序

1. 统一领域契约、系统安全存储、配置状态和可恢复任务。
2. 百炼适配器及完整端到端基准路径。
3. OpenAI、Gemini、豆包、Claude 适配器，每加入一家都运行同一契约测试。
4. 五供应商配置、项目选择和跨供应商回归。
5. 第二批与企业部署层分别建立后续 Ticket。

## 暂不包含

- 自动选择、自动切换或失败回退供应商。
- 用户手填任意模型 ID 或任意 Base URL。
- 向供应商发送完整参考视频。
- 第二批、企业部署层或暂缓供应商的实现。
- 云端密钥托管、账户同步或团队共享配置。
