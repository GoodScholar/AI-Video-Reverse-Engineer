# 全站正式界面迁入规格

Status: resolved
Type: task

## Problem Statement

内部交付团队需要沿用已认可的全站视觉稿完成真实制作。旧界面将商品资料、脚本、声音和成片分散在长表单中，导航与参数密度阻碍操作；新页面还需要共同遵循设计体系，避免后续扩展产生不同视觉语言。

## Solution

以统一应用框架串起项目中心、商品视频制作、项目素材、单条精修、成片与审片、参考视频复刻、本地工具、应用设置。使用真实项目和现有接口，按“准备资料 → 确认脚本 → 选声制作 → 审核导出”完成商品内容流程，保留原有复刻能力与兼容入口。全站遵循根目录设计体系。

## User Stories

1. 作为内部交付团队成员，我希望看到真实最近项目，以便继续已有制作。
2. 作为内部交付团队成员，我希望新建项目失败时保留名称，以便重试。
3. 作为内部交付团队成员，我希望知道当前项目，以便避免把修改写入其他项目。
4. 作为内部交付团队成员，我希望在同一项目各页面之间切换时保留草稿，以便核对素材后继续编辑。
5. 作为内部交付团队成员，我希望未保存时有明确说明，以便先保存再切换项目。
6. 作为内部交付团队成员，我希望一页准备创作简报和项目素材，以便减少重复录入。
7. 作为内部交付团队成员，我希望发送前看到文字和目标分析服务，以便确认本次外部请求。
8. 作为内部交付团队成员，我希望资料保存失败后不发送旧内容，以便避免错误脚本。
9. 作为内部交付团队成员，我希望逐条核对脚本候选和对应画面，以便确认商品事实。
10. 作为内部交付团队成员，我希望修改候选后保存当前版本再确认，以便后续使用正确内容。
11. 作为内部交付团队成员，我希望已确认候选可直接交给批量混剪，以便避免再次录入五条脚本。
12. 作为内部交付团队成员，我希望查看声音特点、适用场景和真实样音，以便选择音色。
13. 作为内部交付团队成员，我希望选择音色与开始配音分开，以便核对后才制作。
14. 作为内部交付团队成员，我希望看到真实制作与预览进度，以便定位失败作品。
15. 作为内部交付团队成员，我希望按审核状态筛选短视频变体，以便集中处理待审核或需修改的作品。
16. 作为内部交付团队成员，我希望选择作品后核对其视频、字幕和审核意见，以便意见不会串到其他作品。
17. 作为内部交付团队成员，我希望从审片进入单条精修后仍处理同一作品，以便明确修改对象。
18. 作为内部交付团队成员，我希望修改输入后旧预览与旧审核被标记失效，以便避免导出错误版本。
19. 作为内部交付团队成员，我希望只导出符合检查且审核通过的作品，以便交付真实合格成片。
20. 作为内部交付团队成员，我希望素材页支持图片、视频与音频的正确呈现，以便核对内容。
21. 作为内部交付团队成员，我希望保留参考视频复刻与本地工具能力，以便处理现有复刻项目。
22. 作为内部交付团队成员，我希望统一管理服务连接和备份，以便配置应用环境。
23. 作为内部交付团队成员，我希望手机上导航和主操作仍可使用，以便浏览项目与成片。
24. 作为内部交付团队成员，我希望失败、空状态、草稿和不可用操作说明清楚，以便知道如何恢复。

## Implementation Decisions

- 复用应用框架、制作页面协调、脚本创作、批量混剪、素材与复刻工作台、服务设置和项目备份模块。
- 不改后端契约或数据库结构；已有接口足以完成本轮正式接入。
- 正式首页默认进入内容工作室，旧工作台保留兼容入口，开发视觉稿继续独立。
- 同一项目的编辑模块保持实例和草稿；项目切换通过项目标识隔离，迟到响应不能覆盖新项目。
- 资料保存、发送预览、显式确认、候选确认和交接遵循现有版本规则。
- 制作、审片和精修共用同一批量任务状态；筛选只改变展示，不修改审核数据。
- 审片使用真实变体集合、预览与审核状态；支持全部、待审核、已通过、需修改筛选。旧审核失效归入需修改。
- 输出必须绑定保存内容、变体和字幕版本；草稿或过期预览不能直接通过审核或导出。
- 封面、缩略图、样音与播放器来自真实项目或真实音色目录；无文件时给出中性占位。
- 素材与声音选择按项目暂存，不以导航切换触发生成；未保存音色与商品/批量草稿位于标签页内存，刷新前需保存。
- 统一颜色、字体、圆角、间距、响应式与可访问性；不新增依赖、模型、字体或外部媒体下载。

## Testing Decisions

- 使用已有页面公开操作和 HTTP API 边界，沿用前端组件行为测试及真实浏览器检查。
- 测试用户看得见的行为：错误恢复、跨页草稿、项目隔离、发送确认、筛选、对应作品选择和过期导出限制。
- 在现有项目入口、脚本与批量编辑测试中补充具体缺口，不测试私有状态或复制实现算法。
- 每个实际行为修复先观察失败测试再实施；样式变更以真实视口截图和溢出检查验证。
- 全部前端测试与生产构建作为最后集成检查；已有后端契约保持不变，本轮不重复无关模型或后端压力验收。
- 审查按设计规范一致性和规格完成度两轴执行，限定本轮迁入相关文件及既有工作区差异；不审查无关未提交成果。

## Out of Scope

- 数字人直播、新增生成模型、专业剪辑功能扩展、远程发布与自动提交。
- 重新选择全站视觉方向，新增组件库或字体依赖。
- 代替用户调用收费分析或生成服务来完成验收。
- 无客户授权素材情况下宣称客户交付验收完成。

## Further Notes

视觉稿已经确认，正式迁入部分实现已在当前工作区。每张任务票需核对已有实现和验证证据，只补剩余缺口。原型完成不等于正式接入完成，根目录设计体系是持续维护基准。
