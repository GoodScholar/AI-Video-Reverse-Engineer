## 1. 执行摘要

项目已经完成一个真实、可操作、可恢复的 **v1 内部交付闭环**：从内容项目、商品简报、真实 AI 脚本候选、人工确认、音色选择、本地配音、两条差异化变体、字幕与时间线、真实预览、人工审核，到批准版本导出，均有正式 UI、服务端状态、版本门禁、备份恢复和真实媒体证据。P0 技术基线和真实商品内部试点均已通过，正式生产路径不是单纯页面 Demo。

但项目尚未完成“商用自动混剪”这一更高阶核心能力。当前所谓按脚本推荐，本质是脚本文字与素材名称/备注的关键词匹配；它没有看片、没有片段级视觉索引、没有智能选择源入点、没有 `MontagePlanner`、没有转场对象、没有主体感知竖屏裁满，也没有商用金标验收。当前系统能稳定生产作品，但仍需要制作人员承担主要选片和剪辑判断。

因此不能用一个“已完成”覆盖所有层级：

| 判断层级 | 结论 | 估算 |
| --- | --- | --- |
| P0 / v1 内部交付范围 | 已完成 | 约 95%～100%；权威验收结论为完成 |
| 当前核心产品（P0 + 已冻结 P1） | 进入中段 | 约 60%～65% |
| 商用自动混剪专项 | 尚未实施 | 6 张实施票据均未开始；底层项目/素材/时间线/审核基础已具备 |
| 客户商业交付就绪度 | 未完成 | 约 50%～60%；缺真实客户签收、质量基准、部署与权限能力 |
| 包含 P2、SaaS、协作、发布等长期愿景 | 早中期 | 约 35%～45% |

当前最准确的阶段描述是：**v1 内部真实商品试点已经完成，项目正处于 P1 商用自动混剪与工程产品化开始之前；不是 Demo，但也不是可对外宣称“商用自动剪辑已完成”的产品。**

## 3. 原计划功能清单

### 3.1 P0：v1 唯一黄金流程

原计划要求：

1. 创建、打开、保存和恢复统一内容项目；
2. 管理项目素材、来源、使用范围、稳定 `assetId` 和引用保护；
3. 保存商品事实、受众、卖点、行动引导和禁用表达；
4. 调用已验证 AI 服务生成五条结构化脚本候选，并支持人工编辑、确认和版本追溯；
5. 试听、选择并生成与确认脚本版本绑定的本地配音；
6. 建立至少两条镜头安排不同的短视频变体；
7. 编辑字幕、音频和变体编辑序列；
8. 生成真实预览，逐条完整听看并进行人工审核；
9. 只允许从当前有效且已批准的冻结预览导出最终 MP4；
10. 保存版本、运行、失败、取消、重试、审核、交付和恢复证据；
11. 完成桌面、键盘、移动查看和明确错误反馈；
12. 关闭与当前外部生成边界冲突的旧最终生成提交入口。

## 7. Demo、Mock 与半成品识别

### 7.1 正式产品路径

没有发现正式八页工作室用 Mock 数据替代核心项目、脚本、配音、预览、审核或导出的情况。正式路径调用真实 FastAPI 和项目级文件状态。

### 7.2 开发原型

仓库仍保留 `WholeSiteStudioPrototype` 和 `ContentStudioPrototype`。它们使用演示数据、标签页内存状态和不可持久化交互，但只在 Vite 开发模式加 `?prototype=...` 时动态加载，生产构建不会进入正式入口。这不构成线上假功能，但构成重复维护和仓库认知成本。

### 7.3 容易被误解为完成的半成品

1. **“智能推荐”**：当前实现明确写为 `asset-metadata-keywords`，只匹配素材名称和备注；不能宣传为视觉语义选片。
2. **ComfyUI Workflow**：可以导出候选 API 格式包，但 README 和包内说明均承认尚未在目标 Queue 验证；不能称为已验证可执行工作流。
3. **可选本地工具**：部分工具有真实实现和协议测试，但缺模型、权重或目标硬件时会明确不可用；不能把“页面存在”算作完整能力。
4. **关系画布**：当前是只读投影与布局组织，不是可以改业务依赖的流程编排器。
5. **移动端**：目标是查看和关键审核路径，不是完整移动剪辑器。

## 8. 前端、后端、存储、接口、权限与状态流转审查

### 8.1 前后端与接口

- 正式 UI 到核心 API 已打通；
- 后端共有 127 个 `/api` 路由，核心模块有显式错误码和冲突响应；
- 前端和后端之间没有生成式 typed client 或统一 OpenAPI 客户端，类型和路径主要手工同步；
- API 没有版本前缀，后续对外开放前需要稳定契约和废弃策略；
- 六个旧最终生成 POST 路由仍注册在 OpenAPI 中，只由中间件统一返回 410。行为边界正确，但接口表面仍会误导调用方。

### 8.2 数据与“数据库结构”

项目当前没有 SQL 数据库，采用项目级 JSON + 媒体文件存储：

| 领域 | 当前存储 |
| --- | --- |
| 项目目录 | `backend/data/projects.json` |
| 分析服务非密配置 | `backend/data/analysis-providers.json` |
| 密钥 | 系统安全存储，不进入项目 JSON |
| 制作计划/素材/镜头/画布 | `project-files/<project>/preproduction/` |
| 商品简报和脚本 | `aigc-content/state.json` |
| 批量任务、变体、配音、预览、审核、交付 | `batch-edits/state.json` |
| 主时间线 | `timeline/state.json` |
| 参考复刻/人物动作/声音 | 各自项目级目录和 `state.json`/`catalog.json` |
| 媒体与产物 | 项目目录下的版本化文件 |

优点是本地部署简单、可检查、可打包；现有实现使用临时文件、`fsync`、`os.replace`、修订校验和备份哈希，已经超过普通 Demo 的可靠性。

限制是没有数据库级外键、事务和查询索引。模块间一致性依赖应用服务，锁主要是进程内 `RLock`；一旦采用多进程、多用户或共享文件系统，当前锁和 JSON 写入模型不能直接保证一致性。当前本地单用户范围可以接受，但未来 SaaS 或多 Worker 不能直接沿用。

### 8.3 权限与安全边界

当前不是账户产品，没有登录、角色、项目成员或 RBAC。已有安全边界包括：

- 默认本地服务；
- 敏感写请求的 Origin 白名单、Content-Type 和 `X-AIVRE-Intent` 检查；
- 分析密钥进入系统安全存储，不进入前端、项目状态或日志；
- 上传、ZIP、路径、符号链接和项目子路径防护；
- 供应商调用前披露和不静默切换。

这满足当前本地内部团队工具的基本假设，但不满足客户自助、局域网多人或公网 SaaS 的权限要求。

### 8.4 状态流转

状态设计总体符合规划：运行成功不等于采用，预览生成不等于审核通过，审核通过不等于任意新版本都可交付。输入变化会通过版本链使预览和批准过期，内容制作阶段是从事实派生的只读投影，而非另存一份全局状态。

这是当前实现最完整、也最有产品价值的部分之一。

## 9. 与原计划存在偏差的功能

### 9.1 能力口径偏差

1. **“AI 智能剪辑”命名超前**：代码仍是元数据关键词匹配，与规划中的视觉语义选片和商用自动初稿有实质差距。
2. **竖屏适配弱于商用规划**：当前说明是“完整适配画布”，渲染允许填边；最新规格明确要求主体感知裁满且不得用黑边冒充完成。
3. **八页 IA 被旧工作台内嵌导航稀释**：进入“参考视频复刻”后仍出现“需求、素材、镜头、工具、剪辑、批量混剪、交付”七个内部页签，与顶层项目素材、本地工具、单条精修、成片与审片发生重复入口。
4. **最终生成边界只在运行时阻断**：旧写路由仍注册，虽然返回 410，但架构上仍保留已废弃提交接口和执行代码。
5. **项目导航没有 URL 深链接**：页面选择和当前项目只在 React 状态中，刷新回到项目中心；持久化数据不丢，但工作上下文不可分享/恢复。

### 9.2 文档与实际偏差

1. `PRODUCT.md` 仍写参考视频 2～10 秒、最低 480P；README 和当前代码为 2～300 秒、无最低分辨率门槛。
2. `PRODUCT.md` 仍写 04c 只支持百炼和本地 OpenAI 兼容服务；README 和代码目录已有八类 Provider。
3. `ai-content-services/roadmap.md` 与 `completion-matrix.md` 仍写真实商品试点未通过、脚本为手工草稿、作品未批准；票据 06 和当前提交已经证明 P0 技术基线与真实商品试点完成。
4. 多套历史验收目录同时存在，部分票据已被新范围冻结结果覆盖，却未统一标记 `superseded`。
5. 最新范围冻结规格、ADR 0011/0012 和商用自动混剪规格在当前工作树仍是未跟踪文件。它们被当作当前权威目标，但没有进入 Git 历史，无法保证换机器或回退后仍能重建相同决策。

### 9.3 历史规划冲突的处理结论

旧计划曾要求应用内直接提交 ComfyUI 最终生成；现行 ADR 明确改为“准备、导出、外部执行、结果回填”。本次不把关闭旧提交入口算作功能倒退，而视为按新范围修正。真正的偏差是旧代码和 OpenAPI 表面仍未完全清理，而不是缺少应用内生成。

## 11. 当前技术债务

按优先级排序：

### 高

1. **权威规划尚未提交且状态互相矛盾**：这是交付和后续 Agent 执行的直接风险。
2. **商用混剪核心算法缺失**：现有元数据匹配不能支撑产品名称和商业承诺。
3. **JSON 多模块事务与进程内锁边界**：当前适合单进程本地使用，不能直接扩成多用户/多 Worker。
4. **缺少 CI 与发布门禁**：仓库未发现 CI 配置；完整测试依赖本地执行。

### 中

5. `backend/app/main.py` 2574 行、`batch_editing_api.py` 1123 行、`preproduction_api.py` 1156 行，模块边界虽已开始提取，但 API 编排仍过重。
6. API 路径和前端类型手工维护，没有契约生成或版本化策略。
7. 正式工作室把多个大型工作区保持挂载，仅用 `hidden` 切换；容易产生后台请求、状态耦合和不必要渲染。
8. 生产 JS 主包约 715.59 kB（gzip 223.53 kB），没有按页面/工作流充分拆包。
9. 没有独立 lint 脚本和严格 Python 静态类型门禁；当前主要依赖测试、TypeScript 与人工约束。
10. 可选模型/硬件检查分散，缺少统一“本机能力矩阵”和可复现环境包。

### 低

11. Starlette `TestClient` 仍产生 AnyIO 旧别名弃用警告。
12. 开发原型与正式样式、媒体并存，增加仓库体积和认知负担。
13. 页面上下文不进入 URL，刷新和深链接体验较弱。

## 12. 当前产品缺口

技术债务影响代码维护；产品缺口则直接影响用户价值。当前最大产品缺口是：

1. **用户仍需完成大部分选片工作**：系统不会理解视频画面并自动选择最佳片段。
2. **自动初稿没有商用品质门槛**：没有 80% 镜头保留率、≤20% 替换率、无黑边、安全区和包装一致性证据。
3. **没有正式的转场、花字和主体竖屏能力**：成片更像基础拼接与字幕成片，而非稳定达到参考样片包装水平。
4. **没有真实客户反馈闭环**：内部试点证明“能交付”，但未证明“客户接受、愿意使用或能产生商业效果”。
5. **参考复刻仍是准备链而非已验证效果链**：工具、模板和回填存在，但最终生成质量由外部环境承担。
6. **没有面向外部用户的身份、权限、部署和计费**：产品当前仍是内部本地工作台。
7. **素材复用效率有限**：缺跨项目素材库、通用 Provider 和片段级检索。

## 13. 建议优先补齐的功能

### P0.5：先把“当前真相”固定下来

1. 提交或正式归档范围冻结规格、ADR 0011/0012 和商用混剪规格；
2. 更新 `PRODUCT.md`、roadmap 和 completion matrix，使其与票据 06 一致；
3. 给旧规格和重叠验收票据增加 `superseded/historical` 标记与权威索引；
4. 明确产品文案：当前是“脚本/元数据辅助混剪”，商用视觉自动混剪尚在 P1。

这是最优先事项，因为当前代码和测试虽然稳定，但权威计划尚未形成可复现的 Git 状态。

### P1-A：商用自动混剪纵向切片

严格按已拆票据推进：

1. 素材片段索引和区间预览；
2. 本地视觉召回；
3. 经披露后的豆包候选复排；
4. `MontagePlanner` 提案、替换与采用；
5. 采用结果写回现有变体编辑序列并触发既有版本/审核规则。

优先完成这条最小纵向闭环，再扩展效果。否则先做大量转场和模板，仍不能解决核心选片劳动。

### P1-B：成片质量能力

1. 正式镜头边界、转场与音频交叉淡化；
2. 主体感知 9:16 裁满和人工覆盖；
3. 字幕、花字、标题、卖点、CTA 的版本化模板；
4. 冻结预览自动质检；
5. 参考视频金标与另外两组不同素材回归集。

### P1-C：产品化与可维护性

1. 增加 CI：快测、前端测试、TypeScript、生产构建；硬件/真实模型验收单独分层；
2. 收敛嵌套导航和重复入口；
3. 对大型 API 编排模块继续做领域下沉，但不重写整个后端；
4. 增加路由契约/类型生成与废弃策略；
5. 页面懒加载、按需挂载和 bundle 拆分；
6. 建立发布版本、迁移、备份兼容和本机能力检查清单。

### 商业化前必须完成

1. 用真实客户素材完成商用自动混剪金标；
2. 获得可追溯客户签收或修改结论；
3. 明确部署方式、数据责任、素材权利、供应商费用和故障支持；
4. 若要客户自助，再立项身份、权限、项目隔离、审计和计费，不能把当前本地信任模型直接暴露到公网。

## 15. 最终判断

项目没有停留在“页面齐全但后端空壳”的阶段。它已经拥有较强的本地生产基础设施、真实媒体链、版本/审核门禁、失败恢复和真实 P0 试点证据；从工程闭环看，v1 是成立的。

项目也没有完成最初广义愿景中的所有能力。尤其是自动视觉选片、商用混剪规划、主体感知竖屏、转场/花字、自动质检、客户签收、权限与 SaaS 都未完成。把当前产品称为“AI 视频创作与生产工作台 v1”是合理的；把它称为“已经达到商用标准的全自动 AI 混剪平台”则与事实不符。

综合判断：**当前整体约 60%～65%，阶段为“内部 v1 已完成，P1 商用品质与自动化尚待实施”。** 下一阶段应集中解决自动选片和成片质量，而不是继续扩展新的一级模块。
