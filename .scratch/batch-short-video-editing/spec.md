# 批量混剪与字幕交付（第一阶段）

Status: resolved

## Problem Statement

内部交付团队已有项目素材库、单条视频的本地时间线与渲染，以及字幕提取工具，但缺少从同一批素材按客户卖点和已确认脚本制作多条差异化短视频的工作流。当前字幕文件还需要到其他软件中编辑和烧录。团队难以集中预览、逐条修改与审核，更难追溯每条成片采用了哪些素材和脚本。

## Solution

在现有本地工作台增加一个项目内的批量混剪任务。团队导入或选取多段素材，录入客户卖点，确认脚本后请求编排 5–20 条短视频变体。系统依据卖点和脚本推荐镜头顺序及片段取舍，保留每条变体独立的可编辑时间线；不会用随机排列冒充差异化。团队批量查看低清预览，逐条修改镜头与字幕，并明确审核通过后才导出竖版成片。每条变体记录脚本、所用素材、预览版本、审核状态和成片版本。

第一阶段按用户“继续”采用以下规划假设，实施前若业务方给出不同约束，应先更新本规格：客户提供卖点、交付团队确认脚本；每批目标 5–20 条；统一竖版输出预设。此处的 5–20 是目标批量，不保证在本机资源不足或素材不满足时全部一次成功。

## User Stories

1. 作为交付人员，我能在一个项目中选取多段视频、图片与音频素材并查看基础信息，以便确认它们能用于本批短视频。
2. 作为交付人员，我能录入客户卖点、目标受众或用途，并为每条计划产出确认脚本或脚本变体，以便编排有明确内容依据。
3. 作为交付人员，我能指定目标数量并发起批量编排，以便一次得到多条围绕不同卖点或脚本组织的候选成片。
4. 作为交付人员，我能看到每条变体的卖点、脚本、镜头顺序及对应素材，以便判断差异来自内容而非随机顺序。
5. 作为交付人员，我能看到没有足够素材、片段与脚本不匹配、识别模型不可用等问题，以便修正输入或只重试失败变体。
6. 作为交付人员，我能分别打开变体的时间线，调整片段顺序、入出点和现有音频参数，以便人工修正成片。
7. 作为交付人员，我能批量生成并观看每条变体的预览，且看清预览对应的保存版本，以便集中筛选。
8. 作为交付人员，我能对每条变体识别语音字幕、逐句编辑文本和时间，再预览字幕效果，以便纠正识别错误。
9. 作为交付人员，我能在最终 MP4 中看到已经确认的字幕，而不仅收到单独的 SRT 文件。
10. 作为审核人员，我能逐条给出通过或退回并记录原因，以便只交付确认过的变体。
11. 作为审核人员，我能在脚本、时间线、字幕或输出设置改变后看到旧审核已失效，以便避免将旧版批准用于新版成片。
12. 作为交付人员，我能仅导出当前版本已通过审核的变体，并在批量结果中看到成功、失败、可重试项及成片入口。
13. 作为交付人员，我能回看某条已交付成片所对应的脚本、素材和字幕版本，以便复盘或按客户意见修改。

## Implementation Decisions

- 工作流归属现有项目，先服务本地交付团队。保留当前单条时间线及素材库；批量任务和每条变体持有自己的编辑与审核状态，避免一条变体覆盖另一条或项目当前时间线。
- 每条变体应有稳定标识，并保存其脚本、卖点、素材引用、独立时间线、字幕数据、预览及导出运行记录。预览和导出基于已保存的不可变输入快照；草稿、预览、审核与成片需能区分版本。
- 编排应以脚本段落和卖点为依据匹配素材片段。镜头检测、语音转写和素材元数据可复用现有能力；具体推荐依据需要可见、可修改。识别或匹配能力不可用时明确报错，不静默切换成随机混剪。
- 第一阶段复用现有本地时间线的校验、FFmpeg 渲染、异步任务和资源限制。超出既有单条时间线限制的变体应在编排前或保存时给出可行动的错误，不隐式放宽上限。批量任务应有有限并发、逐条进度与失败隔离。
- 字幕作为变体的可编辑、带时间码数据保存。识别结果允许人工修订，字幕预览和最终 MP4 使用同一份已保存数据；导出时烧录，保证所见与交付一致。可额外提供 SRT，但不能以 SRT 代替烧录成片。
- 审核绑定到内容版本。修改脚本、时间线、字幕或输出设置后，该变体需要重新预览和审核；其他变体的已通过状态不受影响。最终导出只接受当前内容版本已通过审核的变体。
- 第一阶段只提供统一竖版预设。具体尺寸、帧率、码率和时长上限在实施时选用现有渲染器支持且业务可接受的值，并在界面中明示；不承诺未经验证的跨平台自动适配。
- 可保留人工选择的片段和审核决定，不因重试或局部失败覆盖已保存版本。输入素材缺失时保留可读记录，但阻止受影响变体的新渲染。
- 与 [AI 内容服务路线图](../ai-content-services/roadmap.md) 关联；AIGC 内容创作与数字人直播代运营均不是本阶段的交付范围。

## Testing Decisions

- 通过现有项目 API、工作台界面和真实 FFmpeg 输出验证主要路径；从多段测试素材与两个不同卖点/脚本生成多条可区分的变体，检查镜头来源、顺序和独立编辑结果。
- 验证同一批中一条失败、一条修改或取消时，其他变体的预览、审核与成片记录保持完整；重启或重试后不会覆盖已通过版本。
- 用带语音的短素材验证识别、字幕文本与时间修改、预览以及最终 MP4 烧录；检查成片画面中出现已修改文本。若测试环境无识别模型，相关真实识别验收明确保持未完成，不能用伪造字幕数据宣称识别质量通过。
- 验证修改脚本、片段、字幕或输出设置会使旧审核失效；未通过审核或审核版本过期的变体无法进入最终导出。
- 通过人工内容验收评估卖点与镜头关联及变体差异；自动测试只证明流程和数据正确，不宣称营销质量达标。

## Out of Scope

- 客户自助平台、团队账号/共享任务、云端排队和跨设备协作。
- 自动发布到任何内容平台、平台专用合规判断或效果投放优化。
- 第一阶段自动生成脚本、营销视频素材或数字人直播；对应计划见路线图。
- 完全无人审片、随机重排充数、专业调色/特效等完整非线性编辑能力。
