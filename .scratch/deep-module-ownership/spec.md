# 共享业务模块提深

Status: ready-for-agent
Type: feature

## Problem Statement

内容项目已经具备分析服务配置、项目素材、镜头步骤、时间线和批量混剪，但四组核心规则仍停留在浅模块或调用方中：分析配置事务横跨主程序与持久化；项目素材由前置工作台的状态和目录间接拥有；镜头步骤的编辑与失效规则埋在 HTTP 路由；时间线与批量混剪分别实现素材冻结、核验和失败回收。

这些问题不会直接增加新功能，却会让同一规则在多个调用方重复解释，降低模块深度、局部性和测试杠杆率。

## Goal

在不改变用户可见行为的前提下，依次提深四个内部业务模块，使调用者只消费目的明确的结论，不再学习事务顺序、存储形状、磁盘路径或失效传播细节。

## Confirmed Decisions

- 一份总规格、四张独立实施票据；每张票据单独实施、测试、审查和提交。
- 优先顺序为 `01 → 02 → 03 → 04`。
- HTTP 契约、错误码、状态文件结构和磁盘目录全部保持兼容。
- 不新增页面、用户功能、运行时依赖、数据库、事件总线或数据迁移。
- 现有 `project-files/<project-id>/preproduction/assets` 目录首轮继续使用，但其位置不再泄漏给业务调用方。

## Target Module Ownership

| 模块 | 拥有 | 不拥有 |
| --- | --- | --- |
| 分析服务配置 | 配置身份、非敏感设置、凭据协调、验证结果、并发 CAS 和迟到结果归属 | 供应商网络协议、语义分析结果 |
| 项目素材 | 稳定素材身份、元数据、文件可用性、上传、引用查询和安全删除 | 制作镜头、时间线或批量混剪的业务决定 |
| 镜头步骤制作 | 编辑校验、依赖传播、候选关联、采用有效性和交付检查 | FFmpeg 执行、运行队列、最终 AI 视频生成 |
| 渲染输入准备 | 稳定素材标识到冻结字节的安全解析、复制、内容核验和失败回收 | 运行生命周期、审核决定、交付决定 |

## Dependency Graph

- `01 提深分析服务配置与验证生命周期`：无技术阻塞，优先实施。
- `02 提取项目素材模块`：无技术阻塞，在 01 之后按优先顺序实施。
- `03 收拢镜头步骤编辑与失效传播`：被 02 阻塞，先让素材所有权稳定。
- `04 统一冻结素材字节与渲染输入准备`：被 02 阻塞；按既定顺序在 03 之后实施。

## Acceptance Criteria

- 分析配置保存、凭据回退、连接验证和迟到结果通过一个深模块保持原子与一致。
- 项目素材不再以“前置工作台私有状态”的方式被时间线、批量混剪、内容阶段或备份直接读取。
- 镜头步骤的编辑、依赖失效、候选关联和检查可以通过业务模块接口直接验证，不必经由 HTTP。
- 时间线与批量混剪共享同一套素材冻结、安全校验和失败回收规则。
- 现有 HTTP 响应、错误码、状态文件、磁盘目录、历史记录和用户操作流程保持兼容。
- 每张票据完成时运行受影响测试，并在最后一张票据执行后端、前端和生产构建全量回归。

## Out of Scope

- 新建素材库页面或改变现有素材管理交互。
- 搬迁项目素材文件、修改素材 ID 或重写历史状态。
- 改变分析供应商目录、模型清单、凭据保存位置或失败切换策略。
- 重新设计时间线、镜头步骤或批量混剪的用户流程。
- 重新统一 `durable_runs`、`batch_production` 或短视频变体有效性。

## Evidence

架构候选来自 2026-09-27 对 `391a9e8` 的代码库体检；相关决策沿用 ADR 0005、0007、0008 和 0009。
