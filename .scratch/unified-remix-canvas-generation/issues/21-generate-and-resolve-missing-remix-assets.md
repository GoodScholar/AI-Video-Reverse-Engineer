# 21: 生成并重新解析 RemixPlan 缺失素材

**What to build:** 让脚本驱动 `RemixPlan` 可以声明缺失文本、图片或视频，向用户展示 Provider、模型、外发内容和可能费用；只有确认后才调用 `GenerationService`，将结果入库为项目素材并重新解析计划，不自动覆盖原提案或人工编辑。

**Blocked by:** 08: 验证文本图片视频真实 Provider 闭环; 20: 统一脚本驱动商业混剪为 RemixPlan

**Status:** ready-for-agent

## Scope

- 缺失需求保存模态、用途、输入来源、能力约束和计划位置，不内嵌 Provider 任意 JSON。
- 确认界面显示实际 Provider、模型、外发内容、可能费用和取消语义。
- 生成结果通过统一项目素材链入库，再以稳定素材身份重新解析新的计划版本。
- 失败、取消、部分成功、迟到结果和输入修订变化不会自动采用。

## Source reuse prerequisite

- 阅读现有混剪提案、素材替换、生成披露和结果入库源码。
- 只通过统一 `GenerationService` 复用已验证适配器，不为混剪单独调用 Provider。

## Acceptance criteria

- [ ] `RemixPlan` 能显示具体缺失文本/图片/视频及其下游影响。
- [ ] 未经用户确认不会发出生成请求；确认包含 Provider、模型、外发和费用提示。
- [ ] 成功结果以稳定项目素材身份入库，重新解析生成新计划修订且保留旧计划。
- [ ] 部分成功只解决对应缺失项，失败或迟到结果不自动采用。
- [ ] 用户在请求期间修改输入时，旧运行完成后显示过期并保留结果。
- [ ] 新计划采用后沿用现有编辑序列、预览和审核失效规则。

## Verification evidence

- 领域/API/UI 测试覆盖确认、拒绝、部分成功、过期、迟到、重新解析和修订冲突。
- E3 分别使用至少一种真实生成模态补齐计划并入库；完整三模态链由票据 31 验收。
- 审核门禁测试证明补齐素材后旧预览与批准失效。

## Out of scope

- 把生成设为已有素材混剪的强制步骤。
- 静默路由或自动批准新增内容。
