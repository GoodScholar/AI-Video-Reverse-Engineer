# 01: 冻结五张验收矩阵与三条金标接缝

**What to build:** 把正式规格中的 A01–A18、R01–R40、C01–C35、G01–G27、X01–X18 固化为可持续更新的验收清单，并为三条跨引擎真实金标闭环准备统一的运行标识、输入清单、证据等级和结果记录方式。该清单只记录验收事实，不复制项目、素材、运行、审核或交付状态。

**Blocked by:** None (can start immediately)

**Status:** resolved

## Scope

- 冻结每个矩阵项的分母、允许状态、最低证据等级、零容忍错误和负责人可读说明。
- 定义三条真实金标闭环的统一记录格式：运行标识、项目与素材身份、输入/能力快照、真实媒体、人工结论和未闭合差异。
- 建立从每张后续票据到矩阵项的覆盖关系，并能发现遗漏、重复宣称和无证据“通过”。
- 只复用现有测试、运行记录、审核和交付证据；不建立新的产品业务状态。

## Source reuse prerequisite

- 核对正式规格、已接受架构决定、既有商用混剪规格、既有完整画布规格及 Anil 对齐审计中的验收口径。
- 记录证据清单本身为项目自有验收资产；不得把参考仓库 README、截图或测试文件存在当作通过证据。

## Acceptance criteria

- [x] 五张矩阵的 138 个固定编号均可追踪，且只允许“通过 / 失败 / 阻塞 / 明确不适用”。
- [x] “明确不适用”必须在冻结分母时记录理由、批准者和替代覆盖，运行受阻后不能追记缩小分母。
- [x] 三条金标闭环均有预先定义的真实输入、关键检查点、人工验收和失败/取消/恢复证据槽位。
- [x] 黑边、越界时码、错误素材身份、未披露外发和未经批准交付被标记为零容忍，不能被平均指标抵消。
- [x] 任一矩阵项缺少要求的 E1/E2/E3/E4 证据时不能标记通过。
- [x] 验收清单能输出当前差异，而不会修改内容项目或业务运行状态。

## Verification evidence

- 自动检查矩阵编号完整、唯一、状态合法、证据引用存在且没有循环自证。
- 用一项通过、一项失败、一项阻塞和一项明确不适用的受控样例证明状态规则。
- 人工复核三条金标记录模板足以还原素材身份、运行、版本、预览、审核和交付关系。

## Out of scope

- 实现任何引擎、Provider、平台导入或媒体算法。
- 用验收清单替代现有运行、项目、审核或交付数据库。

- 本轮检查：专用测试 `15 passed`；JSON 语法、Python `py_compile` 与只读校验通过；后端完整回归按原环境排除会直接访问 macOS Keychain 的单项后为 `1575 passed, 8 skipped, 1 deselected`，该单项在隔离的 null keyring 下为 `1 passed`。直接全跑在 86% 阻塞于系统 Keychain，并非断言失败；强制全局 null keyring 会令另一个明确要求安全后端的既有测试失败，故未伪报单一命令全绿。

- 二次复核加固：正式冻结日期与不适用 ID 基线由校验器常量守卫，后续不能只改合同 JSON 并回填日期。
- 最终复核加固：删除会形成第二份自填事实的证据封套口径。E3/E4 必须通过在代码中注册、且会直接查询既有业务真相源的受信验证器；票据 01 不注册占位验证器，因此虚构项目、运行、素材或审核 ID 无法把正式矩阵标记为通过。
