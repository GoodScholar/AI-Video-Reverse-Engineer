# 24: 分离画布业务节点与视图并建立执行 DAG

**What to build:** 在可持久化画布上分离 `CreativeNode` 与 `CanvasNodeView`，建立受控节点注册表、类型化端口、可执行依赖 DAG、非执行关系边和冻结 `CanvasExecution`；以“素材节点 → 处理节点 → 结果引用”贯通数据、API、界面和执行状态。

**Blocked by:** 02: 扩展共享运行契约并兼容迁移旧记录; 23: 对齐 Toonflow 画布主体并贯通持久化

**Status:** ready-for-agent

## Scope

- `CreativeNode` 保存身份、类型、端口、配置、引用和执行状态；视图对象只保存位置、尺寸、折叠等布局状态。
- 可执行边必须经过端口和类型校验并保持无环；注释、分组和纯视觉关系使用不参与执行的边。
- 执行冻结画布修订、依赖子图、输入顺序、配置和能力快照，历史运行不可变。
- 上游变化或切换输出使下游明确过期，只有用户再次执行才产生新运行。

## Source reuse prerequisite

- 阅读 Toonflow 固定提交的节点/边/状态源码、XYFlow 连接机制和现有画布数据结构。
- React Flow/XYFlow JSON 只作为视图适配，不作为唯一业务真相；记录迁移和兼容边界。

## Acceptance criteria

- [ ] 同一业务节点移动或折叠只改变视图状态，不改变内容、依赖或结果有效性。
- [ ] 合法连接可建立并持久化；非法端口、类型不匹配和执行环被阻止且保留证据。
- [ ] 注释、分组和纯视觉关系不进入执行排序。
- [ ] 执行只冻结所选依赖子图和有序输入，刷新后可查看相同快照和领域状态。
- [ ] 上游配置/引用/输出变化使下游过期但不自动运行或计费。
- [ ] 旧节点和边可读取或幂等迁移，不把视图 JSON 伪装成完整业务数据。

## Verification evidence

- 领域/API/UI 测试覆盖端口、类型、环、执行顺序、快照、布局独立和过期传播。
- 用实际素材节点和本地处理结果完成一次可查看执行。
- 并发保存和迁移失败测试证明原画布不被覆盖。

## Out of scope

- Provider 生成和混剪节点委托。
- 自主 Agent 循环和多人实时协作。
