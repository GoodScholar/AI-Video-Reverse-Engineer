# 07: 收口 Provider 路由、取消、恢复与支持声明

**What to build:** 在文本、图片和视频三个已贯通模态上统一显式路由、能力快照、取消、状态未知、迟到结果、失败恢复和支持声明，让用户看到实际使用的 Provider/模型，并确保没有保存路由策略时绝不静默切换。

**Blocked by:** 05: 交付统一图片生成纵向切片; 06: 交付统一视频生成纵向切片

**Status:** resolved

## Scope

- 只有用户保存过的显式路由策略可以自动选择或回退；记录每次实际选择、失败原因和回退决策。
- 统一三种模态的能力快照、状态未知、取消不支持、迟到结果、部分成功和计费未知展示。
- 未配置、未验证或能力未知的适配器不显示为已支持；连接测试与能力验证分开。
- 对已提交请求保持原 Provider/模型和能力快照，目录升级不回写历史运行。

## Source reuse prerequisite

- 先阅读现有 Provider 目录、连接测试、安全存储、配置修订和失败不回退实现。
- 优先沿用已验证的 CAS、披露和凭据边界；不引入第三方通用路由框架。

## Acceptance criteria

- [x] 无显式策略时，任一 Provider/模型失败都明确失败且不会换路由。
- [x] 有显式策略时，实际路由、回退原因、能力与配置版本完整持久化并展示。
- [x] 文本、图片、视频对取消支持/不支持、未知、迟到和计费未知使用一致公共语义并保留模态详情。
- [x] 连接成功不会自动把全部能力标成已验证，未知能力既不展示也不接受。
- [x] 目录或配置变更只影响新运行，历史运行仍引用原快照。
- [x] 所有凭据继续只在系统安全存储，日志和诊断可用但不泄密。

## Verification evidence

- 组合测试覆盖无策略失败、有策略回退、目录升级、迟到结果、取消差异和安全日志。
- UI 行为测试覆盖支持标记、未验证提示、实际路由和计费未知。
- 安全检查证明请求、项目备份和错误报告不含凭据。

## Out of scope

- 自动优化成本或质量的自主路由。
- 开通任何外部账号或购买额度。
