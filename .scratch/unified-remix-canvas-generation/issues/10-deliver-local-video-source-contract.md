# 10: 建立统一视频来源合同并贯通本地导入

**What to build:** 建立所有视频来源共用的识别、权利确认、元数据探测、内容取得、哈希、来源登记和项目素材入库合同，并先用本地文件贯通界面、API、素材预览和下游稳定引用。

**Blocked by:** 03: 统一项目素材结果安装与版本失效传播

**Status:** resolved

## Scope

- 来源合同保存来源类型、原始引用、适配器与版本、探测元数据、用户权利确认、内容哈希、验证时间和状态。
- 本地文件通过现有安全上传/受管文件链导入，不把任意路径作为长期业务主键。
- 入库后下游只使用项目素材身份，来源记录仅作追溯。
- 定义“可用 / 需要登录 / 暂时失效 / 不支持该链接”四类平台状态供后续适配器复用。

## Source reuse prerequisite

- 先阅读现有项目素材上传、媒体探测、哈希、来源记录、预览和安全路径处理源码。
- 直接复用成熟校验和素材安装能力，只增加来源合同缺失字段与交互。

## Acceptance criteria

- [x] 用户在导入前确认拥有使用权，取消确认不会复制或登记媒体。
- [x] 本地视频经过真实内容探测和哈希后形成不可变项目素材版本。
- [x] 来源记录包含适配器版本、元数据、哈希、确认时间和结果状态。
- [x] 文件重名、重复导入、损坏媒体、取消和导入中断有确定行为且不产生半成品素材。
- [x] 素材可预览并能作为混剪或转录输入，下游不再依赖原始本地路径。
- [x] 旧项目素材无需迁移来源字段也能继续读取，新增信息不伪造历史事实。

## Verification evidence

- 合同测试覆盖探测、哈希、幂等、重名、损坏、取消和回滚。
- E3 使用一份授权本地视频完成真实导入、来源登记、预览和下游读取。
- 安全检查证明任意路径、符号链接或未授权位置不能绕过受管导入。

## Out of scope

- 平台下载和账号会话。
- 在本票实现转录、高光或竖屏重构。

## Comments

### 2026-10-01 实施与证据

- 复用项目既有 `project_assets.py` 受管文件安装、原子状态保存、文件 SHA-256 校验、稳定素材身份、预览读取和引用边界；复用 `preproduction_api.py` 的真实 ffprobe/ffmpeg 内容探测。新增 `video_sources.py` 仅补齐可复用的四态来源合同（`available`、`requires_login`、`temporarily_unavailable`、`unsupported_link`）以及本地适配器记录；没有复制第三方源码或引入新许可证。
- 本地视频在写入受管素材区前必须获得显式使用权确认；取消不会发起上传，服务端缺少确认也不会登记素材。镜头结果也走同一服务端合同，并在安装事务中关联候选版本。导入记录仅保留安全文件名，不保存本地绝对路径；记录适配器及版本、探测尺寸/时长、确认时间、内容哈希、验证时间和可用状态。普通导入的相同内容哈希复用既有不可变项目素材版本；同名不同内容仍以不同稳定素材身份保存。
- E3 使用测试内由本机 FFmpeg 安全生成的两份真实 MP4：完成真实 ffprobe/解码探测、受管导入、来源登记、文件预览读取，以及批量混剪建议对两个稳定 `assetId` 的下游引用。定向证据为 `backend/tests/test_local_video_source_contract.py`；同一合同也覆盖确认取消、损坏媒体、保存中断回滚与重启恢复、受管暂存区限制、符号链接拒绝、旧无来源素材读取和重复导入。
- 本票尚未把正式矩阵 R17/R23–R25 标为“通过”：冻结验收要求受信 E2/E3 验证器和持久业务真相源证据，当前目录未注册该验证器。矩阵继续如实保持阻塞，不把自动化 FFmpeg 夹具冒充为正式人工或平台证据。
