# 05: 交付统一图片生成纵向切片

**What to build:** 在统一生成门面上接入一个图片适配器，让用户按真实能力完成文生图、单图或多图参考、可选图片编辑和多结果生成；每个成功结果都安装为项目素材，失败结果和历史运行保持可见，并可被下游画布或混剪引用。

**Blocked by:** 04: 交付统一文本生成纵向切片

**Status:** resolved

## Scope

- 为图片模态增加输入数量、参考类型、编辑、比例、分辨率和结果数量能力描述及服务端校验。
- 支持逐结果成功/失败、部分成功、取消、超时、重试和幂等。
- 复用已验证的图片服务与项目素材安装链，不重写模型调用或另建生成图库。
- 在界面上区分模型图片编辑、普通本地裁切/缩放和模型超分辨率。

## Source reuse prerequisite

- 先阅读现有图片生成、图片处理、素材入库和结果预览源码，并核对现有 Provider 的官方能力与真实探针。
- 记录适配器版本、直接复用范围和必要字段映射；未知或未验证能力不得推断为支持。

## Acceptance criteria

- [x] 文生图、单图参考和多图参考仅按适配器真实能力显示、校验和提交。
- [x] 图片编辑只在真实支持时开放，普通裁切/缩放不显示为模型编辑或超分。
- [x] 比例、分辨率、输入数量和结果数量在客户端提示并由服务端权威校验。
- [x] 多结果逐项保存成功/失败；取消或单项失败不删除已成功结果。
- [x] 成功结果以不可变项目素材版本入库，可预览、下载并被下游稳定引用。
- [x] 重试创建新运行且遵守幂等，不覆盖旧结果或重复安装素材。

## Verification evidence

- 协议假服务覆盖多输入、多结果、部分失败、取消、超时和能力拒绝。
- 使用真实图片文件验证素材入库、预览、下载和下游引用。
- 真正 Provider 的通过证据由票据 08 完成，本票只证明合同和本地数据链。

## Out of scope

- 视频生成和 ComfyUI Workflow。
- 自研图片模型或普通处理算法重写。

## Comments

### 2026-10-01 交付证据与边界

- 在票据 04 的 `GenerationService` 与 `GenerationAdapterRegistry` 上增加图片模态，没有另建运行时或图库。版本化能力合同固定覆盖参考类型与数量、图片编辑、模型超分、比例、分辨率、结果数量、取消和超时；未知字段、未知能力、未验证目录均在服务端拒绝。生产适配器版本为 `configured-image@image-protocol-v1`，且只解析 `capabilitySource=verified` 的目录项；现有用户填写能力保持 `user-configured`，不会因配置保存或连接成功冒充已验证支持。
- 源码复用核查：复用现有 `backend/app/image_generation.py` 的安全配置、密钥隔离和 Provider 调用，复用票据 03 的 `ProjectAssets.install_run_result` 不可变安装及下载路径。核对固定版本 Volcengine Ark Python SDK `629d09880eff23a283a2af1dd98b65294776e614` 的 `volcenginesdkarkruntime/resources/images/images.py` 与图片请求类型，许可证为 Apache-2.0；来源与许可保留在 `vendor/VolcengineArk/`。现有同步调用只返回一张图、无远端取消、也没有独立模型超分操作，因此生产适配器诚实收窄为 `maxResults=1`、`cancel=false`、`superResolution=false`；多结果、取消和模型超分合同由协议假适配器验证，真正 Provider 能力和探针证据仍由票据 08 负责。
- 图片运行逐结果保存 `completed/failed/cancelled/timed_out/reused`，顶层区分完成、部分成功、失败、取消和超时。取消、超时或单项失败保留已安装结果；重试创建新运行，只复用旧成功素材并重新请求失败项，同一重试幂等键返回同一运行。普通历史项目图片按其不可变文件身份稳定映射为 `<assetId>-v1`，与新结果的显式版本一致。
- 素材页通过“图片生成”按需打开；只列已验证模型，按目录显示/提交文生图、参考图、模型编辑和模型超分。界面明确说明普通本地裁切/缩放不是模型编辑或模型超分；结果历史提供预览与下载。响应丢失后仅在用户手动重试时复用原幂等键，不自动重提或切换 Provider。
- TDD 与验证：图片协议、能力拒绝、纯文生图、单/多参考、多结果、部分失败、取消、超时、重试/幂等、真实 PNG 入库/下载/下游引用及生产适配器边界共纳入 `backend/tests/test_generation_service_images.py`；前端能力筛选、纯文生图、参数提交、结果历史和响应未知幂等覆盖于 `frontend/src/ImageGenerationPanel.test.tsx`。最终暂存提交快照的定向后端回归 `75 passed`；前端图片设置、图片面板和前置工作台回归 `39 passed`；生产构建通过。正式完成矩阵未改为通过，真实 Provider 的 E3/E4 仍由票据 08 阻塞，以上证据不能扩展为真实商用 Provider 已验收。
