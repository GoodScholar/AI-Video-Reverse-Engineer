# 统一混剪、创作画布与生成协调规格

Status: ready-for-agent
Type: feature-spec
Decision date: 2026-09-30

## Problem Statement

当前产品已经拥有内容项目、项目素材、脚本候选、批量混剪、编辑序列、本地媒体处理、预览、审核和交付等能力，也已经存在画布、文本与图片生成、项目运行记录等相邻实现。但这些能力尚未形成经过统一协议和真实证据验收的三引擎闭环：脚本驱动混剪与长视频高光拆短仍可能形成不同的数据链；画布的业务节点、视图状态和生成执行边界仍需收口；文本、图片和视频生成尚缺少统一的能力目录、运行语义、结果入库和续创协议；平台视频导入、真实 Provider、取消恢复、版本失效和跨引擎交付也没有共同的冻结验收分母。

用户需要的不是多个彼此独立的工作流产品，而是在同一个内容项目中，从本地或平台素材、已确认脚本、画布节点或已有结果出发，统一完成素材导入、理解与规划、文本/图片/视频生成、混剪、预览、审核和批准导出。所有入口必须共享项目素材、运行、版本、编辑序列、审核和交付真相源；任何失败、取消、恢复、费用、外发和来源关系都必须可见、可追溯、可重试且不会静默改写用户成果。

本规格还要解决“局部功能存在即宣称完成”的验收问题。正式完成口径必须以五张冻结矩阵为分母，以三条真实跨引擎金标闭环为最高测试接缝。模拟服务、空画布、接口分别成功、测试文件存在或参考源码已读，均不能替代真实导入、真实生成、真实媒体、真实下游使用和人工视觉/内容验收。

## Solution

在现有内容项目与生产链上建立三个稳定但不强制独立部署的能力边界：

1. `RemixEngine` 统一承载“已确认脚本 + 多份项目素材”的商业自动混剪，以及“单条长视频转录 + 高光候选”的拆短流程。两个入口都生成唯一版本化协议 `RemixPlan`，再采用到现有编辑序列，沿用同一预览、审核和交付链。
2. `CanvasEngine` 拥有画布文档、业务节点、端口、依赖校验、执行顺序、版本、分支续创、撤销重做和冲突保护。画布节点可以独立于制作镜头；生成节点委托 `GenerationService`，混剪节点委托 `RemixEngine`，结果以稳定项目素材身份回到画布。
3. `GenerationService` 以统一门面、能力目录和适配器注册表协调文本、图片和视频生成。每次运行冻结 Provider、模型、能力、输入、披露、配置和调用来源；成功媒体立即入库为不可变项目素材版本，文本在明确采用后进入画布、脚本或 `RemixPlan`。
4. 三个边界共用一个持久运行基础设施和公共运行标识，公共层只负责排队、取消、恢复、幂等和日志；`RemixRun`、`CanvasExecution`、`GenerationRun` 继续保存各自的领域状态、输入快照和结果语义，不新建平行项目、素材、时间线、审核或交付系统。
5. 视频来源导入强制覆盖本地、YouTube、B站、抖音、小红书和快手。所有来源先完成权利确认、来源识别、元数据探测、下载或导入、内容哈希和来源登记，形成项目素材后才进入下游。
6. 创作画布以 Toonflow 固定提交 `d86cce6b689916ab73f75bc4c1f42a2a7424516c` 为唯一主体页面、节点、浮动工具和编辑器基准；在 MIT 许可和技术栈允许时优先直接复制主体结构，只为本项目 API、状态、项目素材和 React/XYFlow 接缝做必要适配。其他参考只补充 Toonflow 缺少的能力。
7. 长视频拆短以 Anil-matcha/AI-Youtube-Shorts-Generator 固定提交 `a57bb938ba50bf9654c2d5ca2af1295163454349` 的可审计本地链为强制对齐范围，复用或适配 `faster-whisper`、分块、高光、去重、Top N 与竖屏重构能力，同时修正时码缺陷并补齐商用主体跟踪、版本、恢复、审核和交付要求。MuAPI 不是验收前提。
8. 用五张冻结矩阵分别验收三引擎与共享真相源、`RemixEngine`、`CanvasEngine`、`GenerationService` 和跨引擎真实闭环。每项只允许“通过、失败、阻塞、明确不适用”；失败与阻塞都属于未闭合差异，只有冻结分母时才能以书面理由标记不适用。

## User Stories

1. 作为内容创作者，我希望在同一个内容项目中使用混剪、画布和生成能力，以便不维护多套项目和素材状态。
2. 作为内容创作者，我希望所有工作流引用同一项目素材身份，以便结果在不同入口间可追溯复用。
3. 作为内容创作者，我希望混剪、画布执行和生成运行共享统一的排队、取消、恢复和日志基础设施，以便状态语义一致。
4. 作为内容创作者，我希望每类运行仍显示其领域特有的输入、进度、结果和错误，以便理解发生了什么。
5. 作为内容创作者，我希望刷新、重启或网络中断后仍能恢复真实运行状态，以便不重复提交可能计费的请求。
6. 作为内容创作者，我希望重试创建新的运行身份并遵守幂等规则，以便保留历史且避免重复产物。
7. 作为内容创作者，我希望迟到结果被保存但不自动采用，以便旧请求不会覆盖新的选择。
8. 作为内容创作者，我希望影响成片的输入或版本变化使依赖预览和批准明确失效，以便不会交付未经审核的新内容。
9. 作为内容创作者，我希望历史运行、素材版本、计划、编辑序列和审核记录保持可读，以便追溯决策和恢复工作。
10. 作为内容创作者，我希望系统明确区分目标能力、已实现能力和已验证能力，以便不会被未完成的承诺误导。
11. 作为管理员，我希望 Provider 凭据只进入系统安全存储且不进入项目文件或日志，以便保护敏感信息。
12. 作为产品负责人，我希望每项源码复用、设计参考和自行实现都有固定来源、许可、适配范围和证据，以便商用审计。
13. 作为内部交付人员，我希望从已确认脚本和多份项目素材启动混剪，以便获得符合商业目标的可编辑初稿。
14. 作为内部交付人员，我希望看到哪些项目视频尚未建立可恢复的片段索引，以便补齐自动选片准备。
15. 作为内部交付人员，我希望启动、取消、重试并恢复片段索引，以便长素材处理中断后不从头开始。
16. 作为内部交付人员，我希望每个素材片段候选显示稳定素材身份、源入点、出点和预览，以便核实来源。
17. 作为内部交付人员，我希望源文件、切分算法或视觉模型变化后旧索引明确失效，以便不复用过期派生数据。
18. 作为内部交付人员，我希望用脚本段落、卖点或动作描述检索同一或不同素材中的多个候选镜头，以便快速选片。
19. 作为内部交付人员，我希望候选展示视觉相似度、质量、商品可见性、重复风险和选择依据，以便纠正系统判断。
20. 作为内部交付人员，我希望任何云端复排前都看到供应商、模型和实际外发范围，以便决定是否提交。
21. 作为内部交付人员，我希望云端复排失败时仍保留本地候选和明确错误，以便继续人工工作且不静默切换模型。
22. 作为内部交付人员，我希望一份已确认脚本生成一份版本化 `RemixPlan`，以便统一表达段落、来源、节拍和生成需求。
23. 作为内部交付人员，我希望 `RemixPlan` 按脚本段落给出来源区间、顺序、时长和选择理由，以便画面与旁白对应。
24. 作为内部交付人员，我希望切点优先尊重旁白词边界、脚本语义和素材连续性，再参考音乐节拍，以便内容可理解。
25. 作为内部交付人员，我希望系统限制同源重叠、相似构图和重复动作，以便作品具有视觉变化。
26. 作为内部交付人员，我希望同一批次的多个短视频变体共享素材但保持足够镜头差异，以便不是简单重复。
27. 作为内部交付人员，我希望替换某个候选时直接查看相同段落的备选项，以便快速微调。
28. 作为内部交付人员，我希望重新生成提案不会静默覆盖已有人工编辑，以便保护已完成工作。
29. 作为内部交付人员，我希望采用提案后得到普通的现有编辑序列，以便继续使用时间线、字幕、音频和人工精修。
30. 作为内部交付人员，我希望 `RemixPlan` 可以声明缺失的旁白、图片或视频，但不自动生成，以便先掌握成本和外发。
31. 作为内部交付人员，我希望确认 Provider、外发内容和可能费用后再生成缺失素材，以便控制数据和预算。
32. 作为内部交付人员，我希望生成素材入库后重新解析原 `RemixPlan`，以便来源和版本关系保持一致。
33. 作为内部交付人员，我希望每个镜头边界、转场、音频淡化、裁剪轨迹、字幕和花字都属于可版本化编辑输入，以便预览与导出一致。
34. 作为内部交付人员，我希望包装模板统一管理转场、花字、字幕、安全区和行动引导，以便批量作品保持品牌一致。
35. 作为内部交付人员，我希望关闭、替换或编辑单个包装效果时只使相关版本失效，以便不必重做选片。
36. 作为内部交付人员，我希望音乐节拍只提供剪辑建议而不覆盖对白、脚本和镜头语义，以便避免失真。
37. 作为内容创作者，我希望从本地文件导入有权使用的视频，以便进入统一项目素材链。
38. 作为内容创作者，我希望从 YouTube 公开页面或正常分享链接导入有权使用的视频，以便进行后续创作。
39. 作为内容创作者，我希望从 B站公开页面或正常分享链接导入有权使用的视频，以便进行后续创作。
40. 作为内容创作者，我希望从抖音公开页面或正常分享链接导入有权使用的视频，以便进行后续创作。
41. 作为内容创作者，我希望从小红书公开页面或正常分享链接导入有权使用的视频，以便进行后续创作。
42. 作为内容创作者，我希望从快手公开页面或正常分享链接导入有权使用的视频，以便进行后续创作。
43. 作为内容创作者，我希望在需要时显式提供合法账号会话并由安全存储管理，以便访问我有权使用的内容。
44. 作为内容创作者，我希望系统不自动输入密码、扫码登录或绕过 DRM、会员和私密访问控制，以便合规使用来源。
45. 作为内容创作者，我希望每次导入保存来源平台、原始地址、适配器版本、探测元数据、内容哈希和验证时间，以便审计。
46. 作为内容创作者，我希望平台适配器明确显示可用、需要登录、暂时失效或不支持该链接，以便理解失败原因。
47. 作为内容创作者，我希望导入完成后下游只依赖项目素材身份而不依赖外部 URL，以便来源变化不破坏项目。
48. 作为内容创作者，我希望对单条长视频进行 `faster-whisper` 本地转录并保留词级和段级全片绝对时间，以便驱动高光选段。
49. 作为内容创作者，我希望超过 30 分钟的视频按保存的版本化策略分块并重叠处理，以便可靠分析长内容。
50. 作为内容创作者，我希望块内相对时码在进入领域数据前转换并校验为全片绝对时码，以便第二、第三块不会错位。
51. 作为内容创作者，我希望每个高光候选保存稳定身份、全片起止、评分维度、总分、理由、转录证据、模型和提示版本，以便审计。
52. 作为内容创作者，我希望模型输出无效时明确重试或失败，以便不会产生看似成功的空候选。
53. 作为内容创作者，我希望候选按版本化策略去重并确定性排序，以便相同输入得到可解释结果。
54. 作为内容创作者，我希望默认去重兼容候选自身时长 50% 重叠抑制并覆盖对称重叠场景，以便避免非对称遗漏。
55. 作为内容创作者，我希望请求 N 条短视频时看到请求数、候选数、成功数、失败数及每条来源，以便掌握批量结果。
56. 作为内容创作者，我希望单条裁切失败不会删除已成功结果，并可从检查点重试，以便保留部分成果。

66. 作为产品负责人，我希望查看镜头保留率、人工替换率、高光召回、采用率、主体安全区和预览一致性，以便判断商用质量。

## Implementation Decisions

### 1. 能力边界与共享真相源

- `RemixEngine`、`CanvasEngine`、`GenerationService` 是稳定的领域边界，但不要求拆成三个部署单元；按现有 React + TypeScript、Python + FastAPI 和本地媒体基础设施做最少必要适配。
- 三个边界共享内容项目、项目素材、运行记录、版本、编辑序列、预览、审核和交付真相源，不建立平行项目、素材库、任务中心、时间线、批准或交付系统。
- 公共持久运行层只拥有排队、状态持久化、取消请求、恢复、幂等键、日志和公共运行标识；`RemixRun`、`CanvasExecution`、`GenerationRun` 保存领域输入快照、状态和结果语义，不压成无语义通用 JSON。
- 图片、视频和音频生成成功后立即形成不可变、可追溯的项目素材版本；文本结果先作为不可变生成输出保存，只有明确采用后才成为画布文本、脚本版本或 `RemixPlan` 输入。
- 影响成片的来源素材、脚本、生成结果、当前输出选择、`RemixPlan`、编辑序列、裁剪轨迹、包装模板、字幕、音频、模型或配置版本变化时，依赖预览和批准明确失效，历史版本继续保留。

### 2. `RemixEngine` 与唯一 `RemixPlan`

- `RemixEngine` 只有两个入口：脚本驱动入口接收已确认脚本与多份项目素材；高光驱动入口接收一条已入库长视频的转录与高光候选。两者只能输出同一版本化 `RemixPlan` 协议。
- “混剪提案”是用户可查看、保存和采用的候选 `RemixPlan`。采用时通过稳定来源关系物化到现有编辑序列；计划不是第二套时间线，也不直接获得审核或交付效力。
- `RemixPlan` 表达来源素材与区间、内容节拍、顺序、持续时间、转场边界、音频淡化、裁剪轨迹、字幕和包装引用、选择理由、缺失生成需求及其版本，不暴露任意 Provider JSON。
- 脚本驱动路径承接既有商用自动混剪的素材索引、视觉召回、受披露约束的云端复排、候选解释、跨变体差异、节拍建议、包装模板、质检、审核和交付要求。
- 混剪计划可以声明缺失旁白、图片或视频；只有用户确认 Provider、外发内容和可能费用后才委托 `GenerationService`。成功结果入库后重新解析计划，不把生成设为已有素材混剪的强制步骤。
- `RemixEngine` 协调分析、候选、计划、采用和通过现有 Timeline/FFmpeg 形成预览；不拥有独立渲染器、审核系统或交付系统。
- 自动质检只针对冻结预览生成带时间范围和证据的报告；工程错误可阻止交付，但不会产生人工审核通过。

### 3. Anil 本地长视频拆短切片

- 固定参考 Anil-matcha/AI-Youtube-Shorts-Generator 提交 `a57bb938ba50bf9654c2d5ca2af1295163454349`，根许可为 MIT。强制对齐范围只包含可审计的本地转录、分块、高光、去重、Top N 和竖屏重构；MuAPI 仅可作为未来可选适配器，其不可见服务端算法不宣称复用。
- 深度复制高光模块前必须核清其声明的 ViralVadoo 来源和授权链；来源未确认不阻止按同等行为自行实现，但阻止复制来源不清的代码。
- 本切片强制使用 `faster-whisper`，保存词级与段级全片绝对时间；`whisper.cpp` 可继续服务其他场景，但不能作为本切片对齐证据。
- 默认在视频超过 30 分钟时使用 20 分钟块和 60 秒重叠，实际策略和版本随运行保存。传给模型时可以使用块内相对时间，进入领域数据前必须转换并验证为全片绝对时间。
- 高光候选保存稳定身份、全片起止时间、评分维度、总分、选择理由、转录证据、模型与提示版本及来源分块；无效模型输出明确重试或失败。
- 去重策略版本化；默认兼容“候选与已保留项的重叠超过候选自身时长 50% 时抑制低分项”，并补充对称重叠、边界和确定性排序行为。
- 正式竖屏主体重构覆盖人物、人脸、商品等主体、跨帧身份、场景切换后重选、版本化裁剪轨迹、主体框、置信度和人工关键帧覆盖；Haar 最大脸 + EMA 只能作为明确记录的最低回退。
- 请求 N 条时保存请求数、候选数、成功数、失败数和每条结果的稳定身份与来源。单条失败保留成功结果并可从检查点重试；只有 N 条均成功才是完整成功。

### 4. 视频来源导入

- 强制来源为本地、YouTube、B站、抖音、小红书和快手。所有来源统一执行来源识别、元数据探测、权利确认、下载或导入、内容哈希和来源登记，随后形成项目素材。
- 支持公开页面、正常分享链接，以及用户显式提供合法账号会话后可访问的内容；不自动输入密码、扫码登录，不绕过 DRM、会员权限或私密访问控制。
- Cookie、令牌或其他会话只进入系统安全存储，不写入项目文件、日志、导出包或错误文本。
- YouTube、B站、抖音和小红书可优先使用固定版本、许可证已核查的 yt-dlp 适配器；快手使用独立 `KuaishouSourceAdapter` 或另一个固定版本、许可和真实下载均已验证的实现。
- 每个平台保存适配器版本、最近真实验证时间和“可用 / 需要登录 / 暂时失效 / 不支持该链接”状态。平台支持声明绑定固定依赖版本和金标 URL 集，不以一次偶然成功代表长期支持。
- 下游只接收项目素材稳定身份；外部 URL 仅保留为来源证据，不能成为混剪、画布或时间线的运行依赖。

### 5. `GenerationService`

- 采用统一门面、能力目录和适配器注册表；已验证的文本和图片实现满足统一契约后保留为适配器，不无故重写，视频通过新增适配器接入。
- 生成请求由公共信封和模态专属参数组成。公共部分保存模态、Provider、模型、配置版本、输入快照、披露、幂等键和调用来源；专属参数由能力目录校验，不退化为只有 prompt 的最低公共协议。
- 每次运行冻结 Provider、模型、能力、输入、配置、披露和路由策略。只有用户保存显式路由策略时允许自动选择或回退，并记录实际 Provider 与模型；否则失败即明确失败。
- 文本范围包含普通流式结果、稳定文本/图片引用、可选结构化 Schema、输出预算、取消、超时、结果不完整和计费未知；采用动作独立于生成完成。
- 图片范围包含文生图、单图或多图参考、模型允许时的图片编辑、多结果、比例和分辨率校验、逐结果失败、取消及项目素材入库。普通本地裁切和缩放不冒充模型编辑或超分。
- 视频范围由模型能力声明决定，覆盖适用的文生视频、图生视频、首帧/尾帧、多参考、时长、比例、分辨率和音频组合。异步运行持久保存远端任务身份，重启后可查询，取消语义真实，结果入库并可续创。
- 每个适配器提供版本化、经官方资料或真实探针确认的能力描述；未知能力不展示也不接受。配置已保存或连接成功不等于能力已验证。
- 每种模态至少一个真实 Provider 完成适用能力的提交、状态读取或流式响应、取消、失败恢复、结果入库和下游使用；所有对外显示支持的 Provider 还须分别通过真实冒烟。
- `ComfyUIAdapter` 是正式扩展点但不是首个整体 100% 的前提。若界面宣称支持，则 Workflow ID、输入映射、队列、WebSocket 或轮询、取消和结果入库必须独立真实验收。
- 现有 TTS、音乐和字幕继续属于既有生产能力；在没有新的明确需求前，不为了统一接口而重构。

### 6. `CanvasEngine` 与 Toonflow 主体界面

- `CanvasEngine` 拥有画布文档、节点和端口、依赖校验、执行顺序、撤销重做、版本与分支续创；不拥有模型供应商、凭据、生成文件、混剪算法或项目素材真相源。
- `CreativeNode` 保存稳定身份、类型、端口、配置、引用和执行状态；`CanvasNodeView` 只保存位置、尺寸、折叠及其他视图状态。节点通过受控注册表扩展，React Flow/XYFlow JSON 不是唯一业务数据。
- 可执行数据依赖是经过端口和类型校验的有向无环图；注释、分组和纯视觉关系使用不参与执行的关系边。发现执行环时阻止执行并保留证据，不静默删边。
- 每次 `CanvasExecution` 冻结画布修订、依赖子图、输入顺序、配置和能力快照；历史运行不可变。节点只保存当前选中输出的稳定引用，切换输出或上游变化使下游过期，只有用户再次执行才产生新运行。
- 画布以 Toonflow 固定提交 `d86cce6b689916ab73f75bc4c1f42a2a7424516c` 为唯一主体页面结构、节点外观、浮动工具和编辑器基准。实现前读取对应页面、组件、状态和交互源码；许可和技术栈允许时直接复制主体结构并保留 MIT 来源。
- 画布适用独立设计例外：采用 Toonflow 的全幅画布、顶部区域、添加入口、节点、就近浮动工具、画布控制和按需属性编辑，不为旧站点侧栏、表单卡片、设计变量或组件外观删减主体交互。
- basketikun/infinite-canvas 固定提交 `dab19adc0847e32e39b7fc8ff90cb392561fb826`（MIT）补充媒体节点、生成记录、引用、插件、剪贴板和续创；XYFlow 提供底层画布交互。其他参考仅补充经源码和许可核查后确认缺失的能力，不改写主体骨架。
- 生成节点只调用 `GenerationService`，混剪节点只调用 `RemixEngine`；成功结果以项目素材稳定身份返回画布。镜头是可选关联，任何节点都不因画布使用而强制归属 Shot。
- 首期 `AgentAction` 只允许使用与人工相同的领域命令生成可查看的变更提案，经用户确认后应用；操作可审计、可撤销，不直接改数据库、越权调用 Provider 或自动批准交付。
- 自主长期循环和多人实时协作不在首期；仍须处理单用户多窗口版本冲突、草稿恢复和并发保存保护。Yjs 只保留为后续候选。

### 7. 兼容、迁移、安全与源码复用

- 旧画布文档、混剪提案、编辑序列、项目素材和运行记录必须继续读取，或通过幂等迁移升级；迁移前保留可恢复备份，失败不覆盖原数据。
- 现有文本和图片生成结果不得因统一门面而重新生成、改变稳定身份或丢失来源；旧运行可以补充兼容元数据，但不伪造当时不存在的能力快照。
- 每项源码复用记录上游仓库、固定提交、源文件、许可证、复制或移植范围、本项目落点、必要改动和测试证据；自行实现与仅参考设计的部分分开标注。
- 技术栈兼容且许可允许时优先复制成熟主体能力，只写项目数据、API、状态和运行边界的必要适配；无法复制时记录许可、技术栈、功能或适配成本的具体原因。
- 外部模型运行时、平台内容、模型权重、字体、音乐和模板的许可或服务条款分别核查；开源仓库许可不覆盖 Provider 条款、媒体权利或模型权重。
- 未披露外发、错误素材身份、越界时码、9:16 黑边和未经批准交付是零容忍工程错误。

## Testing Decisions

### 1. 测试原则与最高接缝

- 最高测试接缝固定为三条跨引擎真实金标闭环，测试用户可观察行为、稳定身份、版本关系、真实媒体和审核门禁，不断言内部函数调用顺序。
- 第一条闭环：本地或平台视频入库后完成转录、高光、竖屏重构、`RemixPlan`、N 条变体、预览、人工审核和批准导出。
- 第二条闭环：已确认脚本和多份项目素材形成混剪提案；缺失素材在用户确认 Provider、外发和费用后由 `GenerationService` 生成并入库；重新解析计划后形成多变体并完成预览、审核和交付。
- 第三条闭环：画布文本节点依次驱动真实图片和真实视频生成；结果成为项目素材，用于下游续创或混剪，最终进入预览和人工审核。
- 三条闭环以下只保留五张矩阵需要的领域/API 合同接缝，以及现有媒体渲染、任务恢复、版本冲突、审核和交付接缝。优先复用现有接缝，不为测试新建平行项目、素材、运行或渲染系统。
- 自动化测试证明确定性行为、协议、状态机、幂等、异常和版本失效；真实 Provider、真实平台、真实媒体构图与内容质量由真实运行记录和人工验收证明。模拟 Provider 不能替代真实生成或真实费用/取消语义。
- 每一矩阵项只允许“通过 / 失败 / 阻塞 / 明确不适用”。失败和阻塞都计入分母并属于未闭合差异；“明确不适用”只能在冻结分母时写明理由、批准者和替代覆盖，不能在实现受阻后用于缩小范围。
- 每项证据按风险组合使用：固定源码与许可证映射、自动化行为测试、真实平台/Provider/媒体运行记录，以及需要视觉或内容判断时的人工验收。文件存在、旧日志、模拟结果或接口 2xx 不能单独标记通过。

### 2. 矩阵一：三引擎架构与共享真相源

该矩阵逐项分母固定如下：

1. A01：`RemixEngine`、`CanvasEngine`、`GenerationService` 的职责边界与禁止拥有对象有可执行合同和审计证据。
2. A02：三个边界共享同一内容项目身份，没有平行项目系统。
3. A03：三个边界共享同一项目素材身份和不可变素材版本，没有平行素材库。
4. A04：两个混剪入口共享唯一 `RemixPlan`，没有第二套计划协议。
5. A05：采用 `RemixPlan` 只物化为现有编辑序列，没有第二套时间线。
6. A06：预览、审核、批准和交付复用现有真相源，没有自动批准旁路。
7. A07：三个领域运行共享一个持久运行基础设施和公共运行标识。
8. A08：`RemixRun`、`CanvasExecution`、`GenerationRun` 保留各自领域状态、输入快照和结果语义。
9. A09：排队、取消、恢复、幂等和日志在公共层具有一致可观察语义。
10. A10：重启、刷新和网络中断不会重复产生计费请求，未知状态可见。
11. A11：迟到结果保留但不自动采用，旧运行不能覆盖新输入或新选择。
12. A12：媒体生成结果立即形成不可变项目素材版本，文本结果在采用前保持运行输出。
13. A13：来源、脚本、生成结果、选中输出、计划、编辑序列、裁剪、包装、字幕、音频、模型或配置变化能传播过期和审核失效。
14. A14：旧画布、提案、编辑序列、素材和运行可读取或经幂等迁移升级，失败不覆盖原数据。
15. A15：凭据和合法会话只在系统安全存储，项目文件、日志和导出物不含秘密。
16. A16：只有显式保存的路由策略允许自动 Provider 选择或回退，实际选择全程记录。
17. A17：源码复用、设计参考和自行实现均有固定来源、许可、适配与测试证据。
18. A18：UI、文档和运行状态区分“目标 / 已实现 / 已验证”，未验证能力不显示为已支持。

A01–A18 至少需要领域/API 合同测试和持久化状态证据；A02–A14 还需在三条金标闭环中验证稳定身份和版本传播；A15–A17 需要安全/许可审计记录；A18 需要界面与文档人工核对。

### 3. 矩阵二：`RemixEngine`

该矩阵同时承接既有商用自动混剪完整范围与 Anil 本地长视频拆短范围，逐项分母固定如下：

### 5. 矩阵四：`GenerationService`

该矩阵逐项分母固定如下：

9. G09：图片文生图真实运行完成入库和下游使用。
10. G10：图片单图/多图参考按模型能力完成真实运行。
11. G11：图片编辑只在真实支持的模型上开放，普通裁切/缩放不冒充模型编辑或超分。
12. G12：图片多结果、比例、分辨率、逐结果失败、取消和部分成功语义完整。
13. G13：视频文生视频在所选真实 Provider 支持时完成提交、查询、结果入库和下游使用。

17. G17：异步远端任务身份持久化，服务重启后能继续查询而不重复提交。

### 6. 矩阵五：跨引擎真实闭环

该矩阵逐项分母固定如下：

1. X01：本地视频真实导入后形成带哈希与来源记录的项目素材。
2. X02：至少一个平台视频真实导入后形成带哈希与来源记录的项目素材；六类来源仍分别在 R17–R22 验收。
3. X03：超过 30 分钟的授权样本完成全片绝对时码转录、分块、高光和 Top N。
4. X04：选中高光完成主体感知 9:16 重构、无黑边、音画同步和人工构图检查。
5. X05：高光入口生成唯一 `RemixPlan` 并物化 N 条变体，部分失败状态真实。
6. X06：N 条变体进入现有预览、质检、人工审核和批准导出链。
7. X07：已确认脚本和多份项目素材生成可解释 `RemixPlan`。
8. X08：计划声明的缺失文本/图片/视频在用户确认 Provider、外发和费用后提交真实生成。
9. X09：生成结果以稳定项目素材身份入库，计划重新解析且来源、版本和过期传播正确。
10. X10：脚本驱动计划形成多个差异化变体并完成预览、人工审核和交付。
11. X11：画布文本节点通过真实文本 Provider 产生可采用输出。
12. X12：画布使用文本和稳定引用通过真实图片 Provider 生成并入库项目素材。
13. X13：画布使用文本、图片或首尾帧通过真实视频 Provider 生成并入库项目素材。
14. X14：生成媒体在画布下游继续创作或交给 `RemixEngine`，不通过临时文件旁路。
15. X15：最终媒体进入现有预览和人工审核，影响输入变化能使批准失效。
16. X16：三条闭环的取消、失败、状态未知、迟到结果、重试和重启恢复至少各有适用证据。
17. X17：三条闭环全程使用同一项目、素材、运行、版本、编辑序列、审核和交付真相源。
18. X18：三条闭环均保存可复现运行标识、输入/能力快照、真实媒体、人工结论和未闭合差异。

X01–X06 构成第一条真实长视频拆短金标；X07–X10 构成第二条真实商业混剪金标；X11–X15 构成第三条真实画布生成金标；X16–X18 是三条闭环共同门槛。API 各自成功、模拟 Provider、合成媒体或静态截图均不能代替本矩阵。

### 7. 金标样本、证据等级与完成声明

- 本地、YouTube、B站、抖音、小红书和快手各至少一份授权样本完成真实导入、哈希、来源登记和素材预览；其中至少一份超过 30 分钟并继续完成完整高光拆短链，不要求六个平台样本都重复昂贵后处理。
- 长视频拆短另准备至少六份已授权且人工标注的视频，覆盖 30 分钟以内单人、超过 30 分钟多分块、多人交替、商品或非脸主体、快速运动与场景切换、无语音或无有效高光。
- 证据等级按能力风险组合：E1 为固定源码、提交、源文件和许可证映射；E2 为确定性自动化行为测试；E3 为真实平台、真实 Provider 或真实媒体运行记录；E4 为人工视觉、内容、权利或交付验收。每个矩阵项在冻结时标注最低证据组合。
- 黑边、越界时码、错误素材身份、未披露外发和未经批准交付为零容忍；出现任一项，对应矩阵项直接为失败，不能用整体平均指标抵消。
- “100% 对齐”是全部冻结门槛通过，不表示概率模型永远判断正确。可以声明某张矩阵或冻结切片达到 100%，但必须同时写明分母和证据，不能外推为整个产品完成。
- 只有 A01–A18、R01–R40、C01–C35、G01–G27、X01–X18 全部通过，所有阻塞和失败清零，三条真实闭环完成，且所有已宣称源码复用可追溯，才可声明“本次约定范围整体 100% 对齐”。
- 缺少真实 Provider 凭据、合法平台样本、人工视觉验收或上游授权链时，对应项保持“阻塞”并继续留在分母；不得因外部条件未具备而删除验收项。

## Out of Scope

- 为三个能力边界建立独立部署、独立项目、独立素材、独立时间线、独立渲染器、独立审核或独立交付系统。
- 把 `RemixPlan`、画布文档或生成运行改造成第二套编辑序列。
- 用 MuAPI 不可见服务端能力作为首期强制依赖，或宣称其服务端源码已复用。
- 自动输入平台密码、代替用户扫码登录、绕过 DRM、会员、私密访问控制或素材使用授权。
- 在没有显式用户策略时自动切换 Provider、模型或付费路径。
- 首期重构现有 TTS、音乐和字幕，只为追求统一接口而改写已验证生产链。
- 首期把 ComfyUI 设为强制依赖；未宣称支持时不要求其进入整体 100% 分母。
- 首期自主长期 Agent 循环、自动批准、自动交付、自动发布或越权直接修改数据库。
- 首期多人实时协作、Yjs/CRDT 同步、SaaS 账户权限、云同步、费用结算或跨项目共享素材库。
- 把 AI 无限画布收窄为镜头关系图，或要求所有节点必须归属制作镜头。
- 为保持旧站点视觉而改变或删减 Toonflow 主体页面结构和交互。
- 实现通用专业非线性编辑器、任意第三方插件市场、任意 shader 或无限效果参数。
- 用普通缩放冒充模型超分、用本地裁切冒充模型编辑、用连接测试冒充模型能力验证。
- 把源码逐行复制率、仓库数量、局部测试、空画布截图或接口返回成功当作整体对齐。
- 本规格不拆分实施任务票，也不开始任何代码实现。
