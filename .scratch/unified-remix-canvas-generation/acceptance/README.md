# 五张验收矩阵与三条金标记录

本目录是票据 01 冻结的项目自有验收资产，只记录验收事实和证据引用。它不拥有、复制或修改内容项目、项目素材、运行、编辑序列、审核或交付状态；这些状态仍由既有业务真相源拥有。

## 文件

- `matrix-contract.json`：A01–A18、R01–R40、C01–C35、G01–G27、X01–X18 共 138 个固定编号、四种合法状态、E1–E4 最低证据组合和五类零容忍错误。
- `ticket-coverage.json`：票据 02–33 到矩阵项的唯一主责、支持和最终审计关系。支持关系可以重叠，主责关系不能重复或遗漏。
- `evidence-catalog.json`：验收证据的唯一引用目录。初始为空；票据 01 不把旧测试、文件存在、模拟服务或模板本身冒充通过证据。
- `golden-records.json`：GL01 长视频拆短、GL02 脚本混剪与缺失生成、GL03 画布生成三条最高接缝的只读记录模板。
- `validate_acceptance.py`：只读校验与差异输出入口。
- `test_acceptance_contract.py`、`fixtures/`：状态规则与校验器的受控自动化证据，不属于任何正式矩阵项的通过证据。

## 状态与证据规则

合法状态只有“通过 / 失败 / 阻塞 / 明确不适用”。

- “通过”必须引用存在的证据文件，且证据等级覆盖该项冻结的最低 E1/E2/E3/E4 组合；存在任一适用零容忍错误时不得通过。
- “失败”必须记录未闭合差异。
- “阻塞”必须同时记录阻碍与未闭合差异，并继续保留在分母中。
- “明确不适用”只能依据冻结时决定，必须记录决定时间、理由、批准者和替代覆盖；正式合同的冻结日期与不适用 ID 基线同时由校验器常量守卫，普通状态更新不能追记缩小分母。
- 任一零容忍错误一经记录，对应项必须标记“失败”，不能以“阻塞”或“明确不适用”保留。
- 验收定义、规格、票据状态或清单本身不能作为通过证据。证据文件必须位于本验收目录内，目录项再引用既有真相源中的稳定身份或脱敏产物。

E1 是固定源码/提交/源文件/许可证映射，E2 是确定性自动化行为测试，E3 是真实平台/Provider/媒体运行记录，E4 是人工视觉、内容、权利或交付验收。每条正式证据必须使用对应等级的限定类型、携带该等级的真相源字段，并命中校验器代码中注册的受信验证器；仅有文件、自填等级、命令或退出码不能成立。模拟服务只可提供 E2。

正式矩阵的受信验证器注册表在票据 01 中保持为空：E1/E2 后续验证器必须读取固定 Git 来源或实际测试执行记录；E3/E4 还必须登记 `project://`、`asset://`、`run://`、`review://`、`delivery://`、`source://` 或 `provider-job://` 引用，并由验证器直接查询既有业务真相源。静态文件、封套、哈希、自填命令/退出码或自填 ID 只能作为附件，不能自行形成证据。`validate-sample` 的四状态夹具有单独且严格限定的验证器，只能核对 `sample-e2`，不能被正式 `validate` 使用。

## 使用

在项目根目录运行：

```bash
backend/.venv/bin/python .scratch/unified-remix-canvas-generation/acceptance/validate_acceptance.py validate
backend/.venv/bin/python .scratch/unified-remix-canvas-generation/acceptance/validate_acceptance.py gaps
backend/.venv/bin/python -m pytest -q .scratch/unified-remix-canvas-generation/acceptance/test_acceptance_contract.py
```

`validate` 检查 138 个编号完整且唯一、状态合法、最低证据覆盖、证据文件存在、没有循环自证、票据主责不重复、三条金标模板完整。`gaps` 只读取上述文件并输出所有当前未闭合项，不写业务数据或验收文件。

后续票据更新状态时，先把脱敏、可复现的证据登记进 `evidence-catalog.json`，并实现、注册读取实际来源的验证器。验证通过后再在 `matrix-contract.json` 的 `statusPolicy.overrides` 中更新对应项；不得删除默认分母，也不得用完成票据、旧日志或静态截图单独替代能力证据。金标执行时复制对应记录模板为执行记录或填充其引用槽位，但业务状态只保存稳定 ID，不复制业务对象快照。

## 来源复用记录

本资产根据统一规格、ADR 0013、既有商用混剪规格、完整画布规格和 Anil 固定版本对齐审计整理。验收清单、校验器和记录格式均为项目自有实现，没有复制参考仓库源码；Anil、Toonflow 等上游代码与许可证的实际复用仍由其对应后续票据提供 E1 证据。
