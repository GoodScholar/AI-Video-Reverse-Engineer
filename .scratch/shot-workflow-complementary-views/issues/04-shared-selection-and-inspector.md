# 04: 打通列表、画布与检查器的共享选择

**What to build:** 让列表、关系图和检查器围绕同一个当前对象协同工作。用户从任一视图选择镜头、场景或流程节点，其他视图都能定位并表达相同上下文；悬停和键盘焦点保持瞬时，不污染选择、保存或撤销历史。

**Blocked by:** 03 / 提供可切换的只读镜头关系图

**Status:** resolved

- [x] 列表选择镜头会显露、定位并高亮对应 ShotNode，画布选择 ShotNode 会把列表滚动到对应卡片，检查器始终打开同一制作镜头。
- [x] 选择 ProcessNode 时，检查器显示流程节点，列表只弱高亮其所属镜头，不把该镜头加入批量选择。
- [x] 选择 Scene 时列表定位到对应分段，检查器显示场景摘要；折叠场景中的目标可被显式揭示和定位。
- [x] 支持 `Cmd/Ctrl+点击` 增减镜头选择、列表 `Shift+点击` 范围选择和项目/场景视图中的镜头框选，多选检查器只显示兼容操作。
- [x] 悬停和键盘焦点使用可区分的视觉反馈，不滚动、不居中、不持久化，也不产生撤销记录。
- [x] 选择通过统一命令和 store 单向传播，不形成列表与画布互相触发的回调循环；测试覆盖双向定位、多选和项目切换清理。

## Answer

- 统一 store 现在维护镜头、场景与带所属镜头身份的流程节点选择，并用带来源和序号的定位请求驱动列表与画布单向响应；项目切换会清理选择及瞬时状态。
- 列表与画布支持镜头双向定位、场景摘要、流程节点检查器、所属镜头弱上下文，以及 `Cmd/Ctrl` 增减、`Shift` 范围和画布框选；多选检查器只显示兼容摘要。
- 悬停和键盘焦点采用节点级窄订阅，只更新受影响对象，不写入工作区快照、未保存状态或撤销历史。
