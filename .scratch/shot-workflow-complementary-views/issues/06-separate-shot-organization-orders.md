# 06: 保持四种顺序分离地组织镜头

**What to build:** 让用户能从列表和画布组织镜头，同时明确区分镜头管理顺序、工作流依赖、画布位置和时间线位置。每种操作只修改其声明的领域含义，并可作为一个事务撤销。

**Blocked by:** 04 / 打通列表、画布与检查器的共享选择；05 / 独立保存画布布局

**Status:** resolved

- [x] 在列表重排镜头只更新 Shot.rank，不移动画布节点、不修改依赖，也不移动现有时间线片段。
- [x] 把镜头拖入 Scene 框只更新 Scene 归属并保留镜头、候选和素材引用；删除 Scene 前必须让用户选择迁移镜头或确认删除影响。
- [x] 从列表拖入画布只定位或重新摆放已有规范 ShotNode，不创建重复镜头。
- [x] 从画布创建镜头时，以一个原子命令创建 Shot、唯一 ShotNode 和初始布局；任一步失败都不留下部分对象。
- [x] 镜头组织命令支持领域级撤销/重做，批量操作作为一个事务恢复；运行副作用和已经生成的媒体文件不被声称为可撤销。
- [x] 自动化测试分别断言管理顺序、依赖、布局和时间线位置不会因其他三类操作发生隐式变化。

## Answer

- 列表重排、跨场景迁移、场景删除、复制与画布创建统一进入组织领域历史；撤销/重做只恢复归属、排名及命令实际控制的布局节点，不覆盖之后的镜头内容或独立布局修改。
- 列表和场景支持标准 HTML 拖放；列表投放画布只移动已有规范 ShotNode，画布新建则一次创建 Shot、唯一 ShotNode 和初始位置。
- 工作区保存可同时提交内容和项目布局，并通过可恢复事务日志、文件与目录同步保证中断后回滚到完整旧状态；失败不会留下部分镜头或孤立布局。
- 未保存内容期间的项目布局进入待提交队列，内容恢复干净后独立补存；工作区保存期间锁定布局写入，草稿也会保存并恢复项目布局。
- 删除非空场景必须明确选择迁移镜头或删除镜头；运行中的镜头不能随场景删除，已生成媒体文件不属于撤销范围。
