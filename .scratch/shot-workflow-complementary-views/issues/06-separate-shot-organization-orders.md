# 06: 保持四种顺序分离地组织镜头

**What to build:** 让用户能从列表和画布组织镜头，同时明确区分镜头管理顺序、工作流依赖、画布位置和时间线位置。每种操作只修改其声明的领域含义，并可作为一个事务撤销。

**Blocked by:** 04 / 打通列表、画布与检查器的共享选择；05 / 独立保存画布布局

**Status:** ready-for-agent

- [ ] 在列表重排镜头只更新 Shot.rank，不移动画布节点、不修改依赖，也不移动现有时间线片段。
- [ ] 把镜头拖入 Scene 框只更新 Scene 归属并保留镜头、候选和素材引用；删除 Scene 前必须让用户选择迁移镜头或确认删除影响。
- [ ] 从列表拖入画布只定位或重新摆放已有规范 ShotNode，不创建重复镜头。
- [ ] 从画布创建镜头时，以一个原子命令创建 Shot、唯一 ShotNode 和初始布局；任一步失败都不留下部分对象。
- [ ] 镜头组织命令支持领域级撤销/重做，批量操作作为一个事务恢复；运行副作用和已经生成的媒体文件不被声称为可撤销。
- [ ] 自动化测试分别断言管理顺序、依赖、布局和时间线位置不会因其他三类操作发生隐式变化。
