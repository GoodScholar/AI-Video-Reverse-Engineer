# 01: 无损升级工作区模型并建立兼容边界

**What to build:** 让已有前置工作台项目在不丢失内容的前提下进入统一的 v2 模型。首次读取旧项目时，系统为镜头建立默认场景、稳定管理顺序、唯一镜头节点，以及由现有素材输入和流程步骤派生的只读关系；旧界面和已有调用在迁移期间仍能完成原来的读取、保存、运行和交付操作。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] v1 项目可读取为包含 Scene、Shot、WorkflowNode 和 WorkflowEdge 的 v2 内容快照，并派生一份独立修订的初始 CanvasLayout；每个制作镜头恰好对应一个规范 ShotNode。
- [x] 迁移保留原有镜头和流程节点 ID、输入、参数、状态、错误、产物、结果候选及关联快照，现有节点运行和交付检查行为不回退。
- [x] 默认场景和镜头 rank 的生成稳定且可重复；同一份 v1 数据重复迁移得到等价结果，不产生重复场景、节点或边。
- [x] 读取旧项目时可以先返回兼容投影；第一次成功保存 v2 前保留可恢复的 v1 备份，迁移或校验失败时不覆盖原数据，并返回可理解的错误。
- [x] 内容修订仍使用既有 CAS 约束，兼容调用通过同一 v2 事实来源工作，不形成并行的 v1/v2 数据副本。
- [x] 自动化测试覆盖正常迁移、重复迁移、损坏输入、保存冲突和关键关联保留。

## Answer

- 旧 `state.json` 读取时以内存投影进入 schema v2，建立默认 Scene、稳定 `Shot.rank`、规范 ShotNode、素材/流程节点及只读数据边；读取本身不改写磁盘。
- 第一次成功保存 v2 前原子保留唯一 `state.v1.json`，后续内容仍沿用既有 revision/CAS；损坏的 v1/v2 状态返回明确存储错误并保持原文件不变。
- 初始 CanvasLayout 使用独立 `layoutRevision: 0`，本票据不提前实现 05 负责的布局持久化；兼容镜头步骤继续作为唯一事实来源，关系图内容由其稳定派生。
- 旧列表保存会按提交顺序更新规范 rank，同时保留 Scene 归属、节点状态、产物、候选历史和关联快照。
