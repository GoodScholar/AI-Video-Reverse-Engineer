# 05: 独立保存画布布局

**What to build:** 让用户自由摆放镜头节点、折叠场景并恢复上次视口，同时保证这些空间调整不会改变镜头内容、管理顺序、流程依赖或结果有效性。布局拥有自己的冲突检测和撤销历史。

**Blocked by:** 03 / 提供可切换的只读镜头关系图

**Status:** resolved

- [x] 节点位置、尺寸、场景折叠状态和各范围视口以独立 layout revision 保存和读取，不增加内容 revision。
- [x] 拖动期间只更新当前交互状态，拖动结束时至多提交一次布局变更；刷新和重新进入项目后恢复相同布局。
- [x] 同一布局的并发修改通过 CAS 返回明确冲突，不使用强制覆盖；内容保存与布局保存可以独立成功或失败。
- [x] 布局变化不会修改 Shot.rank、Scene 归属、WorkflowEdge、节点 stale 状态、候选关联或交付快照。
- [x] 节点移动和场景折叠支持布局级撤销/重做；选择、悬停、平移、缩放、聚焦和视口提交不进入撤销历史。
- [x] 自动化测试覆盖布局恢复、单次提交、内容与布局修订隔离、冲突处理及撤销/重做。

## Answer

- 新增独立 `CanvasLayoutStore`，按项目、场景和镜头范围原子保存位置、尺寸、折叠状态与视口，并使用独立 `layoutRevision` 做 CAS；内容接口在布局损坏时仍可独立读取和保存。
- 画布支持节点与场景拖动、场景折叠、各范围视口恢复，以及布局专用撤销/重做；拖动只在结束时提交一次，平移和缩放只更新视口且不进入撤销历史。
- 前端按范围缓存布局与历史，冲突时保留本地状态并提供显式重新读取；迟到的非当前范围回包只更新缓存，不会覆盖当前交互。
- 内容增删节点与布局持久化解耦：布局写入按当前领域节点集合收敛，不改变内容 revision、排名、归属、依赖、stale 或交付数据。
