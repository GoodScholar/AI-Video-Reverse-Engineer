# 07: 达到大型项目和跨设备交付门槛

**What to build:** 让 P0 互补工作区在大型项目、键盘操作和窄屏设备上达到可交付标准，并确认旧项目迁移、现有节点运行、结果候选、交付检查和外部生成边界没有回归。

**Blocked by:** 04 / 打通列表、画布与检查器的共享选择；05 / 独立保存画布布局；06 / 保持四种顺序分离地组织镜头

**Status:** ready-for-agent

- [ ] 使用约 1000 个总节点、多个场景和折叠分组的基准项目验证：项目层不展开全部 ProcessNode，列表保持虚拟化，画布只渲染当前范围所需对象。
- [ ] 单个选择、悬停或节点移动只更新相关卡片、节点和检查器；常用选择与悬停路径不产生超过 50ms 的主线程长任务，记录可复现的测量条件和结果。
- [ ] 键盘可以完成画布导航、聚焦选择、打开检查器、多选、撤销/重做和退出当前层；节点、端口、连接和状态具有可读名称及可见焦点。
- [ ] `≥1280px`、`900–1279px` 和 `<900px` 三类布局按设计工作，页面无意外横向溢出，抽屉关闭后焦点返回触发位置。
- [ ] v1 迁移、镜头编辑、现有流程节点运行、候选采用、结果关联和交付检查通过回归验证，布局操作不会使这些结果失效。
- [ ] 工作区不出现浏览器 API Key、远程插件、自定义 JavaScript、应用内最终 AI 视频生成或其他 P0 非目标入口。
- [ ] 完成受影响后端测试、前端测试、类型检查、生产构建、文档差异检查和真实浏览器关键路径验收，并如实记录未执行项。
