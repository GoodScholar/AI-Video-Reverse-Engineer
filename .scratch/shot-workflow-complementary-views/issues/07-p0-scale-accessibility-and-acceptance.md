# 07: 达到大型项目和跨设备交付门槛

**What to build:** 让 P0 互补工作区在大型项目、键盘操作和窄屏设备上达到可交付标准，并确认旧项目迁移、现有节点运行、结果候选、交付检查和外部生成边界没有回归。

**Blocked by:** 04 / 打通列表、画布与检查器的共享选择；05 / 独立保存画布布局；06 / 保持四种顺序分离地组织镜头

**Status:** resolved

- [x] 使用约 1000 个总节点、多个场景和折叠分组的基准项目验证：项目层不展开全部 ProcessNode，列表保持虚拟化，画布只渲染当前范围所需对象。
- [x] 单个选择、悬停或节点移动只更新相关卡片、节点和检查器；常用选择与悬停路径不产生超过 50ms 的主线程长任务，记录可复现的测量条件和结果。
- [x] 键盘可以完成画布导航、聚焦选择、打开检查器、多选、撤销/重做和退出当前层；节点、端口、连接和状态具有可读名称及可见焦点。
- [x] `≥1280px`、`900–1279px` 和 `<900px` 三类布局按设计工作，页面无意外横向溢出，抽屉关闭后焦点返回触发位置。

- [x] 工作区不出现浏览器 API Key、远程插件、自定义 JavaScript、应用内最终 AI 视频生成或其他 P0 非目标入口。

## Answer

- 继续复用开源 `@xyflow/react` 的只读画布、连接可访问名称与视口裁剪，以及 `@tanstack/react-virtual` 的列表虚拟化；本次仅补充产品域键盘语义、焦点回退和验收覆盖，没有从零实现画布或虚拟列表。
- 基准数据为 20 个场景、200 个镜头、每镜头 4 个流程节点，共 1000 个镜头/流程业务节点；半数场景折叠。投影测试确认项目范围只有 120 个场景/镜头对象且无 ProcessNode，单镜头范围只有 4 个 ProcessNode，投影耗时小于 50ms。
- 真实 Headless Chrome 153.0.0.0（macOS、10 个逻辑处理器，Playwright CLI 0.1.21，1280×900）中，列表仅挂载 9 张镜头卡，项目画布仅渲染当前视口可见的 22 个节点，进入单镜头范围后仅渲染 4 个流程节点。页面完成暖机后同时启用 `PerformanceObserver` 的 `event`（`durationThreshold: 16`）与 `longtask` 采样：依次悬停并点击一个可见虚拟列表卡片，再将一个可见 ShotNode 分 4 步拖动 36×18 像素，分别静置 180ms 与 250ms 后取样。悬停/选择最长事件 40ms、节点拖动最长事件 32ms，两个路径均无超过 50ms 的 Long Task。
- 画布节点支持 Space/Enter、Ctrl/Command 多选、`F` 聚焦、Ctrl/Command+0 适配范围、Ctrl/Command+Z 与 Shift 组合撤销/重做，以及在镜头范围内按 Escape 返回项目范围；节点、端口和连接具有可读名称并沿用全站紫色焦点环。
- 检查器通过关闭按钮、遮罩或 Escape 关闭后，焦点返回实际触发元素；从画布节点打开时返回该节点，从工具栏打开时返回“打开检查器”按钮。
- 真实浏览器在 1280、1100、800 像素宽度下分别验证桌面分屏、中宽抽屉、窄屏单视图/全屏抽屉；三档 `document.body.scrollWidth` 均等于视口宽度，无横向溢出。
